# 技能刷新运维（skill-refresh-ops）

> **能力自报块**（总接口 I3）：能力域=管理｜输入型=触发口令+会话插件清单｜输出型=刷新报告（预检/盘点/通道矩阵/移交或停止结论）+通报落库｜只读性=部分（写 <通道库> 通报与 output 报告；装安装位仅可写窗口）｜依赖=shell、select_tools、<通道库> MCP
> **纪律继承声明**（I4）：继承 conf 词表统一、红线条款、写类例外、全局共同遵守（autonomous-advance-ops 为准）；重装动作本身移交 skill-reinstall-ops，本件不越俎。

## 一、定位

「刷新」≠「重装」。本件管**盘点—热加载—通道验证—移交/停止—通报**全链路；真正改写安装位属 skill-reinstall-ops（预检→备份→换位→核验→回写）。两条件（可写窗口∧dist 包源）同真时本件只做移交，不亲自重装。

## 二、标准工作流（六步，顺序执行）

1. **预检**：`touch <技能安装位>/.writetest && rm`；只读即如实记录「重装停止」，禁止假装成功、禁止部分成功报全成。
2. **盘点**：`ls <技能安装位>`＋`/app/.agents/skills`＋逐技能 grep `version:` 字段，形成版本基线表；无 version 字段=常态非漂移。
3. **热加载**：用户点名技能逐件 read_file 入上下文，报告版本与在位状态（缺席=如实报缺）。
4. **通道强制健康检查**：对**本会话已装载的全部插件**逐通道执行一次最小调用，调用方式按 `references/channel-registry.md`——该表只存已研究结论；遇到表外新插件，按 §三 自行研究后**回写该表**（本件的自我更新点）。结果矩阵四态：🟢在线（附实证数据）/🟡在位未授权（给一句话用户动作）/🔴缺失/⚪未装载。缺席≠失败，未测=未测，禁止编造在线。
5. **包源搜索与移交**：`find <上传区> -maxdepth 3 -iname '*.skill' -o -iname 'skill-dist*'`；有包∧可写→移交 skill-reinstall-ops；缺一→如实停止并给降级路径（用户放包/可写会话/桌面端）。
6. **哨兵与通报**：检查「重装窗口哨兵」cron 在册（list_cron_jobs）；缺席即实装（每日 06:40 模板见 §四）。全量结果落 <通道库> `governance_records`（category=通报，conf=A），产出报告落 `<输出区>/`。

## 三、通道调用方式研究规程（遇表外插件时）

按插件形态四分类取最小调用，**每通道限一次**（额度纪律）：

| 形态 | 识别 | 最小调用 |
|---|---|---|
| MCP 插件 | tools_added 有 `mcp__plugin-*` | select_tools 加载其最轻只读工具（get_me/get_quota/list_*）调一次 |
| CLI 插件 | SKILL.md metadata.requires.bins | `which <bin>`＋`<bin> auth status` 或 `--version` |
| agent-gw 数据源 | Skills 列表、无独立 MCP | 按其 SKILL.md 发一次最小查询；无任务时以「待命」登记、不空转 |
| 纯技能 | 无通道对象 | 读 SKILL.md 首部即视为调用验证 |

研究结论回写 `references/channel-registry.md`（日期+实证数据+缺口动作），禁止只验证不回写。

## 四、哨兵模板（cron 内容）

依据写回队列常设预授权：每日检测①安装位可写②upload 出现 dist 包；同真→按 skill-reinstall-ops 四规程直接执行并通报；前提缺失静默登记；异常停止报告。（在册实证：task_id 1a05bfef-c2b2-855f-8000-00601cbbbd68，每日 06:40，2026-09-01 雁西席实装。）

## 五、边界（四条）

- 不越位向 `/app/.agents/skills` 安装用户技能（该位可写≠该装）；
- 凭证红线：任何通道验证不打印/不转播秘密值，授权态只看 status 不看值；
- 预授权解决「要不要逐次问」，不解决「能不能写」——物理只读时一切重装如实停止；
- 本件为运行时纪律件：台账载体（skill-iteration-registry）缺席时以 governance_records+cron 双轨登记，载体恢复后回填。
