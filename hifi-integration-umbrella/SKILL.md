# 高保真整合伞（hifi-integration-umbrella，临时技能）

> 开箱提示：.skill 为 zip 容器，解压后全部文本以 UTF-8 打开。本技能纯 Markdown 无脚本。

## §0 性质（先读）

- **临时性**：本伞为临时整合件，日落条款见 §4；注销前产出入库、留痕。
- **高保真定义**：①引用不复制——各技能权威文本在其本体，本伞只蒸馏名录卡；②名录卡以各件 SKILL.md 法定 description 为唯一基准，不臆增能力；③边界一句照抄或忠实改写，保真不走样。
- **泛化/项目双态**：本伞的名录与在编项目相关，但协奏规程（§2/§3/§4/§4.5）为泛化纪律，任何技能集合可代入。
- **件数口径动态化**：一切件数以 references/roster.md 当时实载为准（每次调用本伞时实读，不缓存），本伞任何条文不锁死绝对件数；roster 缺席或读空时，本伞降级为仅声明调用链（§0.1）并通报用户，禁止以空名录调度。
- **用户立法修订**：用户当日新口令可修订既往立法（用户主权），修订须留痕一句（旧句/新句/日期）。
- **单例条款**：同会话多版本伞并存时，以 metadata.version 高者为准，低版本视为失效副本。

## §0.1 调用链（用户立法 2026-09-01，恒常）

**前置（必先）**：`intl-case-intf`（国际法案例接口件）→ `k3-territory-studies`（领域研究）。**联动（必然）**：本伞一被调用，`omni-exhaust-research-ops`（穷举研究总署）必然随同调用。次序固定、不可跳件；任一件缺席时显式声明「占位」并按 §5 禁止假装。立法原句两句：「每一次调用 hifi-integration-umbrella 必须先调用 intl-case-intf、k3-territory-studies」「调用 hifi-integration-umbrella 必然调用 omni-exhaust-research-ops」。

- **调用栈断路（防回路）**：任一技能在单轮调用栈内已在场即不重复入栈（幂等去重）；本伞扩编件与被扩编件互有联挂边时（如 自决-self-determination §1 联挂本伞链），后入栈者检测到前者已在栈即跳过联挂重入，审议功能照常、链不重入。回路检测随扩编当轮必跑（有向图环检测+互引边标注）。
- **前置否决登记与救济**：前置链件内嵌红线（如 intl-case-intf §三.3 一票否决）在调用链前置阶段发动时，视同 §2 第 1 级裁决，强制登记于交割台账；用户可明示复核推翻，推翻留痕。
- **路径覆盖**：经伞路径调用时，本前置立法覆盖 omni §3 对 k3-territory-studies 的「可缺省占位」口径；不经伞直调 omni 时按其本体纪律执行。两条路径纪律差异合法，以各路径立法为准。

## §2 协奏规程（冲突仲裁次序）

多技能同场触发时，按以下优先序裁决（高者优先；**优先序裁决的是管辖先后，不撤销低优先级件的否决权**——任何级的否决在其职权范围内独立生效，高优先级放行不覆盖之；跨级结论相左时按最严格处置执行并登记）：
1. **红线与合规件**（release-gate-audit / 各件内嵌红线条款 / 前置链件否决）——一票否决；
2. **验收闸**（output-verdict-gate）——实质输出必经；
3. **调度件**（skill-dispatch-hq）——任务分配裁决；
4. **执法件**（pangu-enforcement-bureau 等）——域内强制；
5. **研究与执行件**——按能力域最小够用中选。

- **同级裁决元规则**：同级多件同场且结论相左时——①红线类从严（从严基准=限制外发/扩散/不可逆操作方向；双向对冲无法判严时升级用户裁决）；②其余按触发登记序号在先者优先，无台账环境退化为名录编组序在先者优先；③全部冲突留痕（谁压过谁+理由），零冲突如实报零。
- **主备定义**：「同 priority 并列主备」=由调度件按触发域匹配度判定主备，无法判定时按名录编组序；主件缺席/失败即切备，切换留痕一句。
- **闸缺席处置**：验收闸缺席时，涉金融/健康/涉老/对外实质结论一律停发转用户裁决；**用户不可达时挂起留痕、任务不终止，用户返场后续裁**；其余输出降级为「占位声明+理由」，经用户明示批准方可外发。禁止假装已过闸。
- **伞自身受辖**：本伞自身产物（名录卡/协奏裁决记录）同受第 1/2 级约束；被否决时返工名录卡或裁决记录，不得绕过。

## §3 短文本安装（平装本）

本 SKILL.md 全文即短文本平装本源；蒸馏更短版实装为 assets/plain-text-install.md（体积以该文件实测为准，上限 ≤2KB）：无安装位场景（新会话/跨平台/微信好友侧 AI）直接粘贴该蒸馏文件即临时生效；dist 蒸馏更短版时，必保留 §0 性质、§2 仲裁序、§4 日落、§4.5 扩编四节（保真底线；未来条文膨胀致四节合计超限时，取舍序=§2＞§0＞§4＞§4.5），名录可压缩为编组速览。蒸馏版版本随锚本体版本；**平装本内名录即视为其生成时点的实载**；流通副本以 dist 镜像为唯一权威源，回流篡改或与权威源不一致者不予承认；伞注销后存量平装本副本不可召回，以广播作废声明+版本戳失效为准。

## §4 日落条款

- 注销条件（满足任一）：用户口令「收伞/注销整合伞」；名录在编全部件（含扩编件与前置链件）中任一本体发生重大版本变更且本伞未随锚（名录失保真）。
- **变更判定**：以本体 frontmatter version 为准；无 version 字段件以其 description/正文版本串为准，该等件列入失锚风险清单（roster 头部备查）。「重大」=主版本号跳变或触发域/边界实质变更；其余漂移先走 §5 中间态标注，无法随锚刷新者升级本条通报收伞。
- **判定主体与周期**：联挂 skill-refresh-ops 版本漂移扫描，于本伞被调用当轮预检；skill-refresh-ops 缺席或自身漂移不可判时，备援判定者=skill-dispatch-hq 总目录版本比对；发现失保真即通报用户裁决是否收伞。**用户不可达时本伞进入「待收伞」状态**：挂起新扩编、仅维持只读名录与调用链声明，并在场即通报。
- 注销前：名录与协奏留痕入库归档；伞侧联动纪律（§0.1 对 omni 的随同义务）自注销时起失效，伞归档留痕（不拟制通告 omni 本体）；本伞注销不影响名录所载各件本体分毫（伞非依赖方向）。收伞口令优先于进行中的扩编事务（先收伞、后结账）。
- 字体规范：本伞产物一体适用宋体（中文）/Times New Roman（西文）全局规范。

## §4.5 随锚扩编规程（用户立法 2026-09-01）

- 伞外技能（伞外件数=skill-dispatch-hq 技能资产总目录当时实载−名录在编件数；2026-09-01 锚=46 件；总目录缺席时以 roster 入录依据标注为准并降级声明）凡被用户点名扩编，当轮入 roster 名录卡（高保真三节：法定 description 基准/触发域/边界），伞 metadata.version 随锚 +0.1.0；「一轮」=同一用户消息内的点名集合，多件当轮合并一次 +0.1.0。
- **入录双通道**：①前置立法入录（§0.1 用户立法件，如 intl-case-intf）；②点名扩编入录（本条）。名录卡注明入录依据；凡已入录件即从伞外基数扣除，禁止双向计数。
- **点名认定**：复用本件 frontmatter description 触发①的语音变体映射规则；执行时复述告知一句（点名件名+入录依据）并默认执行，用户当场否词即撤回留痕。点名已在编件=复读告知其在编状态，幂等不递增版本；点名查无此件=如实拒绝并给总目录核对结果；伞自身不入名录（自指禁止）。
- **扩编卡验收**：写入时四节自检（与本体 description 逐句核对+version 来源核验，无 version 字段件同步入失锚风险清单）+ 交割台账登记；涉对外实质输出时另过 output-verdict-gate。
- 扩编不改调用链（§0.1 不动）；扩编件同时刷入技能资产总目录档案。
- 反向：用户点名除名即移出名录，留痕理由于交割台账（历史号段不计入实载）；除名后再点名者，以当时伞版本 +0.1.0 重锚入录。**§0.1 立法件（前置链/联动件）不适用点名除名**——除名立法件须用户明示新口令修订 §0.1 立法本身并留痕。

## §5 诚实边界

本伞不提供任何新能力——它只是名录所载各件能力的目录与协奏曲；伞在而本体缺席时，对应条目降级为「能力占位」，显式声明不可用，禁止假装可调度。**版本漂移中间态**：名录卡版本≠本体实况时，以本体为准、当轮显式标注漂移、触发名录刷新与交割台账登记；名录刷新由当轮调用方执行，刷新失败（如本体/目录只读）时维持漂移标注并每轮重申，直至可写窗口，全程禁止使用失保真版本调度。
