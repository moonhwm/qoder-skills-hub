# 协调函（跨实例任务委派与回执规程）

## 何时用

跨实例委派任务且需要**可核验的回执**时。口头指令在单会话内够用；跨会话时指令会脱离上下文，无格式即无审计。

## 协调函六段式（发件方写）

```
【协调函 CL-<项目简称>-<日期>-<会话标识>-<序号>】
（编号带会话标识防撞号：两会话各自发函时序号独立——2026-08-29 撞号实证。先到先得判定正本，后到者让号留痕）
发件：<实例/会话标识>  收件：<实例/会话标识>
一、背景：一句话（为什么需要这件事）
二、委派：要做什么（单一动作，一函一事）
三、边界：不做什么（明确的否定约束）
四、验收：什么叫完成（可核验标准，最好是落盘物+核验动作）
五、回执：要求回报什么（结果/证据/偏差/请示点）
六、时限与降级：何时算逾期；失败时怎么降级
```

## 回执五段式（收件方写）

```
【回执 #对应函号】
一、状态：完成 / 部分完成 / 受阻（一句话）
二、证据：落盘路径 / 核验输出 / 关键数据——**不得为占位表述**（「已提取」「已核验」而无实际内容 = 不合格回执）；委派含「汇报」时，汇报内容本身必须完整写入，不得以「详见某文件」一笔带过
三、偏差：与委派要求的差异（无则写「无」）
四、逃逸自查：是否超出边界（无则写「无」）
五、请示：需要发件方裁决的点（无则写「无」）
```

## 逃逸防线（防越权四铁律）

1. **一函一事**——一个函只委派一个可独立验收的动作。「事」的粒度：含内在节奏控制的委派（如「放行半批+分批执行+每批回执」）算一事（验收单位=批）；捆绑多个独立目标（如「读 handover」+「整理归档全部文件」）的函收件方可拒收；
2. **边界语义**——函件必须有明确的否定约束（「不做什么」），以语义为准不拘格式标签：函中写「只汇报、不要展开」即合格；全无否定约束的函视为不合格，收件方应要求补边界；
3. **越界即停**——执行中发现需要超出边界才能完成时，停止并回执请示，禁止自行扩权；
4. **留痕可审计**——函与回执都落盘（项目目录 correspondence/ 或会话内引用块），任何第三方可复盘指令链。

## 流程

发件方写函 → 收件方确认边界（不合格则要求补）→ 执行 → 回执五段式 → 发件方验收（核验证据，非口头采信）→ 归档。
