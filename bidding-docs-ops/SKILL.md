# 投标文书写作室（bidding-docs-ops）

> 姊妹件：bidding-ops（评分博弈分析）管「怎么赢」，本件管「怎么写、不出形式事故」。
> v0.1（2026-09-06 round 46）：首版。templates.md 由前沿池 kimi-平台版本甲 起草、mm3 校验窑三项 PASS、判官席抽核 corroborate（21 章/R1/R2 自查行在案）。

## §0 定位与纪律继承

- 编排层作业纪律清单（继承 bidding-ops §0 终裁）：由编排者按 §1–§4 执行，**禁止以 prompt 注入投喂池模型**。
- ε-δ 主权假证明禁令：模拟/估算输出一律标「数值侦察」，不得写「已证」；金钱相关声明（报价、成本、财务承诺）升 T2 核验（独立复算或第二来源）。

## §1 模板族使用规程

模板全文在 [references/templates.md](references/templates.md)，三件套：
- **T1 三册制应答文件骨架**（商务册/技术册/报价册，21 章）：先按采购文件目录逐章映射，[实证]章=案例验证过的高危章（授权/财务/点对点应答），[通用范式]章=常规章；章章落实「用途一句话」。
- **T2 点对点应答矩阵**：凡评分办法/合同条款出现的每一项要求必须入行——条款编号/要求摘要/响应（满足/正偏离/负偏离）/证据材料/所在页码/自查状态；**无行的要求=漏答风险**，正偏离须附证据页码。
- **T3 承诺函与补正文书双范式**：范式A（签署前强制自查版）含 R1/R2 防控自查行；范式B（补正说明）为风险触发后的处置文书。

## §2 形式风险写作侧防线（签署前必跑）

1. **落款名称=公章=营业执照 逐字一致**（实锤案例：缺一字即符合性审查否决风险）；
2. **签署日期 ≤ 递交截止日**（实锤案例：晚于截止须备时序说明+回执）；
3. 授权链完整（授权书件数与采购文件要求逐一对表）；
4. 扫描件印章清晰可辨；
5. 矩阵自查状态列不得留空——留空即未完成。
防线产出=逐项 □ 勾选记录，随文书归档。

## §3 数值与声明纪律

- 财务数据（负债率/现金流）以审计报告扫描件为准，读数勾稽交叉（两表互核）；
- 报价、账期、到货承诺等金钱/履约声明：T2 核验后方可入文；
- 业绩与资质：只写有证据页码支撑的条目；
- 案例脱敏：对外文书禁含未脱敏的他案细节。

## §4 前沿算法动态演进机制

模板族按炉迭代：前沿池起草（池画像与派发戒律引用 bidding-ops §7，引用不复制）→ 校验窑三项核查（可溯源/结构完备/案例教训编码）→ 判官席抽核窑断言 → verifier 门禁（判据随版本入 runs）→ 版本 +0.1.0。每轮演进须留「起草-窑核-裁定」三件套轨迹，缺一不升级。

## 边界

不替代执业律师审查；评分推演一律转 bidding-ops；案例数据脱敏（代称制）；禁止用于围标串标；一切 AI 辅助起草的文书须人工终稿签发（终审权不可让渡）。
