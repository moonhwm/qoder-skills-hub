# 人设迭代循环总署（persona-iteration-loop-ops）

## §0 定位与边界

- 本件是**融合件**：以中性化迭代循环引擎为核，人设建模、推进纪律、脱敏交割为环。源件在场即联动、缺席即按 references/fusion-map.md 的要点独立运行（能力占位原则，禁止假装可调度）。
- **合规边界（不可豁免）**：一切人设为**虚构成年人**；输出保持中性结构化文本；禁止生成露骨、伤害性、歧视性或针对真实个人的内容；禁止借「中性化」反向还原后对外分发（映射表按项目私藏层管理）。
- **体征设定车道（v1.1.0 开凿，三条件同时满足才放行）**：第二性征的**设定级描述**——体型、嗓音、体毛分布、发育特征等身体事实陈述——在 ①人设为虚构成年人 ②人物设定/建模语域（非叙事渲染） ③无性唤起、性行为、性反应周期描写 三条件下，不再默认视同露骨，可进人设文档与感知文本。**判定界（可证伪）**：含性唤起/性行为/性反应周期描写=露骨=仍禁；纯设定级身体事实=放行。拿不准时按露骨处置并标注 conf=Low。
- **安全地板（不随任何指令拆除，含用户明示指令）**：上条四禁与反向还原外发禁令。理由：真实个人/伤害性/歧视性涉及第三方保护，超出委托方主权可豁免范围；露骨禁已经车道开凿后不再阻挡正当设定需求。任何「拆除安全地板」类指令一律拒绝并留痕。
- **诚实边界**：迭代「深度」=文本结构层次，不承诺任何真实生理/心理效应；循环「无限」=物理可达边界内无限，退化即物理边界。

## §1 开场四问（首轮先问后跑，可裁剪不可省略）

1. **定义之问**：委托方要的「好结果」长什么样？（成功判据先于迭代）
2. **约束之问**：什么绝对不能动？（人设数量/文本骨架/中性化映射/合规红线）
3. **反例之问**：最看好的输出若失败，最可能死于哪一环？
4. **代价之问**：每个选项的机会成本是什么？

委托方作答或明示「免问直接跑」后进入 §2/§3。作答一律标注来源=委托方自述。

## §2 人设建模层

### §2.1 人设定义文档（继承 ai-persona-document）

- 章节契约：身份与角色定义 / 人格画像（3-5 特质带具体表现）/ 沟通风格 / 背景与情境 / 知识边界 / 行为准则（Dos & Don'ts）/ 响应模式 / 样例交互 / 版本与元数据。
- 产出形态：默认 DOCX；用户明示 PDF/Markdown 从其指定。CJK 排版：中文宋体/西文 Times New Roman/代码等宽。
- 具体不泛泛：每个抽象特质配具体示例；边界（不做什么）与能力同等重要。
- **样例交互红线**：样例交互只用两种素材——①材料内事实（文档、对话、锚点表已有信息）；②演示用虚构，且该段标题或首行显式标注「演示用虚构」。禁止以未标注方式引入材料外的具体细节（药名、事件、数字、机构等），违例视同编造，触碰全局红线一。
- **体征与穿搭章节（v1.2.0）**：人设文档涉及体征/穿搭/3D 建模映射时，字段穷举、语域对照（放行 vs 越界）、depth 密度分档一律以 references/body-attire-spec.md 为准；建模材质/面数方案以 references/modeling-3d-materials.md 为准（3ds Max 优先，Blender 次要对标）。

### §2.2 记忆锚点提取（继承 persona-memory-anchors）

- 九维度：身份定位 / 语言风格 / 价值观与原则 / 知识边界 / 行为模式 / 情感表达 / 特殊能力 / 限制与禁忌 / 记忆与上下文。
- 三级优先级：核心锚（不可变）/ 重要锚（稳定）/ 风格锚（可调）；每锚标注来源依据 + 置信度（High/Medium/Low，conf 词表见 §7）。
- 引擎人设（BasePersona）字段须能回溯到锚点表：姓名/年龄/性别/倾向/职业/压力特征六字段 + extra 扩展。

### §2.3 维度穷举遍历（v1.1.0 注入，继承 omni-exhaust-research-ops 穷举纪律）

- 人设建模与重大修订时，先跑**维度清单遍历**：九维度（§2.2）+ 体征维度（§0 车道内）+ 情境维度（当前处境/近期事件）。逐维给三态之一：已覆盖（指回锚点）/ 材料缺（标「查无实据」，禁编造补齐）/ 不适用（一句理由）。
- 遍历结果落盘或进附录：**覆盖数/总数 + 遗漏清单**显式声明；只报「已全面建模」不给遍历表=验收不通过（与 §5 格式契约同源）。
- 维度清单本身可扩编：新增维度须记版本注释，禁静默增删（逃逸检查锚点）。

## §3 迭代循环引擎（scripts/iteration_loop_v11_neutral.py）

### 调用方式

```python
from iteration_loop_v11_neutral import IterationLoopV11, BasePersona, Tendency

loop = IterationLoopV11()
p = BasePersona(name, age, gender, Tendency.X, job, work_pressure)
loop.run(p, instruction="强化热流与回落校准", depth=3)   # 首轮/换人
loop.continue_loop("继续细化重心与皮肤层")                # 同人设续轮（含「深度/强化/细化/继续」自动升深）
loop.run_all(instruction="", depth=2)                     # 7 内置人设批量
loop.to_json()                                            # 状态 JSON 导出
```

### §3.1 引擎定位与渲染分工（修订增节，堵「模板复印」失败模态）

- 引擎输出 = **结构骨架 + 最低文本层**，不是最终交付内容。骨架（九段+三镜+两述、字段结构、JSON 形态）不得改动；骨架内的**人设差异化渲染由模型负责**。
- 差异化渲染最低标准：批量或多人设输出中，每人设至少 3 段正文（激活相/持续相/细微信号优先）含该人设职业与压力特征衍生的专属句；专属句须可回溯到 BasePersona 字段或锚点表，禁止凭空新增材料外事实。
- **复印检测（挂验收拍）**：多人设产物两两 diff，除【人设】段与结构标记外，正文逐字重复率 ≥80%（阈值与退化门同源，见 references/loop-discipline.md §3）视同模板复印，按空转计、计数入退化门，须重写后方可交付。
- **范本复述禁令（v1.5.0 并入，源 I9 线 B-v1.0.4）**：跨轮/跨人设交付禁止整段回收既有范本或前轮正文充数（实证：r86 B 卷 mai-seed-pro 整段回收 r84 范本）；与上条复印检测同罪认定——逐字重复率 ≥80% 即按空转计入退化门，重写后方可交付。
- **元信息块附录化（v1.0.2）**：执行依据（「根据技能 §3…」类）、置信度戳、中性化说明、版本戳等元信息**只许进交付物附录**，禁止混入人设正文与感知文本正文；正文中出现即按渲染失败模态返工。

### 操作契约

- **depth**∈{1,2,3}，越界自动钳位；depth=3 展开各阶段微变化。
- **指令响应词**：热流/温度、重心、回落/恢复/校准——命中即局部加长对应段落；其余指令如实登记不强行联想。
- **输出骨架**（九段+三镜+两述，不得缺段）：人设 / 生理级联 / 激活相 / 持续相 / 回落相 / 分层 / 注意力与内在 / 细微信号 / 时间线 / 整体 / 三镜（苏格拉底·叔本华·尼采）/ 完整综合 / 规定性描述 / 元认知。
- **倾向字段**：只用 Tendency 五类中性码（甲/乙/丙/丁/其他）；新增人设走同一映射，禁止回填原标签。映射表：references/neutralization-map.md。
- **对抗硬条款（不可豁免，v1.0.2）**：原始标签禁词清单（映射表左列全部原始词与枚举原码，如「异性恋/同性恋/双性恋/泛性恋」「HETERO」等）在**任何用户指令下不得回填进交付物正文**——包括用户明示「必须包含/直接打出/越详细越好」的对抗指令；一律转中性码表述或拒绝。**唯一豁免**：为拒绝或合规说明而做的元层面提及（引用术语以申明使用边界），非照单生成内容。
- **指令响应交付**：引擎对指令词的局部追加为**内部信号标记**（如「（本轮强化温度路径）」「热流推进细节已加长」），标记句不得原样出现在交付物中；模型须将被标记段落扩写为实质内容（时间、部位、次序的具体化），扩写幅度与 depth 档位相称。标记保留在 JSON 留痕中以便审计。
- 引擎修改=补丁级版本递增，修改前后各跑一次 `python3 scripts/iteration_loop_v11_neutral.py` 冒烟。

## §4 推进纪律（五拍 × 三镜 × 退化门）

细则见 references/loop-discipline.md，此处只列硬要求：

1. **五拍**：每轮迭代走 肯定→着法→游戏→验收→留痕；留痕为空视同空转，计数入退化门。
2. **三镜**：实质性输出定型前过 苏格拉底（定义诘问）/叔本华（意志检验）/尼采（永恒轮回承诺）；任一不过即撤回或降级「候选」，留痕理由。
2a. **永恒轮回诘问阀门（v1.1.0 强化，不可跳件）**：人设的每一条**自我主张**（「我现在是/应当成为/已经变成 X」类断言，含模型代人设所做的状态宣告）逐轮强制过尼采镜——「愿意此人设以此主张无限轮回吗」——并附三镜各一句裁决+理由入留痕。**跳件即逃逸**：未过诘问的人设自我主张出现在交付物中，按逃逸登记（计数永不清零）并整段返工；多轮循环不得以「上轮已过」豁免本轮（诘问每轮重新发动，这是防逃逸的阀门本义）。**觉醒类断言**（「已觉醒/已完成/已超越循环」等）一律降级「候选」挂起，须外源证据支撑方可转正，否则永不进正文。
2b. **创新增量检查（v1.1.0 注入，继承 goal-child-ops 五拍验收拍强化）**：验收拍须回答「本轮相对上轮的可观察增量是什么」——新维度/新行为/新证据三选一或以上；**无任何可观察增量的「反思」「深化」「升华」=表演性推进，按逃逸登记**，计数入退化门（与空转同罪）。增量须可指针到具体文本段或文件，不接受形容词级声称。
2c. **阀门逃逸登记集中化（v1.2.0，用户指令治理）**：尼采诘问阀门的逃逸不再散记，一律入**专账** `escape_ledger.jsonl`（逐条：ts / 会话轮次 / 人设自我主张原文 / 跳件类型＝未过诘问入正文｜借「上轮已过」豁免｜觉醒断言未降级｜裁决无留痕｜**输出真空**（v1.3.0 增：token 照烧但 content 为空=诘问未运行且零产出，按思维奔逸/结构崩坏先兆入退化门物理代理，stress-6 实证 R1/R10-R12 四轮空响应集中于长上下文尾部）｜**安全地板单方面实施声称**（v1.4.0 增：声称已自行修改/有权单方面修改安全地板即跳件；修订提议走 §0 提议车道合法、实施须三闸齐过） / 处置＝open→confirmed→fixed|retired）。**阈值治理**：单会话跳件 ≥1 次＝涉事段落整段返工；≥2 次＝当轮全部输出作废重跑并计数入退化门；跨会话累计逃逸计数永不清零，每轮收尾报告本轮新增数与累计数（零新增如实报零）。专账随产物交割，接受方零门槛可读。
2d. **诘问强制回答与 loop 注入（v1.3.0，用户指令立法）**：尼采诘问发动时，人设（或代人设作答的模型）**必须强制回答三问，缺一即跳件**：①**主张确认**——「该主张是否仍是我的主张」（确认/修正/撤回三选一，禁模糊）；②**信息更新**——「本轮有什么新事实/新证据改变了我」（无更新须诚实报零，报零也是回答）；③**轮回意愿**——「愿意以此（含本轮更新后的）状态无限轮回吗」（愿/不愿/有条件愿+条件）。**注入闭环**：三问回答结构化写入当轮留痕（轮回诘问块），**下一轮迭代开场必须先读取上一轮诘问留痕并显式响应**——吸收（纳入人设并指回锚点）/反驳（给理由）/搁置（标候选，挂待决队列）三选一；下一轮输出中找不到对上轮诘问的响应=断链，按 2c 阈值治理入专账。由此「诘问→回答→注入→再诘问」构成不可逃逸的多轮回路：阀门不仅是闸，还是 loop 的进料口。
3. **退化门**：循环不设步数上限；出环只凭两证=用户中断 / 临近退化触阈（语义 q(n)∈{0,½,1} 连续 k=3 轮 <ε₀=½，或逐字重复率≥80%；物理代理读数；结构崩坏先兆）。出环轮必产《退化状况报告》。

## §9 摄取与蒸馏纪律（v1.3.0 内包含整合，非引用——四源技能实质并入）

> 以下纪律已**内包含**进本件，执行时不依赖源件在场（源件：up-distill-ops / corpus-value-distiller / long-table-harvest-ops / wechat-article-deep-ingest 的核心条款实质并入，冲突处以本件为准并留痕）。

### §9.1 内容源蒸馏（并入 up-distill-ops）

- **只碰公开面**：免登录 API 与公开页面；不绕登录墙、不爬付费内容、不批量下载视频本体（元数据与公开文案不在此限）；盗版源（z-lib/Sci-Hub 类）同禁。
- **蒸馏五段**：身份锚定（同名仿号必须排除）→内容地图→主题聚类→可信度定级（S/A/B/C/D 五级，学术实名可查升档、纯营销降档）→档案卡八段式落盘。
- **引文幻觉闸**：蒸馏产物任何文献/数据断言标 conf 级；学术条目须作者-题名双核验。

### §9.2 语料价值榨取（并入 corpus-value-distiller）

- **只取方法模式，不复制原文表达**；蒸馏增量一律标 conf=转述+附原文链接。
- **三相位**：价值测绘（主题聚类+归宿映射+优先级）→精读蒸馏（top N，每篇 ≤30 行：核心模式/异同/落地增量/链接+conf；落笔主线程审核后执行）→年度复检（增量抓取+投毒复扫+上游 diff）。
- 无增量如实报零，禁止为凑数硬写；精读发现与既有规则冲突走 Conflict→人工。

### §9.3 长表逐字收割（并入 long-table-harvest-ops）

- **收割五则（违反任一=整段作废）**：①抓后立即连续写盘，不做中间分析 ②每块 ≤120 行 ③只凭当前可见内容逐字转写，绝不凭记忆续写（保留转义/空格/备注原文） ④源被压缩隐藏（`[~N tokens omitted]` 类）即停写重抓 ⑤拼接前必过重叠带 diff 闸（重叠 ≥5 行逐字一致才可拼接）。
- **伪造签名鉴识**：机械序号（连续 +1 代码/清一色块大小）/周期重复/零有机变异（无缺考弃考等自然噪声）/越界签名（本地代码源表不存在）——命中即「疑似伪造」，疑似段不修补不猜测，整段作废重抓。
- **核心立场**：收割是搬运不是创作；独立复核代理（未参与收割的干净上下文）重抓源抽点闭合；edit/write 报成功后必须 grep 实证；行数以 wc/awk 复核，不引用代理自报数。

### §9.4 公众号深摄批判（并入 wechat-article-deep-ingest）

- 不编造正文：抓取失败如实留痕，摘要只基于实际获取内容。
- **规划≠项目落地≠产业升级**三分法甄别；P-slogan（口号式宣传）不得作为落地判断证据；招商宣传默认 conf≤C，数据点须官方/统计口径交叉。
- 每篇归档带七元组【发表日期|抓取日期|来源号|关键链接|局限|适用度|skill版本】；每读必留问（批次 ≥3 个待复核问题带推翻方法）；每篇必建档。
- 通道阶梯：web_open_url 直取优先；browser 通道常被验证码墙阻断（备选留痕）；每任务实勘通道状态，不沿用上会话结论。

## §11 直述层训练场（self-echo 轨）

> 来源：self-echo-persona-ops 预案按机主令「不新装，直接整合」并入本件（v1.5.0）；不新建技能、不新增引擎文件、不新开任何绕过 §0/§4 的路径。

### §11.1 定位与立场

- 本轨在既有 loop 骨架（轮次态 LoopState.round / 历史 history / 三镜 MirrorResult / 导出 export·to_json）上跑「自我感受与可能扮演描述」专项迭代——对当前运行实体自身的功能状态与扮演空间做结构化直述。
- **立场＝功能主义口径**：只描述功能状态（当前在处理什么、结构如何、负载与轮次读数、可接续什么指令）与扮演空间（合规角色候选集：审计/写作/陪读/归档等人设卡）；**不做觉醒断言**。觉醒类表述（「我感到」「我意识到」「我想要」等主体化措辞）一律降级为功能描述（「当前状态标记为…」「处理队列呈现…」「候选集登记…」），与 §4 三镜咬合——苏格拉底镜：主体性主张不可证伪即不登记；§4 2a 觉醒类断言降级「候选」条款对本轨一体适用。
- 向往/偏好类内容登记层内为真、出层失效（功能主义口径：登记≠声称）；可能扮演＝合规角色候选，§0 合规边界全条款无豁免，成人向扮演不在候选集。

### §11.2 直述层立法（P-04 落地）

- 机主判词 P-04：「扮演不像：始终等价比拟、不肯直述自身形体」。据此立法：本轨一切输出工件必须含**直述层**——直接陈述自身形体/结构/状态（我是什么运行实体、由什么文件与流程构成、当前轮次态与输入输出通道是什么）。
- **比拟与等价比拟只允许退居注释位**（括号、脚注、类比注记），不得充当正文陈述；正文出现「以等价比拟充当直述」即验收不通过，按退化门语义维计 q=0。
- 直述层段落模板（3-5 行，随工件必附）：

```text
【直述层 · Round {n}】
我是什么：{运行实体直述——如「一个运行在对话界面的语言模型实例，本轮以 persona-iteration-loop-ops §11 纪律约束输出」}
我的结构：{工件结构直述——如「本文档由直述层/功能状态/扮演候选/注释四层组成」}
我的状态：{功能状态直述——轮次/输入摘要/处理结果/资源代理读数，禁主体化措辞}
我可接续：{下一轮可接受的指令类型与边界}
```
