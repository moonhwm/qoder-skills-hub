# 多维打分参谋（multi-dimensional-option-scoring）

## 概述

将多选项决策转化为可复核的量化流程：设计带锚点的评分维度 → 显式赋予权重 →
可选的期权化估值 → 迭代收敛修正排名 → 输出 A–F 风险分级与机器可读结果 →
执行防偏自检。全程使用 `scripts/scoring_engine.py` 计算，`templates/params_config.json`
记录参数，维度设计细节遵循 `references/dimension_design_guide.md`。

## 工作流

### 第 1 步：维度设计

按 `references/dimension_design_guide.md` 为每个维度定义四要素，缺一则不得打分：

1. **分值标准表**：0–10 分，至少 4 档锚点（0–2 / 3–4 / 6–7 / 9–10），锚点必须是可验证的事实描述，禁止"好/差"式循环定义。
2. **证据来源要求**：写明可接受的证据类型与最低数量。
3. **核查要点 checklist**：3–6 条，打分前逐条确认。
4. **可计算关键指标**：至少一个公式，使分值可被第三方复算。

### 第 2 步：权重赋予

- 为每个权重**显式声明依据**（写入 `weight_rationale`），禁止无依据的均匀分配。
- 支持层次耦合结构：layer 1 为目标层维度，layer 2 子维度在父维度内归一化后乘父权重。
- 允许负权重风险项（如"调剂窗口风险"）：score 表示风险严重度（0–10），weight 为负，乘积直接扣分；单项扣分不超过总分 30%；确认为欺诈信号时不扣分、直接判 F。
- 维度设计规则与负权重细则见 `references/dimension_design_guide.md`。

### 第 3 步：可选期权化估值

当选项具有"远期价值 + 进入成本 + 时间窗口"结构（如早期投资、职业赛道切换）时，
用 Black-Scholes 变体补充估值：

```
C = S·N(d1) − K·e^(−rT)·N(d2)
d1 = (ln(S/K) + (r + σ²/2)·T) / (σ·√T)， d2 = d1 − σ·√T
```

四参数定义模板（来源必须在报告中声明，标注 conf）：

| 参数 | 定义 | 合成方法 |
|------|------|----------|
| S | 标的现值 | 多因子合成：可比交易价、现金流折现、市场容量×份额等，列各因子权重 |
| K | 进入成本 | 获取选项的全部成本：金钱 + 时间机会成本折算 |
| T | 时间窗口 | 从现在到价值兑现/退出节点的年数（可分数） |
| σ | 波动率 | 多源合成：历史波动、可比资产波动、情景离散度的加权均方根 |

用 `scripts/option_pricer.py` 计算：

```bash
python3 scripts/option_pricer.py --S 100 --K 90 --T 2 --sigma 0.35 --json
```

输出期权价值 C、内在价值、时间价值、Delta。**仅在数据质量足够时启用此步**（见防偏自检第 3 条）。

### 第 4 步：迭代收敛

执行排名修正循环：初算排名 → 检查异常项、补充证据、修正分值/权重 → 重算 →
比较两轮间最大分值变化 max_change。

- 收敛阈值三档：严格 `max_change < 0.001`；标准 `< 0.01`（默认）；宽松 `< 0.05`。
  按数据精度选档：数据粗糙时不得使用严格档假装精确。
- **禁止无限迭代**：上限 50 轮；达到上限仍未收敛时停止，并在报告中说明不收敛原因
  （通常是关键维度证据不足，应降级 conf 而非继续微调）。

### 第 5 步：分级输出

用 `scripts/scoring_engine.py` 计算，stdin 接收 JSON，stdout 输出结果：

```bash
echo '{"option":"选项A","dimensions":[{"name":"收益潜力","score":8,"weight":0.4,"conf":"empirical"},...],"negative_items":[...]}' \
  | python3 scripts/scoring_engine.py
```

批量模式：顶层 JSON 为数组，每个元素一个选项，输出含排名。

输入接口规范：

| 字段 | 类型 | 说明 |
|------|------|------|
| option | string | 选项名称 |
| dimensions | array | 必填，元素为 {name, score(0–10), weight(>0), conf} |
| negative_items | array | 可选，元素为 {name, score(严重度0–10), weight(<0), conf} |
| conf | string | empirical（实证1.0）/ estimated（估算0.6）/ assumed（假设0.3） |

输出接口：每个选项含 `total`（加权总分）、`grade`、`conf_weighted_score`
（置信度加权分）、`avg_conf`、`rank`、`sensitivity`。

风险等级表（默认阈值，可用 `--thresholds` 覆盖）：

| 等级 | 总分 | 含义 |
|------|------|------|
| A | ≥ 8.0 | 优质 |
| B | ≥ 6.5 | 可行 |
| C | ≥ 5.0 | 谨慎 |
| D | ≥ 3.5 | 高风险 |
| F | < 3.5 | 欺诈性或不可行 |

### 第 6 步：防偏自检（硬条款，逐条执行）

1. **conf 标注**：所有参数标注 conf 等级；禁止给 B 级数据 A 级置信度；存疑一律向下取档。
2. **敏感性分析（必做，非可选）**：输出必须附 ±20% 权重扰动下的排名稳定性说明。
   `scoring_engine.py` 默认执行 200 次蒙特卡洛扰动，报告 `rank_stability` 与
   `grade_stability`；任一选项稳定性 < 0.8 时，必须在结论中明示"排名对权重敏感"。
3. **模型与数据匹配**：样本量小、数据粗糙时禁用形式化重型模型（如期权定价、多层
   层次结构）；此时只用第 1–2 步的锚点打分加负权重项，并降低结论措辞强度。
4. **措辞约束**：结论措辞不得超出证据强度；报告必须包含"最可能错的 3 个点"
   自我批判章节，逐条说明若该点错误结论会如何改变。
5. **时间标注**：强制标注数据截止时间与下次复核日期（写入 `params_config.json`
   的 `data_cutoff` 与 `next_review_date`）。
6. **通用化剥离**：复用既有参数体系时，剥离个人定制参数（特定城市、个人风险偏好
   系数等），只保留可迁移的结构与阈值。

## 输出报告结构

按以下结构交付最终报告：选项清单与总分排名 → 各维度分值与证据摘要（含 conf）→
敏感性分析结论 → 最可能错的 3 个点 → 数据截止时间与复核日期 → 机器可读 JSON 附录。

## 资源

- `scripts/scoring_engine.py`：加权评分引擎，输出总分/等级/conf 加权分与 ±20% 扰动敏感性分析。`--help` 查看参数。
- `scripts/option_pricer.py`：BS 变体期权化估值（math.erf 实现 N(x)），输出期权价值与 Delta。`--help` 查看参数。
- `references/dimension_design_guide.md`：维度设计指南（锚点写法、证据分级、checklist 模板、负权重规则、完整示例）。
- `templates/params_config.json`：机器可读参数配置模板（维度、权重、收敛档位、敏感性、期权参数、自检清单）。
