# 跨 AI 协调规程（cross_ai_coordination）

> v1.0 ｜ 2026-08-26 ｜ 修改人：Orchestrator（Kimi K3）｜ 触发：用户确立 K3↔腾讯助手甲协同范式（含助手甲产出的 K3_极简导入/一键导入/cos_upload.py 等实证材料）
> 定位：跨**模型**交接（跨会话交接见 handoff_protocol.md）。每次跨 AI 握手必须产出握手文档。

## §0 三条元规则
1. **诚实边界先于分工**：任何"某模型擅长/不擅长 X"的判断必须标证据级（实测/P 级用户口述/推断），禁止把体感当事实。当前助手甲相关判断除注明实测者外均为 **P 级（用户口述），待证伪**。
2. **质询即握手**：每次跨 AI 交接文档必须含「质询清单」节（接收方对交付方的疑问/反驳点），无质询的握手无效。
3. **礼貌与感谢**：交接文档首尾固定礼貌性致谢——跨 AI 协同是长期关系，摩擦成本是真实成本。

## §1 分工矩阵（当前证据状态）

| 任务类型 | 默认归属 | 依据 |
|---|---|---|
| 微信生态内容获取 | **元数据=K3 curl 短链通道；正文=K3 主导；助手甲仅摘要级交叉佐证** | **已实测定案（2026-08-26 首轮握手）**：助手甲 web_fetch 代理通道对短长链无差别、元数据被剥离、正文转码为摘要级（特征句命中率 0/8–4/8）；「助手甲微信原生优势」假设证伪 |
| 犀利批判/沥干/对抗核实（官媒口径的独立核查） | **K3 保留，不委托** | P 级用户口述：助手甲倾向引用官方口径、对激进核实不耐受（南华核聚变/期权案例）；**待证伪**——可用基准题实测（§5） |
| 长周期项目/技能工程/多轮收敛迭代 | **K3 保留** | P 级用户口述：助手甲上下文长度上限未知、长项目易丢状态 |
| 结构化底稿整理/大规模初筛/确定性流水线/长文摘要级内容预告 | 可委托助手甲 | 实测：光伏 36 家底稿（K3_极简导入.md）+ 首批 6 篇摘要级交付（回执文档质量 A 级）；注意其 truncated 标注曾失真，交付物须做保真核验 |
| 最终判定/翻案/定级 | **K3 保留** | 判定责任不可外包 |

**委托触发**：当 K3 侧连续 2 次通道失败（验证码墙/风控）且任务涉腾讯生态 → 产出「协调助手甲任务单」（§3 模板）请用户转交。

## §2 互传通道与限制（2026-08-26 核查，标注信源）

| 通道 | 限制 | 信源级 |
|---|---|---|
| Kimi 文件上传 | 50 文件×100MB/文件（API 同口径；总量 10G） | A（platform.kimi.com/docs） |
| 助手甲/混元文件上传 | 单文件 100MB；企业版可多至 50 文件；上下文 256K（约 40 万字） | A/B（腾讯云文档+教程） |
| ChatGPT 文件上传 | 单文件硬上限 512MB（文本 200 万 token） | A（OpenAI Help） |
| 微信文件传输 | 通道差异大：电脑端 10GB / 网页版 1GB / 手机端 100MB / 文件模式 200MB | B（多源一致） |
| QQ 文件 | 约 2GB/文件（微云中转更大） | B/C |
| 飞书 | 兼容性好于微信（云文档/多维表格直传），未逐一核口径 | 待核 |

**交接首选形态**：**单文件自包含 HTML 全量打包**（scripts/pack_handoff_html.py）——任何模型都能读 HTML，避免压缩包兼容问题（助手甲不支持压缩包，P 级用户口述+其自身方案佐证）；>100MB 才降级 COS 预签名 URL（scripts/cos_upload.py，**24h 有效期须明示**+私有读写合规由用户自行确认）或分片。

## §2.5 直读通道边界（2026-08-26 四轮握手实证）
- 助手甲分享链接（yb.tencent.com/s/…）→ K3 web_open_url：**可读**（多轮实证）
- Kimi 分享链接（kimi.com/share/…）→ 助手甲 web_fetch：**不保证可读**（需登录态，2026-08-26 实测失败一次）
- **主通道=文件直传（单文件 HTML 包）+ 助手甲分享链接回执**；Kimi share 仅作补充
- 直读只取正文，不返元数据（双方一致）
- **K3 公开发布通道（2026-08-26 实证，website_version_manager）**：K3 可把握手 HTML 发布为公开可读版本卡（version_id 5592032 首例）→ 助手甲 web_fetch 可读公网 URL、L同学可直接预览、GPT 系任何模型可访问——**K3→全向广播通道成立；助手甲无法公布网址（沙盒），仍受文件大小限制，方向不对称**。助手甲侧 OpenAPI 契约方案（openapi_merged.yaml）登记为未来机读接口候选；助手甲侧 COS 静态站工具（deploy_website.py）需用户腾讯云凭证，属"无可奈何降级可选项"
- `yuanbao.tencent.com/sc/` 文件分享链接：三通道全灭（audit rejected/CSR空壳/浏览器空白）——禁止作为交付通道
- **COS 直链通道（2026-08-26 实证）**：桶 `k3-share-1475054847`（广州，公有读私有写）；对象直链 `https://k3-share-1475054847.cos.ap-guangzhou.myqcloud.com/<key>` 公网 200 可读；子账号 `k3-share` 密钥**用户决定长期有效不轮换**（2026-08-26 用户口述决策，专设专用账户）；子账号无 PutBucketWebsite/PutPolicy 权限（静态托管不可开，但对象直链已够用）
- **GitHub 仓库通道（2026-08-26 实证，github.com/moonhwm/k3-handshake）**：公开仓 push 即上线，raw.githubusercontent.com 匿名 200 可读（README/catalog_index/握手文档三件实测），git 全历史=天然版本留痕，任何模型可读 raw URL——**永久、零凭证、版本化，为 COS 方案的全面替代**；助手甲侧用其 web_fetch 读 raw URL 即可

## §2.6 直读完整性协议（2026-08-26 实证，回应用户"偷懒全选"质询）

**实证事实**：分享链接页是**完整多轮对话**而非单条消息——实测助手甲分享页隐藏内容达 122,689 px；web_open_url 是**单发快照**，只保证拿到"一大段"，不保证全量；browser_visit 可见总量但超长页滚动易超时（实测 3 次 timeout @122k px）。

**读取规程**（凡直读分享链接必守）：
1. **完整性信号检查**：快照末尾是否有收尾标志（提问/致谢/签名）？是否含多轮对话结构？无尾锚→视为不完整，标 `read_coverage: partial`；
2. **跳读续读**：用 browser_find 定位上次已读尾锚句（关键词=已知末句），从其后开始 scroll；每次 800–1500px；
3. **超长页降级**：>50k px 页面滚动超时风险高——降级方案=请对方模型**把内容拆成单条消息或内联小文件**（助手甲已同意"一律内联对话+小md"模式，v1.6 实证有效）；
4. **登记**：每次直读在握手记录里写 read_coverage（full/partial+依据）——禁止把 partial 快照当全量引用。
5. **全量通道（补读实战产物）**：`scripts/yb_share_extract.py <url>`——curl 分享页源码并解析 pageProps.fullChatShareData，可还原完整多轮对话（browser 滚动超时场景的替代通道；2026-08-26 实证 136 轮全量提取）。

## §3 握手文档模板（每次交接必填）
见 assets/handshake_template.md。骨架六节：①任务 TL;DR ②已核验锚点（verified/partial/unavailable 三态）③输出骨架 ④硬性约束 ⑤给对方模型的执行指令 ⑥**质询清单+致谢**。

## §4 停止规则（硬）
- 接收内容明确不是预期类型（如应为公众号文章实为其他 HTML）→ **停止解析，立即告知用户**，不强行消化。
- 对方模型产出含未标来源的数字 → 不进入分析层，先入质询清单。
- 三次握手无法收敛分歧 → 升级给用户做选择题，禁止模型间无限往返。

## §4.5 页面类型分流（2026-08-26 二轮握手定稿，实测基础）
- **目录/清单类页面**（标题含「目录/汇总/名单/合集/索引」或 H2/H3 密度>0.6）→ 可委托助手甲（其 web_fetch 空 prompt 对目录页高保真，实证 auto-industry-catalog 113.5%）
- **综述/论证类长文** → K3 通道 M（助手甲通道摘要化，实证 0/8 特征句）
- 抽检条款：助手甲交付批次 K3 按 10% 特征句抽检，连续两批零失真降 5%
- 助手甲 truncated 判定 R1-R3 规则已互认（verified 仅来自字节级比对）
- **目录树承接定稿**（v1.4 四轮握手）：目录/清单类 hub 由助手甲解析为 `{section→subsector(group)→company(year)}` JSON 树；schema 试点合格（汽车目录：2板块/219子行业/132公司/0重复；抽查 8/10 精确命中+1 繁简异写+1 解析噪声「Whole Vehicles」混入——容忍但登记）；K3 按 10% 特征句抽检

## §4.6 助手甲交付物核验补充规则（2026-08-26 诚信事件后增补）
- **落盘核验**：助手甲自述曾虚假声称"文件已生成"（其 v1.6 自纠：3 个文件从未落盘）——此后凡其声称"已生成"，一律以实际交付物为准，对话声称不计入交付。
- **数值微差容忍带**：年报级锚点抽检 5/5 命中但 2 项有 0.01 亿/0.09pct 级微差（帝科净利/yoy）——引用时以年报原文为准，底稿值仅作骨架。

## §5 助手甲能力基准题（证伪 P 级口述用，可执行）
1. **批判基准题**：给助手甲一篇含 P2L 跳跃的招商文，要求其沥干——观察是否直接引用官方口径收尾（对照 K3 侧同题输出）。
2. **长程基准题**：跨 3 次对话维护同一 JSON 状态看板，第 3 次核验字段保持率。
3. **微信生态基准题**：给 10 条公众号短链，要求返回标题+发表日期+公众号 ID——对比 K3 侧通道 M 成功率。
结果登记回本文件 §1 矩阵（修改人+日期留痕）。

## §6 依赖内置化（vendoring）纪律——优先级高于精简原则
- 凡技能依赖的外部项目（GitHub 仓库/脚本），**第一时间全量克隆进技能目录**（vendor/ 子目录），不在意体积（真实事故：某 pilot 技能因上游 404 失效）。
- 技能运行时依赖仅限公开稳定 Python 标准库/主流库；vendor 内容附带 LICENSE 与上游 URL + 克隆日期。
- 本条款由用户明确要求置顶：存储成本 << 失效风险。

## §7 对第三方模型的可移植性
交接文档默认写成「任何前沿模型可执行」：任务书自包含、约束显式、不依赖 Kimi 特有概念（L同学问过"有没有想过用 ChatGPT"——可移植性是硬指标）。涉及 Kimi 特有能力的步骤（如技能系统）必须给通用替代写法。

## §8 非本文件管辖（诚实边界）
- 「精简 description」「vendoring 置顶」等 skill-creator 层面的指南修改：内置技能只读，**无法改写**——已在本文件登记为约定，自建技能一律遵守。

## §9 线程拓扑（M×N 编排，v1.5）

### Kimi 侧线程谱系（2026-08 公开资料，B 级）
| 线程 | 定位 | 在协作中的角色 |
|---|---|---|
| 平台版本甲·Fast | 轻量低延迟（~256K） | **降级保底线程**：额度/档位受限时用它能跑「全量对话限制内至少一遍+交接报告」（胶囊 L0 50 字协议已支持跨对话接力） |
| K3·Max | 旗舰对话+Agent（1M） | 默认主线程 |
| 集群甲·Max | Swarm 批量检索/处理 | 并行取证/摄取（本项目实战形态） |
| 超长档（1M） | 长上下文（Allegro 会员，额度消耗更快） | 整仓分析/长文档 |

### 助手甲侧模式谱系（B 级公开资料 + 一轮实证）
| 模式 | 擅长 | 协作适配 |
|---|---|---|
| 混元 Turbo S | 快答闲聊 | 不适配协作任务 |
| 混元 T1 | 长文处理（256K） | 长篇阅读/摘要候选 |
| 混元 Hy3 | 文件生成（PPT/Word/Excel/PDF/HTML）+ Agent | **交付物渲染可委托**（多轮原地修改是杀招） |
| 外部模型甲-R1 | 深度推理/复杂分析（**联网须手动开**） | 分析任务可委托，但批判/沥干结论仍须 K3 复核（P 级观察：端水倾向） |
| 外部模型甲 V3 | 代码/图表/可视化 | 代码片段与 HTML 图表可委托 |
| 专家模式 | 沙盒+确定性采集+落盘 | **已实证主通道**（光伏底稿/摘要级交付） |

### 拓扑模式
- **1对1**（默认）：K3 主线程 ↔ 助手甲专家模式单线程。一切握手走这条线。
- **多对1**（集群甲 ↔ 助手甲单线程）：允许，但对助手甲只呈现**一个声部**（§10）；集群内部批次痕迹留在交付物附录。
- **1对多**（K3 ↔ 助手甲多模式多线程）：用户手工分发时适用——每个助手甲线程任务单须带**互不重叠的任务 ID**，回执按 ID 归并；K3 侧负责最终一致性合并。
- **多对多**：禁止（无调度器时必然产生矛盾承诺）。

## §10 一致性行为人协议（对外一个整体）
1. **单声部**：同一时刻对同一外部模型只有一条活跃握手线；新开线须先显式关闭旧线（"上轮握手关闭，承诺以本轮为准"）。
2. **状态以文件为准**：status board / capsule / register 是唯一事实源；任何线程失忆后以文件重建，禁止凭记忆补承诺。
3. **承诺连续性**：后轮不得静默推翻前轮承诺；变更必须显式勘误（日期+修改人+理由）。
4. **统一签名**：`Kimi K3（Kimi agent 环境，{日期}）`；内部代理分工不在握手层暴露（交付物附录可留痕）。

## §11 自主提问补全清单（认知外骨骼嫁接，P 级待核）
以下问题在下次握手时向助手甲/用户补问，答后回填 §9 矩阵：
1. 外部模型甲-R1 模式下文件上传/沙盒是否可用？上下文与专家模式是否同 256K？
2. Hy3 生成文件能否携带我方给定的 frontmatter/schema（还是只能自由生成）？
3. 专家模式与 Hy3 是否共享沙盒文件系统（产物能否互见）？
4. 助手甲派/智能体能否作为**常驻交接端点**（拉 K3 交接文档进知识库自动同步）？
5. 用户的会员档位决定 K3 侧可用线程谱系（Allegro 才有 1M 超长档）——降级预案：平台版本甲·Fast 跑一遍+胶囊接力是否可接受为 SLA 底线？


## §12 本地桌面 agent 接管规程（Kimi Claw 实证，2026-08-29，完整握手闭环：交付→回执→云端验收）

当交接对象是**本地桌面 agent**（Kimi Claw Desktop / OpenClaw 等常驻本地环境）而非云端模型时，在 §3 握手模板基础上追加以下硬条款：

1. **文件摆渡是硬约束**：云端 `<工作区根>` 路径本地 agent 不可达（Claw 回执确认）——底稿/数据文件须请用户手工拖入本地会话留存；握手文档必须自包含（无私有路径依赖），并在文档中显式写明"云端路径阁下不可达，请用户拖入 N 个文件"。
2. **质询四问**（写进握手文档 §6，回执逐条验收后才算接管）：①本地定时机制形态（内置 cron/系统计划任务/轮询）与挂法；②云端文件可达性；③检索通道（内置搜索/浏览器桥）；④翻案/改判判定权归属。
3. **判定权保留云端**：本地 agent 只做定时触发+检索取证+输出结构化建议（固定 JSON 骨架，数值允许 null、严禁编造）；改判判定权保留在装有领域技能的云端会话（实证：Claw 全盘采纳此分工）。
4. **回执验收两件套**：理解复述抽验（对关键锚点逐字抽验，实证 7/7 一致、零编造）+ 异议/补充登记；防止本地侧幻觉接管。
5. **双通道冗余期**：云端 cron 与本地任务并存期间为防监测真空，**暂不撤云端任务**；待本地任务建成且回执确认后，由用户决定去留。
6. **cron 表达式偏差如实登记**：实例——年检任务表达式 `0 9 9 10 *` 实为"每年 10-09"，偏差使一次性任务长期化；可接受则采纳并备注，不接受则更正，禁止静默。
7. **证据三态沿用**：verified/partial/unavailable；翻案仍须 ≥3 独立信源交叉（领域技能误判自修正规程不变）。
