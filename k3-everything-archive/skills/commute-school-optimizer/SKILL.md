# 通勤择校参谋（commute-school-optimizer）

在择校与选址视野下做交通通勤寻优：硬约束一票否决先行 → 候选集全量穷举 → 时间/金钱/机会/隐性成本四核算 → 帕累托非劣分层 → 对接评分引擎与空间壁垒模型 → 敏感性分析 → 输出带证据链的排序。

本技能是 amap-travel-skill v4.0 核心能力（12306 实时查询 + 内置估算降级、铁路局差异化定价核查、hrank 分层管道、/v1/rating 评分对接）的重建，并升级为"通勤×择校"综合模块。注：amap-travel-skill 已全域丢失（史料载两次沙箱销毁），输出 JSON 中的 /v1/rating 字段为预留语义。航线逆向抓取（飞猪 MTOP/途牛 deviceId）**不内置代码**，仅保留合规警示与降级路径，见 `references/data_sources.md`。

## 核心原则（硬条款）

1. **分层不可补偿**：L1 可行性门槛不合格，L2/L3 任何高价值都不得补偿。先用一票否决缩小候选集，再做多目标权衡。
2. **门到门全核算**：通勤时间含候车、换乘、步行接驳，禁止只报车程；机会成本必须区分"可利用时间"（高铁上有桌板可办公学习）与"不可利用时间"（换乘、拥挤站乘）。
3. **穷举类请求以官方底表为准**：禁止凭记忆给样本名单。全量穷举纪律详见 `references/exhaustive_query_protocol.md`。
4. **conf 三级标注**：empirical（实测/官方数据）/ estimated（估算模型）/ assumed（假设），存疑向下取档；所有结论标注 data_cutoff。
5. **落盘纪律**：候选清单、成本明细、穷举覆盖声明写入工作目录文件，禁止只留在对话里。

## 工作流（七步管道）

### 步骤 0：需求澄清与参数确认

- 向用户确认：候选学校/住址清单（或需穷举的范围）、出行频次（次/月）、月交通预算上限、单程时长上限（分钟）、时薪（用于机会成本）、安全红线（如未成年独自跨城、夜间路段）。
- 缺关键参数时用占位假设并标 conf=assumed，在报告中显式列出。

### 步骤 1：L1 可行性门槛（一票否决先行）

对每个"住所×学校"组合逐条核查，任一不通过即淘汰并记录否决原因：

| 门槛 | 默认参考值 | 说明 |
|------|-----------|------|
| 单程门到门时长上限 | 中小学 ≤60 分钟；大学/异地 ≤90 分钟或按用户声明 | 门到门，非车程 |
| 月交通预算上限 | 用户声明；无声明按当地家庭可支配收入 3–5% 提示 | 票价×频次，含优惠后净值 |
| 安全红线 | 未成年独自长距离跨城=否决；深夜末班车依赖=否决 | 一票否决，不可协商 |

- L1 数据获取走 `references/data_sources.md` 的三级降级路径：实时查询 → 估算模型 → 人工录入。
- 输出 L1 淘汰清单（组合 + 否决原因 + 证据来源 + conf）。

### 步骤 2：候选集全量穷举

- 当用户要求"所有/全部/有哪些"类范围（如"某省所有通高铁的城市""某校全部可选通勤方案"）时，严格执行 `references/exhaustive_query_protocol.md`：以官方底表为准，按省/线/站逐一核对，输出穷举覆盖声明（总数/已核/未核清单）。
- 通勤方案层面同样穷举：对同一 OD 至少覆盖 公交地铁 / 骑行+轨道 / 高铁城际 / 校车班车 / 驾车 五类，缺类需注明原因。
- 禁止只给"最有名的两三个方案"。

### 步骤 3：成本四核算

对每个通过 L1 的方案核算四类成本（明细落盘）：

1. **时间成本**：门到门分钟数 = 接驳步行 + 候车 + 乘车 + 换乘步行；高峰期按 +20~30% 拥堵修正。
2. **金钱成本**：月成本 = 单程票价 × 2 × 月出行天数 − 优惠（学生票/月票/计次卡）；铁路注意铁路局差异化定价（广铁等浮动定价可上浮，见 `references/data_sources.md` 核查清单）。
3. **机会成本**：月机会成本 = 时薪 × (门到门分钟 × 2 × 月天数 / 60) × (1 − 可利用时间比例)。高铁整段可利用比例约 0.5–0.8；换乘/拥挤路段取 0。
4. **隐性成本**：疲劳（单程 >75 分钟记疲劳惩罚）、安全暴露、社交断连（跨城通学的同伴网络损失），用 0–10 严重度记为风险项。

用 `scripts/commute_scoring_bridge.py` 做统一核算（stdin 输入候选方案数组，stdout 输出评分引擎兼容 JSON）：

```bash
cat candidates.json | python3 scripts/commute_scoring_bridge.py
```

### 步骤 4：L2 帕累托层（多目标非劣排序）

- 目标向量：（时间成本↓，金钱成本↓，机会成本↓，学校质量↑，居住成本↓）。学校质量与居住成本由用户或下游评分引擎提供，本技能只核算前三项。
- 先求非劣解集（一个方案在所有目标上都不劣于另一方案且至少一项更优，则后者被支配），淘汰被支配方案；**不要**一上来就加权和。
- 对非劣集内方案，再按用户声明的偏好序（时间优先/金钱优先/均衡）排序，并标注"若偏好改变排序如何变"。

### 步骤 5：对接评分与空间模型

- **对接 multi-dimensional-option-scoring**：`scripts/commute_scoring_bridge.py` 的输出即为兼容 dimensions JSON（时间成本/金钱成本/机会成本/可靠性四维，各含 score 0–10、weight、conf、锚点说明、data_cutoff），可直接作为该技能 `scoring_engine.py` 的输入维度片段；权重默认值可覆盖。
- **对接 diffusion-dynamics-extension**：当需要分析"跨城通勤/择校的空间壁垒"（如某城市群学校对本城生源的实际渗透率异常低）时，把门到门通勤分钟数作为其 gravity 模型的距离参数 d（该模型已支持通勤时间语义），导出壁垒系数并强制标注 `unverified_hypothesis`。
- 预留 /v1/rating 语义：输出 JSON 中保留 `rating_endpoint_payload` 字段，供评分系统直接消费。

### 步骤 6：L3 时序层（情景与后悔成本）

- 对非劣集前列方案做情景推演：搬家、换校、票价调整、时刻表变动、政策变化（学区划片调整）下该方案的后悔成本。
- 数据不足以支撑 MCTS/模拟时，退化为三情景表（乐观/基准/悲观），每情景给出成本变化幅度与 conf；禁止在粗糙数据上假装精确模拟。
- L3 只用于在 L2 非劣集内排序与风险提示，**禁止**用 L3 的远期价值（如"该校升学率将上升"）补偿 L1 不合格项。

### 步骤 7：敏感性分析与输出

- 必做敏感性：票价 ±10%、时刻/时长 ±20% 扰动下重算排序，报告排名稳定性；任一头部方案稳定性差时明示"结论对票价/时刻敏感"。
- 输出报告结构：L1 淘汰清单 → 穷举覆盖声明 → 非劣解集与四维成本明细表 → 推荐排序（附证据链与 conf）→ 敏感性结论 → top3_likely_wrong（最可能错的 3 个点，逐条说明若错结论如何改变）→ data_cutoff 与 next_review_date → 机器可读 JSON 附录。
- 全部中间产物（候选清单、成本明细、覆盖声明）落盘到工作目录。

## 元范式纪律

- **conf 三级**：每项数据标 empirical/estimated/assumed；B 级数据不得标 A 级置信度。
- **top3_likely_wrong**：每份报告必须含"最可能错的 3 个点"自我批判节。
- **落盘纪律**：穷举清单、成本明细、覆盖声明写入文件；对话中只给摘要。
- **合规红线**：OTA 逆向接口（飞猪 MTOP/途牛 deviceId）仅限个人研究，存在失效与违反服务条款风险，任何输出须标注该风险；禁止伪造 12306 深链，一律指引官方入口。详见 `references/data_sources.md`。
