## 1. 病理一：单台 AP 的 DNS 转发模块局部崩溃

- **签名**：坐某房间时电脑网页全灭、QQ 正常；换房间/换设备就正常；nslookup 显示服务器=网关 192.168.1.1 且全部超时；ping 公网 IP 通。
- **根因**：多 AP 共 SSID，每台面板的 DNS 转发模块独立；某台崩溃后，只有连该面板的终端中招。Windows/老 iOS 无 DNS fallback，全灭；HarmonyOS 新机有备用 DNS，免疫。
- **确诊**：三命令矩阵 + 换位置复测（关开 WiFi 强制换 AP 后恢复 = 实锤）。
- **处方**：终端手动固定 223.5.5.5 / 119.29.29.29（终局）；重启该台 AP（临时）；固件升级 + 频繁复发则换面板。

## 2. 病理二：AP 上联端口非千兆协商

- **签名**：交付报告/APP 告警"检查端口协商速率：非千兆全双工"（实测 3/8 台中枪）；高负载时该 AP 上 DNS、视频等业务间歇性卡死。
- **根因**：AP162 支持 802.3ab 千兆自协商，协商成百兆 = 水晶头只压 4 芯 / CAT5 老线 / 交换机端口配置问题。WiFi6 空口 2.4Gbps 被百兆上联卡死。
- **确诊**：设备详情 → 接口页看 GE0/0/0 速率；APP 诊断告警页。
- **处方**：APP 改不了，转装维：交换机侧强制千兆或重做水晶头/换线。

## 3. 病理三：漫游粘滞

- **签名**：iPhone 从负一层上到二层后不能上网；APP 显示该终端仍挂在负一层 AP 的下联列表里，信号穿两层楼板。
- **根因**：默认漫游阈值 -75/-80 太保守，老终端死撑远 AP。
- **处方**：漫游调优改 -65/-70，开粘滞终端优化、5G 优先；无 AP 覆盖的房间（盲区）靠阈值逼终端切到邻近楼层 AP。

## 4. 病理四：2.4G 信道拥堵

- **签名**：2.4G 干扰分析 CH1~CH7 强度 58~86；8 台面板必然复用 1/6/11 三个不重叠信道。
- **处方**：Wi-Fi 自动调优每月一次；手动调优时 2.4G 优先 CH11；同楼层相邻面板 5G 信道错开；5G 开 160MHz 极速频宽。

## 5. "重启 AP 就好了"的真相

实战复盘：某次"重启后恢复"实为 AP 凌晨**固件自动升级重启**（纳管通道日志：配置通道断连，原因=设备升级），DNS 模块随之复位。教训：

- 看到"重启就好"先查纳管通道状态/升级日志，区分人工重启与自动升级。
- 自愈时刻（"帮别人查资料突然通了"）多为安全软件后台扫描结束或 AP 模块瞬时恢复，不可复现，不作归因。

## 6. 维护节奏表

| 频率 | 动作 |
|---|---|
| 每月 | Wi-Fi 自动调优 + Wi-Fi 体检 + AP 诊断各跑一次；重点面板单独重启 |
| 每季度 | 全屋 AP 断电 30 秒重启（或装维远程重启）；检查固件/补丁版本 |
| 故障时 | 先定位故障终端所连 SN → 单独重启该面板 → 无效再走五层定位 |
| 长期 | 全家终端手动固定公共 DNS；频繁复发的面板申请更换 |

## 8. 沟通话术（对电信/装维）

> "我家 N 台 AP（SN: …）上联端口没协商到千兆全双工，麻烦远程把对应交换机端口改强制千兆；改不了需上门查水晶头是否只压 4 芯或 CAT5 老线。AP162 硬件支持 802.3ab 千兆自协商，这是链路侧问题。"

> "某台 AP（SN: …）DNS 转发疑似反复崩溃，已用终端手动 DNS 绕过；请查该面板固件版本并评估更换。"
