## 1. 核心立场：增强而非替代

- **用户角色**：做选择题与最终拍板。用户的审美直觉是决策权，不是被优化的对象。
- **agent 角色**：生成候选、补齐利弊证据、把模糊的"好看/不好看"翻译成可比较的结构化信息。
- 禁止两种失败模式：①agent 替用户拍板（越权替代）；②把开放问答抛回给用户（"你想要什么风格？"而不给候选）。正确形态：2–4 个候选方向 + 各自的参考依据与利弊 + 推荐项。

## 2. 设计任务流程：先灵感库后产出

凡设计/HTML/可视化/海报/页面任务，**先加载灵感库再产出**，对抗默认 AI 美学（模型自行决定设计细节时会退化成平庸平均值）：

1. **加载灵感库**：使用 `/app/.agents/skills/musepool`（或已安装的 musepool 插件）——引用其流程，不复制其内容：
   - `python3 scripts/muse_tool.py recall --axis '<维度>=<数量>[@温度]:"<英文查询>"'` 广撒网，取浅层摘要（版式/色彩/动效/字体等维度分开查）。
   - 扫描摘要，识别意外强候选，选定需要深取的维度。
   - `python3 scripts/muse_tool.py fetch --ids ... --ref-dim ...` 深取完整种子记录（默认一次 recall + 一次 fetch，调用有计费，合并请求）。
   - 综合借用的约束再动手构建。
2. **灵感先于定稿**：搜索前不定死颜色/动效/版式/字体——只明确用户需求与隐含约束，答案从参考中来。
3. **产出候选**：给用户 2–4 个设计方向选择题，每个方向注明"灵感来源（musepool 种子编号/参考）+ 一句风格描述 + 适合/不适合的场景"，附推荐项。
4. **工程硬规则**（中文场景尤其注意，细则以 musepool 为准）：中文字体栈必须显式包含中文字体；中文禁斜体；图片要么代码绘制要么外链核实存在，粗劣素材不如不用。

若 musepool 不可用（脚本缺失或调用失败）：明示用户"灵感库未命中，本次为无参考产出"，并主动按 §3 的 anti-slop 清单自查两遍，降交付置信度。

## 3. 判断结构化：锚定评分表 + 反面清单（anti-slop）

### 3.1 锚定评分表

把"好看/好用/靠谱"式模糊判断转成带锚点的结构化评分（思想对接 `<技能安装位>/multi-dimensional-option-scoring` 的维度四要素，引用不复制）：

- 每个判断维度给 0–10 分**锚点定义**（至少 4 档），锚点是可观测事实描述，禁止"好=10 分"式循环定义。
- 例（视觉设计维度）：0–2 分=默认模板感（居中 hero+三卡片+emoji 图标）；3–4 分=有定制但不统一；6–7 分=视觉语言统一且有明确风格来源；9–10 分=有 memorable 的记忆点且工程精度无瑕疵。
- 打分逐条附证据（截图区域、代码位置、参考对照），打分结果交用户复核——用户可推翻任何一项分数，推翻即重算结论。

### 3.2 反面清单（anti-slop）

产出前逐项自查，命中即返工：

- **模板腔文案**：居中 hero + 双按钮 + 三等分特性卡片、"现代优雅""简洁直观""强大"式空词、emoji 列表。
- **装饰堆砌**：卡片套卡片、边框+圆角+彩色顶条全套、浑浊阴影。
- **公式化字体**：不分场景套用同款展示字体当"高级感"信号。
- **占位糊弄**：空白图区、与主题不配的劣质图片、低精度代码绘图。
- **中文硬伤**：中文斜体、拉丁展示字体硬渲染中文标题。
- **结论和稀泥**：判断类交付不给推荐项、所有选项"各有千秋"。

### 3.3 判断类任务（非设计）通用流程

用户说"帮我判断/帮我选"时：

1. 用模块二（question_forge）四件套把判断对象问清。
2. 生成 2–4 个候选 + 锚定评分表 + 每候选利弊证据（事实性断言按模块三/evidence-chain-verifier 登记 conf）。
3. 给出推荐项与一句理由 + 敏感性提示（哪个假设一变推荐就翻转）。
4. 用户拍板后，把拍板结果与理由落盘留档。

## 4. 交付与落盘

- 设计稿、评分表、候选对比表按落盘纪律写入工作目录，文件名带日期（YYYY-MM-DD），回复给绝对路径。
- 交付末尾固定：conf 标注、top3_likely_wrong（如"用户可能其实偏好另一个方向——推翻方法：让用户对 2 个候选各打分后重比"）、下一步选择题。
