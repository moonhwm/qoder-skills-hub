# commute 模块：通勤×择校/选址七步寻优管道

> 整合自 commute-school-optimizer。本模块是多目标决策管道，可调 railway/amap 模块取数。

## 七步管道

### 步骤 0：参数确认
候选住所×学校/就业地清单、出行频次（次/月）、月交通预算、单程时长上限、时薪、安全红线。缺参数用占位假设并标 conf=assumed、报告显式列出。

### 步骤 1：L1 可行性门槛（一票否决，不可补偿）
- 单程门到门时长：中小学 ≤60min；大学/异地 ≤90min 或按用户声明
- 月交通预算：无声明按当地家庭可支配收入 3–5% 提示
- 安全红线：未成年独自长距离跨城=否决；深夜末班车依赖=否决
- 输出 L1 淘汰清单（组合+否决原因+证据+conf）

### 步骤 2：候选穷举
同一 OD 至少覆盖 公交地铁/骑行+轨道/高铁城际/校车班车/驾车 五类，缺类注明原因；禁止只给最有名的两三个方案。穷举范围类请求以官方底表为准。

### 步骤 3：成本四核算（本模块核心脚本）
```bash
cat candidates.json | python3 scripts/commute_scoring_bridge.py
```
输入字段（中英文键均可）：名称、单程分钟（门到门含候车换乘步行）、换乘次数、单程票价、月出行次数（往返次数，脚本×2）、可利用时间比例（高铁整段 0.5–0.8，换乘/拥挤段 0）、时薪、可靠性、conf。

四类成本：
1. 时间成本：门到门分钟数；高峰 +20~30%
2. 金钱成本：单程票价×2×月次数 − 优惠；铁路注意路局差异化定价
3. 机会成本：时薪×(门到门×2×月次数/60)×(1−可利用比例)
4. 隐性成本：疲劳（单程>75min 记惩罚）、安全暴露、社交断连

### 步骤 4：L2 帕累托层
目标向量（时间↓金钱↓机会↓学校质量↑居住成本↓）；先求非劣解集，再按用户偏好序排序；标注"若偏好改变排序如何变"。

### 步骤 5：对接评分引擎
脚本输出即 multi-dimensional-option-scoring 兼容 dimensions JSON（时间/金钱/机会/可靠性四维，含 score/weight/conf/锚点/data_cutoff），可直接喂 `<技能安装位>/multi-dimensional-option-scoring/scripts/scoring_engine.py`。

### 步骤 6：L3 时序层
三情景表（乐观/基准/悲观）评估搬家/换校/票价调整/政策变化的后悔成本；数据粗就退化三情景，禁止假装精确模拟；L3 远期价值不得补偿 L1 不合格。

### 步骤 7：敏感性与输出
票价 ±10%、时长 ±20% 扰动重算排序；报告排名稳定性。输出结构：L1 淘汰清单 → 穷举覆盖声明 → 非劣解集四核算明细 → 推荐排序（附证据链 conf）→ 敏感性 → top3_likely_wrong → data_cutoff/next_review → 机器可读 JSON 附录。中间产物全部落盘。

## 与其他模块的组合

- 跨城方案：railway 模块取精确票价（conf=empirical），amap 模块取两端接驳（conf=estimated）
- 实证案例：衡阳↔长沙/广州就业通勤矩阵（med-career-transition-L 项目，2026-08-24）——「广州→衡阳回家」时间成本触底 0 分，「长沙工作+衡阳回家」获量化支持
