# 蒸馏规程细则（distill_protocol）

## 目录
1. 蒸馏卡格式 2. 归宿映射决策树 3. 版权边界 4. 外部模型协助判定（助手甲等）

## 1. 蒸馏卡格式（每篇 ≤30 行）

```
### seq N《标题》（原文链接，conf=转述/仅摘要级）
- 核心模式：3-6 条（方法/结构/纪律，用自己的话）
- 与归宿技能现制的异同：必须实读归宿技能现制文件后写，禁止凭空对照
- 可落地增量建议：切成可直接落笔的粒度（写什么、进哪个文件哪节）
- 证据强度：全文级 / 摘要级 / 上游 diff 实证
```

## 2. 归宿映射决策树

1. 文章主题与某技能 description 触发词重合 → 候选归宿；
2. 候选归宿已有同主题 references → 增量进该文件；无则新建一层 references
   （SKILL.md 必须显式链接新文件）；
3. 无归宿技能 → 登记"待收录"，不为单篇文章新建技能（奥卡姆）；
4. 归宿疑似多个 → 取方法模式主归属，其余写互指一行；
5. 归宿技能无工作副本（安装位只读）→ 登记待集群通道，不强行落笔。

## 3. 版权边界

- 蒸馏=方法模式层面改写，禁止整段复制原文；引原文短语≤15 字且加引号注出处；
- 开源 skill 代码按 license（如 MIT 注明出处）；文章本身默认不授权复制；
- 字幕组式注记同样适用于蒸馏产物（distill 文档头部注来源与授权范围）。

## 4. 外部模型协助判定（助手甲等）

默认不需要外部模型协助。三种情形才引入跨模型验证（如腾讯助手甲/外部模型甲）：
①蒸馏结论与我方现制冲突且 Conflict→人工前想多一证；②方法模式涉及专业领域
（如医学/法律）需要第二意见；③年度复检时做一次跨模型抽验。
引入时按 cognitive-exoskeleton 的跨模型验证模块执行，结论标 conf=外部模型转述。
其余情形如实声明"不需要助手甲协助"——不为仪式感引入外部依赖。
