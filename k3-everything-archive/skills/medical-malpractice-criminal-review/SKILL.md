# 医疗事故刑事评估员（medical-malpractice-criminal-review）

> 版本：v1.2.2（2026-08-24 同步）。跨会话迭代产物：v0.4.0-rc → v1.0.0（引擎修复、阻尼收敛、Sigmoid 映射）→ v1.0.1（真实案例校准）→ v1.1.0（严重不负责任检查、R9 红线、批量对比）→ v1.2.1（数据集 v3.3：60 案例，A 级 42 / B 级 18）→ v1.2.2（文档-代码同步：罪名判定伪代码对齐校准后代码、params_config 解包 engine_params 修复、版本号单一来源）。
> **免责声明**：本技能输出为信息性风险分析，不构成法律意见。正式决策必须咨询执业律师。

## 核心能力

- **五维量化评分**：医疗过错、因果关系、损害后果、注意义务、减责事由
- **九轮红线核查**：R1-R9 触发检测，自动上调责任等级
- **严重不负责任检查**：七种法定情形量化映射，兜底条款争议自动识别
- **司法风险提示**：7 种分级特殊情形（致命/重大/一般/参考），基于真实判例
- **批量案件对比**：支持 2+ 案件横向对比、相似度分析、趋势统计
- **诊疗阶段分段**：首诊/交班/术后观察/术中/出院后分阶段责任评估

## 工作流程

1. **证据收集**：引导用户提供病历资料、诊疗记录、鉴定意见、证人证言
2. **维度评分**：调用 `scripts/scoring_engine.py` 对五维度进行量化评分
3. **红线核查**：执行 R1-R9 九轮红线检测
4. **严重不负责任检查**：七种法定情形量化映射，识别兜底条款争议
5. **特殊情形检查**：未做尸检、专家意见、多因一果、次要原因力、连锁漏诊、新手医生
6. **迭代收敛**：运行 auto_correct 至收敛（最多 5 轮）
7. **结果输出**：生成包含责任比例、等级、罪名、建议、司法风险提示的结构化报告

## 五维评分体系

| 维度 | 权重 | 红线阈值 | 说明 |
|------|------|----------|------|
| 医疗过错程度 | 0.30 | 85 | 诊疗行为偏离规范的程度 |
| 因果关系强度 | 0.25 | 80 | 过错与损害后果的因果关联 |
| 损害后果严重性 | 0.20 | 90 | 死亡/伤残等级、精神损害 |
| 注意义务违反 | 0.15 | 85 | 是否违反核心诊疗义务 |
| 免责/减责事由 | 0.10 | — | 患者自身因素、系统性因素、其他医疗机构过失（注意义务不转移） |

## 红线规则 (R1-R9)

触发任意红线将显著上调责任等级，并标注需人工复核：

- **R1** 伪造、篡改病历资料
- **R2** 隐匿、拒绝提供病历
- **R3** 未取得执业资格独立行医 → 直接定性非法行医罪
- **R4** 明知无救治条件仍强推手术
- **R5** 术后未履行基本观察义务致死亡
- **R6** 重复同类过错致多次损害
- **R7** 拒绝会诊或转诊致病情恶化
- **R8** 使用未经批准的医疗器械/药品
- **R9** 无相应处方权使用限制级药物（南阳吴某案校准）

## 严重不负责任七种法定情形

医疗事故罪的入罪门槛是"严重不负责任"，以下七种情形是司法实践中认定的**法定标准**：

| 情形 | 关键词 | 严重级别 | 置信度惩罚 |
|------|--------|----------|------------|
| 一、擅离职守 | 离岗、不在岗、值班睡觉 | 致命 | -0.25 |
| 二、拒绝救治 | 拒收、拖延、无床位 | 致命 | -0.25 |
| 三、擅自试验 | 未经批准、未伦理审查 | 重大 | -0.15 |
| 四、违反查对 | 未做皮试、输错血、开错刀 | 重大 | -0.15 |
| 五、违规药品器械 | 过期、变质、无处方权 | 重大 | -0.15 |
| 六、违反核心规范 | 违反无菌操作、禁忌症 | 一般 | -0.10 |
| 七、兜底条款 | 漏诊、疏忽（存在司法争议） | 争议 | -0.05 |

## 罪名判定逻辑

以下伪代码与 `scripts/scoring_engine.py::_determine_crime_v3` 一致（v1.2.2 同步，以校准后代码为准）：

```
if 多因一果阻却（mitigation_type ∈ {patient_factor, systemic_factor} 且 mitigation > 60 且 ratio < 50%）:
    → 不构成犯罪（刘希河案校准；v1.2.1 起先判多因一果阻却，避免误入后续罪名分支）
elif R3触发（完全无执业资格）:
    if 因果关系强度 < 50分:
        → 非法行医罪（基础情节，情节严重）
    else:
        → 非法行医罪（致人死亡/严重损害）
elif R9触发（有执业资格但超权限用药）:
    → 医疗事故罪（非非法行医罪，南阳吴某案校准）
elif 责任比例 < 30%:
    → 不构成犯罪
elif 损害后果 >= 90分 且 责任比例 >= 60% 且 减责事由 < 50分 且 因果关系 >= 60分:
    → 过失致人死亡罪（刑法233条，褚某案校准；v1.2.1 校准依据：责任比例阈值由 50% 提高至 60%，避免医疗事故罪被过度升级为过失致人死亡罪）
else:
    → 医疗事故罪（刑法335条）
```

## 特殊情形与司法风险提示

| 情形 | 关键词 | 级别 | 惩罚 | 参考判例 |
|------|--------|------|------|----------|
| 未做尸检 | 未做尸检、未行尸检、家属拒绝尸检 | 致命 | -0.25 | 李建雪案（2020年无罪） |
| 专家意见支持无罪 | 专家论证、符合诊疗常规 | 参考 | -0.02 | 温红案（2023年无罪） |
| 多因一果 | 系统性因素、设备不到位 | 参考 | -0.02 | 刘希河案（2016年无罪） |
| 兜底条款争议 | 漏诊、未查体 | 重大 | -0.15 | 韩杰案（2026年有罪争议） |
| 次要原因力 | 次要原因力、参与度低 | 参考 | -0.02 | 温红案（2023年无罪） |
| 连锁漏诊 | 其他医院、此前就诊 | 一般 | -0.05 | 注意义务不转移 |
| 新手医生 | 刚执业、经验不足 | 参考 | -0.02 | 刘希河案（技术水平局限≠严重不负责任） |

## 脚本用法

### 单案例评分

脚本通过 Python API 调用（须在 scripts 目录下，或先 `sys.path.insert`）：

```python
import sys; sys.path.insert(0, "scripts")
from scoring_engine import ScoringEngine
engine = ScoringEngine()
result = engine.evaluate(case)              # case 结构见下
report = engine.generate_report(result, case)
```

`case` 输入结构（五维 score 0-100、confidence 0-1、notes 列证据；evidence 为 R1-R9 布尔）：

```json
{"case_id": "CASE-001",
 "dimensions": {"medical_fault": {"score": 78, "confidence": 0.85, "notes": ["..."]},
                "causation": {...}, "damage_severity": {...},
                "duty_violation": {...}, "mitigation": {...}},
 "evidence": {"r1": false, "r2": false, ..., "r9": false}}
```

直接 `python3 scripts/scoring_engine.py` 运行内置 DEMO 案例自检。收敛参数见 `templates/params_config.json`：当前仅 `engine_params` 下的收敛参数可调（convergence_threshold / max_iterations / auto_correct_enabled / red_line_boost / mitigation_floor，v1.2.2 起经 `engine_params` 子键解包生效）；维度权重与红线定义为代码内置常量，不可经配置覆盖。

### 批量案件对比

直接运行 CLI 会用内置基准三案（韩杰案/李建雪案/温红案）自检：

```bash
python3 scripts/batch_compare.py
```

自定义 2+ 案件用 Python API（须在 scripts 目录下调用，因其 import scoring_engine）：

```python
import sys; sys.path.insert(0, "scripts")
from batch_compare import run_batch_comparison
result = run_batch_comparison([case1, case2])  # case 结构同单案例输入
# 输出：横向对比表、罪名分布、红线汇总、趋势统计、相似度矩阵
```

## 防偏硬条款

1. 所有证据标注 conf 等级（实证/估算/假设）；结论置信度不得高于其最弱支撑证据。
2. 报告末尾必须列出**最可能错的 3 个点**及各自影响方向。
3. 强制标注数据截止时间与建议复核日期。
4. 措辞纪律：仅有 B/C 级证据时用"高度疑似"，不得用"系/确为"；情绪化措辞禁止进入正式结论。
5. 统计口径引用需独立复核后再作为旁证（跨会话数据集可能未持久化，2026-08-24 实测）。
