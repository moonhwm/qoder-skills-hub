# 技能全量导入机制（机制 A/B/C + 诚实边界）

用户核心诉求：切换对话/项目时不必每次手动点击技能插件按钮。先记住诚实边界，再选机制。

## 诚实边界（禁止越界承诺）

- Kimi 的技能加载由**平台**按各技能 SKILL.md 的 description 匹配自动触发；agent **无法编程强制平台勾选 UI 按钮**，也没有 API 可以批量开关技能。
- 因此「全自动批量勾选」做不到，禁止向用户承诺。三条机制合计能做到的最好效果是：**把「每次点 N 个按钮」降为「一句话 + 至多一次确认」**。
- 能做的：让一句话（如「继续项目」）稳定命中伞技能；让 agent 在 5 秒内列出「本任务需要哪几个技能」；让用户只需点一次确认（或在支持多选的 UI 上照单全选）。

## 机制 A：伞形触发（本技能即伞）

- 原理：本技能 description 开头放置宽触发语，使用户在任何新对话说「继续项目 / 加载项目环境 / 继续上次进度」时，平台自动命中本技能。
- 触发后规程（即 SKILL.md 的开场规程）：
  1. 读 `<上传区>/MASTER_SKILL_INDEX.md`（没有就跑机制 B 现场生成）；
  2. 对照当前任务，列出相关技能清单（技能名 + 一句话用途 + 触发词）；
  3. 请用户一次性确认勾选（至多一次确认），随后按任务加载使用。
- 维护责任：新建用户技能时，其 description 里必须含足够触发词，否则机制 A 列得出、平台却触发不到。

## 机制 B：索引脚本（scripts/build_skill_index.py）

- 命令：`python3 scripts/build_skill_index.py [--user-only]`
- 行为：扫描 `<技能安装位>/` 与 `/app/.agents/skills/` 下全部 `SKILL.md` 的 frontmatter（`--user-only` 只扫前者），生成 `MASTER_SKILL_INDEX.md`，列含：技能名、触发词摘要、路径、一句话用途、是否用户技能。
- 落盘策略：优先写入 `<上传区>/MASTER_SKILL_INDEX.md`（跨会话可见）；upload 不可写时退写 `<输出区>/MASTER_SKILL_INDEX.md` 并**提示用户手动转移到 upload**。
- 使用时机：新会话开场发现索引缺失/过期；会话收尾规程第 2 步强制重跑。
- 纯标准库实现，已在真实双目录环境实测。

## 机制 C：元引用常驻（统一前缀标签）

- 做法：在每个用户自创技能的 description 里加统一前缀标签「[项目技能]」，例如：
  `description: "[项目技能] 城市舒适度评估：……"`
- 收益：用户在技能面板一眼区分自建技能与内置技能，配合机制 A 给出的清单可批量勾选，不漏勾。
- 规程：本会话内新建/修改任何用户技能时，检查并补上该前缀；发现缺前缀的旧技能，顺手补上并告知用户。
- **现状注记**：「[项目技能]」前缀为**增量约定**——存量 18 个用户技能未补齐，下次批量维护时统一执行，不逐个返工。

## 组合使用（推荐顺序）

1. 用户新对话说「继续项目」→ 机制 A 命中本技能；
2. agent 读/建 MASTER_SKILL_INDEX（机制 B）→ 列出本任务相关技能（带 [项目技能] 标签，机制 C）；
3. 用户一次确认 → 开工。

## 反模式（禁止）

- 禁止说「我已自动为你加载全部技能」——做不到；
- 禁止在没有索引的情况下凭记忆列技能清单——先跑机制 B；
- 禁止把 MASTER_SKILL_INDEX 只写在 output 而不提示转移——下会话就丢了。
