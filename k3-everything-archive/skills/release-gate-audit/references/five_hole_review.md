# 五道漏洞审查报告模板

> 每道不过即退回修订；全部通过才进入用户确认环节。

```markdown
# <发布事项>·事前审查报告（日期）

## 一、五道漏洞审查
| 漏洞面 | 审查结论 |
|---|---|
| 范围是否封闭 | <发布物清单是否穷尽？白名单还是开口集合？> |
| 时限是否明确 | <存续期/复审周期> |
| 撤销路径是否存在 | <怎么撤回？撤回对已扩散副本无效的风险评估> |
| 逃逸面（组合放大） | <git 历史/路径泄露/词表泄露/聚合呈现 等> |
| 与红线是否冲突 | <逐条对照：凭证铁律/第三方隐私/实名记录聚合风险> |

## 二、可发布性分级清单（P0/P1/P2，逐项）

## 三、脱敏扫描结果（preflight_scan.py 真实输出摘要 + report.json 路径）

## 四、待用户确认事项（编号清单）

**结论：通过 / 有条件通过（条件列明） / 不通过**
```

## 实战样例

`<输出区>/github_publishing_review_v1.md`（2026-08-29）：结论=有条件通过（白名单+脱敏+新库无历史），三点待用户确认后执行。该样例同时示范了「既有公开库的追认复审」分支（moonhwm/sleepless-flower-under-sealevel 存在性核验 + README 脱敏抽查）。
