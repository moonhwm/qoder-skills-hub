任何内容流出沙箱前的**强制闸门**。条款来源：v2.5.8 代码外发禁令（默认禁止，用户拍板也须主程序事前审查）。

## 流程（不可跳步）

1. **分级**：对待发内容逐个判 P0/P1/P2（rubric 见 [references/privacy_tiers.md](references/privacy_tiers.md)）。P2 直接终止并说明理由。
2. **脱敏扫描**：`python3 scripts/preflight_scan.py <目录> --blocklist <私有词表> --json report.json`。
   - verdict=BLOCK → 禁止推送，逐项修复后复扫；
   - verdict=REVIEW → 命中项逐条人工过目（误报登记白名单理由）；
   - verdict=PASS → 进下一道。**禁止编造扫描结果——必须是脚本真实输出**。
3. **五道漏洞审查**：按 [references/five_hole_review.md](references/five_hole_review.md) 模板出报告（范围封闭/时限/撤销路径/逃逸面/红线冲突），任一不过即退回。
4. **用户确认**：写类例外——报告+扫描结果+分级清单交付用户，获明确批准后才执行推送。
5. **推送纪律**：全新仓库 + 单次 squashed 首提交（禁带历史）；凭证文件名/key 模式列入黑名单；推送后登记库名/URL/可见性进台账。
   - **网页发布槽位核验**（2026-08-29 网址混淆事件实证）：部署目录（如 `app/`）是**单槽位**——build_version 前必须核验槽位当前承载内容（页面标题/文件指纹），确认是目标页面再发布；多页面并行时维护「快照 ID↔页面↔槽位」对照表，禁止凭记忆发布；发现错发→当轮如实报告+换回正确内容+重新快照+修订对照表，不假装无事。
6. **售后**：公开库每季度复审一次公开适宜性（内容会随时间变化）；既有库转入同周期复审。

## 反幻觉条款

扫描与审查只报真实运行结果；未跑扫描不得声称"已脱敏"；私有词表未提供时在报告中显式标注「词表缺测」。发现已发布内容含漏网 PII → 当轮如实报告 + 给出处置路径（删库/删文件/轮换凭证），不假装无事。
