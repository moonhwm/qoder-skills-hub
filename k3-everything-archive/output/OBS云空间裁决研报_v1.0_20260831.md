## 一、决策背景

据审议书载，用户在华为云持有消费级「云空间」套餐：已用 429GB、总额度 2TB，订购期至 2027 年 11 月 2 日。该容量产生于一次误购语境——原本意图采购约 400G 规模的服务，实际落地为 2TB 消费级云空间，由此形成约 1.5TB 的账面余量。

用户的原始诉求是：能否把这 1.5T 余量「接通」给 agent 基建使用，使其成为程序化可读写的大容量存储，避免资源闲置。这一诉求连同多云格局（华为/腾讯/阿里三栈分工）、「外包到华为云+隔离账目」的设想，一并提交审议。

审议书已就多云格局作出总裁决：华为云为主栈（agent 基建+网站+备案集中投入），腾讯云保留冻结（不轻易迁移、不轻易触碰，维持域隔离），阿里云不引入（当前无任何独占任务域）。本件研报聚焦其中的存储裁决支线：1.5T 消费云空间何去何从、agent 侧对象存储采用何者、以及因用户质疑触发的接口核查所引发的勘误与路线重估。

需要前置说明的背景约束：个人备案的网站依法不能用于经营活动；网站定位为现阶段私域推送、未来可能升级为企业法人代表名下的公司门户。存储裁决须与该备案现实相容。

## 二、裁决主文

经审议与勘误核查，存储事项裁决三条如下。

### 裁决一：OBS 仍是正道

agent 基建侧的对象存储采用华为云 OBS。据审议书载，理由为「有 API、按量计费、与备案站点同栈」——三点分别对应程序化接入能力、成本弹性与主栈一致性。勘误之后，此裁决不仅维持，而且加固：Drive Kit 路径经查证虽技术上可行但脆弱（详见第三、六节），不足以动摇 OBS 的主存储地位。

### 裁决二：1.5T 消费云空间转为手机端备份+分享链接分发

消费级云空间不承担 agent 程序化存储职责，转为两个正当用途。据审议书载：

1. **手机端备份与图库之家**：该空间本就是手机备份、图库的归宿，429GB 的既有用量说明其在正常使用中，无须强行改道。
2. **分享链接分发，服务私域推送线**：云盘分享链接恰好能服务「私域推送」场景——大文件（知识卡 HTML、报告 PDF）经云盘手动分享链接推送给私域对象，零 API 需求，闲置容量立刻变为推送通道，且不占用工程队列。

据审议书原文口径：「2TB 到 2027/11，与其心疼不如物尽其用。」

### 裁决三：Drive Kit 老路列为观察项（spike 工单挂线三，口令「试 Drive Kit」）

据勘误文书载，Drive Kit（HMS Core）REST API 真实存在，接通 1.5T 技术上可行；但受 token 刷新、scope 审批、HarmonyOS NEXT 弃用、ToS 擦边四重脆弱性约束，不作主路径采用，列为【观察项】。后续验证以 spike 工单形式挂在线三，启动口令为「试 Drive Kit」。Cloud Kit Web 端接入能力正式开放后，对本条路线重新评估。

## 三、核查证据链

本次核查因用户质疑触发（「云空间 1.5T 接不通，但 kimi work 说有鸿蒙开发者等接口」），按 G2 对口性与 L1 一手复核纪律执行联网核查。据勘误文书载，证据链四环如下，证据等级与来源名称一并标注：

| 环节 | 结论 | 来源 | 证据等级 |
|---|---|---|---|
| ① Drive Kit 存在性 | Drive Kit（HMS Core）REST API 真实存在：OAuth2（scope drive）+ REST 可程序化读写用户云盘；有第三方服务端实证 | 华为开发者联盟官方文档；第三方实证博客 | 存在性成立（一手文档+三方实证互证） |
| ② NEXT 弃用 | HarmonyOS NEXT 已停止提供 Drive Kit，REST 老路存续期不明 | 论坛技术支持（官方技术支持确认） | 硬约束成立（官方渠道确认） |
| ③ Cloud Kit 定位 | 替代品 Cloud Kit 为「应用自有数据端云同步」，须开发鸿蒙 App 作桥，非通用文件仓 | 华为开发者联盟官方文档 | 定位成立（文档定性） |
| ④ Web 端接入新能力 | HDC2026 宣布 Cloud Kit 新增 Web 端接入+云图库，陆续开放中，当前不可用 | HDC2026 报道 | 方向可信、时点未定（发布会口径） |

证据链的逻辑闭环为：环节①推翻原「无公开 API」的绝对断言（kimi work 说法部分成立）；环节②给出该路径的存续期天花板，使其即使可行也不堪主用；环节③排除「Cloud Kit 可直接替代」的误判——它是应用数据同步框架而非通用文件仓，接入成本是「开发一个鸿蒙 App 作桥」；环节④指出未来的变量——Web 端接入若正式开放，桥接成本结构将改变，届时触发重估。

四环合起来支撑裁决三：可行但脆弱，列观察项而非否决项，亦而非采纳项。

## 四、勘误与纪律登记

据勘误文书「纪律登记」节载，本次登记两条：

1. **失实断言入册**：审议书第三节原表述「消费级云空间没有公开 API，agent 无法程序化读写」过于绝对，经核查为失实断言，勘误入册，同「72 份 CSV」先例处理。原断言的错误性质是「把『未见通用开放接口』误述为『不存在公开 API』」——Drive Kit REST API 的存在即构成反例。
2. **外部断言一手复核条款再次验证**：kimi work 的外部断言经一手复核后部分采信（「该接口存在」为真，但其所暗示的可用性受 NEXT 弃用等约束折损）。「该文存在」类断言复核条款的必要性再次得到验证，纪律维持。

## 五、后续挂账

2. **Cloud Kit Web 端重估触发器**：HDC2026 宣布的 Cloud Kit Web 端接入+云图库「陆续开放中」，正式开放后即触发对 Drive Kit/Cloud Kit 路线的重新评估，观察项届时升级审议。
3. **moonclaw.top 备案线**：按审议书，现阶段以个人主体发起备案、网站定位私域推送，与个人备案相容性较好；未来若升级为公司门户（经营性质），届时须变更为企业法人代表名下公司备案或新增备案。此线与本存储裁决并行推进，互不被阻塞，此处一句带过。

## 六、风险与边界

1. **token 1 小时过期**：Drive Kit OAuth2 访问令牌有效期短，须持续刷新维护，对「无人值守的 agent 长任务」构成运维负担，是该路径脆弱性之首。
2. **scope 审批不确定性**：drive scope 的开通审批流程与门槛存在不确定性，个人开发者能否稳定获得并保有该权限，未经实证，留待 spike 工单验证。
3. **NEXT 弃用存续期不明**：HarmonyOS NEXT 已停止提供 Drive Kit，REST 老路在存量设备与接口层面尚能运行，但官方支持已转向，存续期无法预估；任何建立在该路径上的自动化均有「一觉醒来接口失效」的尾部风险。
4. **消费云盘当服务器存储的 ToS 擦边风险**：将消费级云空间以程序化方式当作服务器侧存储使用，与服务条款的预期用途存在张力，存在账号侧被限制的合规风险。此为裁决二「云空间只做备份+手动分享链接」的深层理由之一——手动分享属消费级正当用途，程序化批量读写则不然。
5. **aircode 三方壳不采信**：aircode 类三方 App 关于可接入云空间的说法未经核实，标记 unverified，不采信；且不建议把账号登录信息交给第三方壳应用。该说法不构成任何裁决依据。

**边界声明**：本件仅登记在册文书所载事实与裁决，全部容量、日期、额度数字（429GB、2TB、2027-11-02、1.5T 等）均引自审议书与勘误文书原文，未作外搜补充，未新增任何事实。spike 工单实测结论、Cloud Kit Web 端开放进度、华为云备案支持文档细节等待证事项，以届时一手复核为准，本件不预判其结果。
