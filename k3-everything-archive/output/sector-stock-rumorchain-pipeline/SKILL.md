# 研报个股谣言链一体化管线（sector-stock-rumorchain-pipeline）

> 溯源：2026-09-01 实盘固化——消费电子研报+奋达科技(002681)反转研判+舆情谣言链核查全流程（三案过闸卷宗可查）。

## §0 性质与边界

本技能是**编排件**，不产生新能力：把「行业研报 + 个股分析 + 舆情核查」三件事编为一条管线，每一段的权威规程在其本体技能（引用不复制）。行业与个股均为占位符（消费电子/002681 只是实例）。

## §1 触发与首动作（点进去搜）

用户指令命中 description 任一触发语时，**第一步必须先读两个上游技能本体**（用户口令「得点进去搜」的法定含义）：

1. 读 `<技能安装位>/hifi-integration-umbrella/SKILL.md` ——确认在场技能名录与 §2 冲突仲裁序，本管线按仲裁序调度：红线件（plugin-datasource-ops）→ 验收闸（output-verdict-gate）→ 执行件。
2. 读 `<技能安装位>/rumor-chain-verifier/SKILL.md` 及其 `references/playbook.md` ——舆情核查段的拆链/定断方法以其为准。

路径回退：上述 `<技能安装位>/` 路径缺席时，依次在 ① 当前工作区同名技能目录、② 其他已挂载技能根目录 中搜索同名技能；均缺席才允许声明降级。读取非标准路径时须在 plan.md 注明实际读取路径。缺席则显式声明降级（能力占位原则），禁止假装已调度。

## §2 五段式管线（顺序不可跳）

```
S1 数据采集 → S2 研报写作 → S3 舆情谣言链 → S4 输出审议闸 → S5 成稿与归档
```

- **S1 数据采集**（plugin-datasource-ops 纪律）：探针先行→按市场路由金融插件（A 股：iFinD/Wind/Gildata；舆情：新华财经）→多检索式交叉→原始返回落盘 `<输出区>/research/{topic}/`→每数字紧邻（来源，日期）。
- **S2 研报写作**（report-writing 技能）：研究与写作分离；行业→细分→板块行情估值→个股（基本面/技术面/催化/风险）→总结风险；`.agent.final.md` 为必经中间件。
- **S3 舆情谣言链**（rumor-chain-verifier 六步 + evidence-chain-verifier 登记）：采集多空传言清单→拆链（事实/因果/价值节）→逐节定断+conf→四表交付→断言登记 JSON 脚本校验。
- **S4 输出审议闸**（output-verdict-gate，金融实质输出必过）：控辩对抗→5 席盲评 4/5 超级多数→监管门；不过闸不发出。
- **S5 成稿与归档**：md→docx（按在场字体规范）；全部产物归集归档。

**路由明文**：命中「研报+个股」即触发整管线；用户未点名舆情时，S3 仍以压缩口径固定执行（≥2 条传言），禁止因未点名而跳过；用户明确排除舆情核查时方可跳过 S3 并在 plan.md 声明。个股代码有效性核验为 S1 首动作：核验失败（非个股/已退市/无此代码）→ 显式降级 + 给出补正路径，禁止以占位标的充数；处置声明须同时写入 plan.md 与成稿文首。

各段细则与 checklist 见 [references/pipeline.md](references/pipeline.md)（执行前读）。

### 压缩模式（用户要求简版/演示/时间受限时）

| 段 | 可压缩 | 不可压缩（最低实质水位） |
|---|---|---|
| S1 | 采集广度、数据源数量 | ≥5 个核心真实数字（行业 2 + 个股 3），紧邻（来源，日期） |
| S2 | 章节数（可单章）、图表、docx | 行业主线判断 + 个股分层研判（确认/破坏信号 + 把握三档） |
| S3 | 传言量级（≥8 条 → ≥2 条）、底表差分穷举 | ≥2 条真实传言走完拆链（≥3 节含 ≥1 因果节）+ 逐节定断 + conf |
| S4 | 控辩/盲评/监管门全流程 | 骨架声明 + 产物标注「未经实闸」 |
| S5 | docx、卷宗归档 | md 落盘 + 免责声明 |

压缩模式产出仍是**成稿**（数字真实、定断真实），只是范围更小；压缩的是工作量，不是真实性。

## §3 实证事故清单（硬性，来自实盘闸口抓获）

1. **量级数字必复算**：媒体「N 倍量/翻倍」类约数不得照抄——用原始数据复算（实证：「4 倍量」实算 3.03 倍，首轮 5 席全否）。
2. **三层产物级联**：md/JSON/checklist 任何一层修订，其余层必须同步重生成（实证：chains JSON 与 checklist 漂移致两轮不过闸）。
3. **修订声明≠落盘事实**：每轮修订后 grep 复验零残留再送审；edit 类工具对长中文文件可能未持久化，以读回为准（实证：三次"编辑成功"实际未生效）。
4. **悬空引用检查**：来源日期晚于报告日落款=未来日期，一律剔除（实证：IDC/中商 2026-09-02 残留图注三处）。
5. **互斥数字并置检查**：同段落数字做算术自洽检验（实证：2267.1 万/2368.7 万/45% 三数互斥）。
6. **多口径并列**：YTD/涨幅/募资额等存在双口径时并列呈现并注明基期（实证：实募 8.49 亿 vs 原拟 11.69 亿裁决曾反转）。
7. **占位 URL 禁充数**：查不到的链接填 no_public_url_reason + 检索路径，禁拼凑深链。
8. **全占位交付禁止**：「骨架轮/成稿轮」二分是规程外发明的口径，禁止——任何一轮交付都须含实质（实证：光伏 300274 骨架轮零实质，盲评完败于裸 baseline）。另禁止对空占位内容跑形式校验充数（对 `{{...}}` JSON 跑校验脚本零 errors 无任何意义）。

## §4 交付物

交付物验收第一问：「用户能否从产物中读到真实数字与真实定断？」不能则整体返工，不论结构多合规。

- 研报：`.agent.final.md` + `.docx`；谣言链核查报告 md + 证据链 JSON；审议闸卷宗目录；plan.md 全程留痕（状态/偏差/降级三栏，禁止复述规程）。
- 结尾必备：免责声明「本报告为研究分析，不构成投资建议」。
