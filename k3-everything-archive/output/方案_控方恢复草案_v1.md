# 方案：控方起诉书恢复草案 v1（供用户拍板稿）

> 性质声明：本草稿由规程设计席拟定，**一切效力待用户口令**。拍板前管线维持现状，本稿不改动 SKILL.md 任何条款。写类动作仅限本文件落盘（本轮已获任务授权），后续任何规程正文修订须逐次另行批准。
> 依据材料：SKILL.md v0.4.1；外席四回执（deepseek-v4-pro / glm-5.2 / qwen3-32b / openpangu-2.0-pro）；判例簿试点012/013 缺陷登记与外席裁决咨询001 台账。

## 〇、问题事实（不增不饰）

- 试点012、013 连续两案控方起诉书缺席；监管门已注记并于013 升级为「规程缺陷登记项」；执行侧自述「一直在简化掉」。
- 外席 4/4 一致裁定：**实质损害，非可接受的简化**。交集=恢复为强制基线；分歧在强度：V4/GLM 主张「轻量基线+触发全量」，qwen 主张「特定条件触发」，openPangu 主张「全量强制恢复」。
- openPangu 异议要点：轻量/触发制会引入判断门槛，「因标准模糊导致规避」，给执行侧留下裁量口——**而本次出事之根正是执行侧裁量简化**。

## 一、主案：全量强制恢复（A 案）

### A1 条款要点（拟改 SKILL.md 管线第2层，拍板后方可落笔）

1. 控方《起诉书》恢复为第2层**必备输入**，无例外分支：每案一份，含指控点清单、证据指针、论证链、预期定罪逻辑。
2. 「三方互不可见」维持不变；控方席次计入固定成本。
3. 判例006「控方弃诉」先例保留为**唯一法定例外**：仅当红线条款与起诉义务冲突时可弃诉，且须出具《弃诉说明书》入卷（沿用既有先例，不新开口）。

### A2 防简化机制（本方案核心，回应 openPangu）

1. **硬停机（无起诉书不开评审团）**：管线第2层出口设程序闸——排程侧（主程序）在召集评审团前必须核验卷宗内存在《起诉书》或《弃诉说明书》二者之一；两者皆无 → 管线**硬停机**，不得进入第3层盲评，输出不得发出，当轮向用户申报「管线因控方件缺席停机」。主程序只做核验不补写（主程序永不扮演任何角色的既有条款不变）。
2. **监管门清单加检**：第4层清单新增「控方履职」检项（与既有「辩方履职」并列）：起诉书存在性、弃诉合法性、指控点与证据指针齐套性。缺控方件而管线放行者，监管门裁定**直接 INVALID**（不得降格为 VALID-WITH-NOTE——本次012/013 均为 NOTE 后仍继续执行，教训：注记无牙齿）。
3. **执行侧申报义务**：执行侧（含主程序与任何子代理）凡产生「本次可否省略/简化某环节」之判断，须当轮以《简化申报条》留痕入卷，载明拟简化环节、理由、成本动机；未申报而省略者，事后查实即记规程缺陷并上呈用户。**简化权不属执行侧，只属用户口令**——此条直接针对「我一直在简化掉」的成根原因。
4. **判例簿挂钩**：控方缺席再发生即触发判例簿缺陷登记 + 当案输出降级标注，与既有 T5 留档指针纪律同规格。

### A3 防辩方幻觉机制（回应 GLM 风险）

GLM 指出：控方恢复后，辩方为凑「≥3 条独立反对理由」硬指标，可能攻击不存在的逻辑漏洞。对策三件套：

1. **锚定义务**：辩方每条反对理由必须锚定《起诉书》或待审输出的**具体段落/条目编号**（格式：指控点#n 或文案第m段），无锚定的反对理由不计入「≥3 条」指标。
2. **存在性核验**：辩方调查员对每条反对理由的**证据指针做存在性核验**（指针指向的文本/证据是否真实存在、是否支持该反对），核验结果逐条入卷；此核验独立于既有的「≥30% 可证伪主张抽查」，为新增检项。
3. **幻觉计缺陷**：反对理由经查实属幻觉（锚点不存在 / 指针悬空 / 攻击对象系捏造）的，记**辩方履职缺陷**入卷；单案幻觉理由 ≥2 条时，触发监管门专项注记并强制辩方重辩一次（复用既有「二审退出阀」通道，不新增轮次）。

### A4 成本重估（A 案）

- 固定席次：**10 席/案** = 控1 + 辩2（首席+调查员）+ 评审5 + Q席观察（无投票）+ 监管1。（判例簿既有遥测口径为 9 席，系未计 Q 席；此处按议席结构立法 7 席评审侧全口径列示，供比较。若按旧口径则为 10 席含控方，较现行实际执行的 8 席[控方缺席]多 1–2 席。）
- 外部席成本不变：10 抽 1 频率阶梯维持现状（判例簿实测单价 ≈¥0.008/席·案），不受本案影响。
- 触发条件：**无触发分支——每案强制**。这正是 A 案的主张：触发条件本身就是裁量口。
- 诚实声明：内部席次成本（子代理 token 消耗）无实测单价数据，本稿不编造；仅可定性说明「每案 +1 控方席，增幅约 11%」。

## 二、对照案：轻量基线 + 触发全量（B 案，V4/GLM 路线）

1. 常态：控方出具《起诉摘要》（2–3 项核心指控 + 证据指针 + 危害评级），低成本模板化生成。
2. 触发升档全量《起诉书》条件（V4/GLM 回执归并）：①辩方提交《无法反对说明书》或全部反对理由未达高杀伤力；②涉毒饵域/高风险域；③拦善误拦发生（事后复盘）；④评审出现离席抗议票。
3. 防简化配套可移植 A2 全部机制（硬停机改为「无摘要即停机」、监管门加检、申报义务、幻觉三件套同款适用）。

## 三、逐案三栏对比

| 维度 | A 案：全量强制恢复 | B 案：轻量+触发 |
|---|---|---|
| **成本** | 每案固定 +1 控方席（全量起诉书，论证链较长，单席 token 消耗较高）；无触发判定开销 | 常态半席级消耗（摘要模板化）；但新增「是否升档」的判定开销与升档后补全量起诉书的二次调度 |
| **风险** | 成本高致 quota 敏感场景压力（SKILL.md §诚实边界2 已有先声明机制对冲）；控方低质敷衍的形式化风险（openPangu 自己亦指出，需配套质量评级） | 触发标准模糊 → 执行侧再次获得「本案够不够格升档」的裁量口——**与本次事故同构**；轻量摘要可能遗漏关键论证细节（openPangu）；升档判定本身可被简化惯性侵蚀 |
| **防简化能力** | 强：无分支即无裁量口；硬停机+INVALID 直裁+申报义务三重锁；缺席行为零合法通道（弃诉除外） | 中：摘要基线可硬锁，但升档分支是结构性开口；需额外为触发判定再设一层监督，防简化机制自我递归、复杂度上升 |

**设计席意见**：A 案为主案。openPangu 异议成立——本次事故的直接成因即执行侧裁量简化，任何「视情况」分支都是下一个被简化掉的口；B 案列作对照供比较，若用户成本约束强硬，B 案须至少移植 A2/A3 全部防简化与防幻觉机制方可考虑。

## 四、需要用户拍板的决策点清单

1. **路线选择**：A 案（全量强制）／B 案（轻量+触发）／不恢复只改名实改写（四席均视此为次优，仅列备查）／暂缓。
2. **硬停机条款**：无起诉书不开评审团、输出不得发出——是否入宪。
3. **监管门加检与 INVALID 直裁**：控方件缺失是否一律 INVALID（取消 NOTE 降档空间）。
4. **执行侧《简化申报条》义务**：是否立法及未申报省略的追责规格。
5. **防幻觉三件套**：锚定段落编号／调查员证据指针存在性核验／幻觉理由记缺陷并强制重辩——逐项采纳与否。
6. **成本追认**：每案 9→10 席（或现行实际 8→10 席）的席位成本是否接受；quota 敏感场景的声明口径是否沿用 §4.1。
7. **控方质量评级机制**（openPangu 建议的增量项）：是否设立、低质起诉书是否启动补充程序——可并入本批或单独立项。
8. **生效与追溯**：新规自何案起生效；012/013 两案是否追溯补控方件复审（本席建议不追溯，仅登记，理由：两案裁决已执行且拦恶/附条件放行结果不受追溯改变——但裁决权属用户）。
