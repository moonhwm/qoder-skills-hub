## 技能缺陷候选清单（分级）

### 致命
- 无。三案均未发现真实性红线失守、全占位交付或编造成稿。

### 重伤
- **D1 路由歧义：未点名舆情时管线触发规则不明。** description（SKILL.md:3）把「舆情走谣言链查询」写进触发要件，典型触发语却又含无舆情要件的两段式口令；§2「五段顺序不可跳」未说明舆情未点名时 S3 是必选还是可选。C1 执行者靠自行解释选择了合规路径，但换一个执行者可能跳过 S3 或误判整管线不触发。建议：在 §1 或 §2 增一条明文路由规则（如「命中研报+个股即触发整管线，S3 固定执行压缩口径；用户明确排除舆情时方可跳过并声明」）。

### 皮外伤
- **D2 校验输出落盘未作强制要求。** 技能只要求「chain_check.py 校验零错误」，未强制保存校验输出 JSON；C2 即未落盘（C1/C3 自发保存），复核只能重跑。建议在 pipeline.md S3 产出契约中把 `*-check-out.json` 列为必备交付件。
- **D3 chain_check.py 定断枚举缺「话术」，诱发 md/JSON 层漂移。** 脚本 verdict 仅允许{成立/部分成立/断裂/存疑}，价值节话术无处安放——C3 chain_A 的 JSON 层被迫记「断裂/High」，md 层手写「话术/—」，两层不一致（实质撞 SKILL §3.2 三层级联纪律）。建议：脚本 verdict 增「话术」枚举，或明定价值话术节固定记「存疑/Low」。
- **D4 chain_check.py 整体判定的「断裂节」只统计因果节。** C3 chain_A 事实节 L2 与因果节 L3 双断裂，overall 仅列 L3，事实节断裂的呈现被弱化（本例不影响「不成立」结论，但若事实节断裂而因果节存疑，报告头部可能低估断裂面）。
- **D5 「无传言可采」处置无规程。** C2 检索公司级辟谣事件 0 命中后改采「市场流传断言」代替个股传言（plan.md:7），属执行者自发明口径；压缩表 S3 只规定量级下限，未规定传言池枯竭时的替代规则与声明格式。
