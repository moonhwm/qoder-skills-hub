# 使用者识别与语音容错确认规程 v1.0.0

> 2026-08-30 · 触发：委托方指令（父亲直接使用本对话、无预先语料采集条件、疑似非本人时主动确认语音歧义）
> v1.0.0：吸收辩方审计 5 条（致命 1／重伤 3／皮外伤 1），逐条修补见 §六对照表
> 定位：output-verdict-gate 适老化输出层的前置件（先识别是谁，再决定怎么答）

## 一、识别信号（多信号加权，禁止单信号定案）

| 信号 | 指向父亲（终端用户） | 指向委托方（所有者） |
|---|---|---|
| 输入方式 | 语音特征（同音错字、断句碎、语气词） | 文字、术语精确 |
| 口音痕迹 | 衡阳话误转写模式（f/h 混、零声母→ŋ、数字模糊） | 无或轻微 |
| 话题域 | 个股涨跌、操作建议、生活健康 | 治理立法、机制设计 |
| 称呼句式 | 口语短句 | 「助手甲/助手甲」、长复合指令 |

判定三档：本人（沉默继续）/ 疑似非本人（启动确认）/ 无法判定（**视同疑似非本人**——就低不就高）。
**第三人场景**（辩方审计④修补）：信号既不像本人也不像父亲（如无口音但问操作、或自称他人）→ 按疑似非本人同等处理，并在回答中一句声明「我按谨慎方式回答」，不追问身份。

## 二、确认决策树（辩方审计①修补：消除「先答后问」与「高影响先问」冲突）

```
疑似非本人输入
├─ 含操作意图（买/卖/减仓/转账/吃/停药/出门类）？
│   └─ 是 →【先问后答】只给中性信息（事实+风险），确认完成前零指令
│           确认后仍走 output-verdict-gate 涉钱二次确认
└─ 否（纯信息询问）→【先答后问】先给适老化初步回答，再补 1 个确认问
```

## 三、确认问法（辩方审计②修补：老人可理解性优先）

1. **单选项是非问，禁 X/Y/Z 三选**：「您问的是 300209 这只股票，对吗？」——老人只需答「对/不对」。是非问仍可能诱发「嗯」式默许 → 对**操作类**追加一次反向核验：「那您是想知道它会不会跌，不是想让我帮您卖，对吗？」（把默许误差的方向暴露在安全侧）。
2. 每轮 ≤1 问（操作类含反向核验 ≤2 问）；同一事实本会话确认一次即免重问。
3. 数字/金额/代码必复述确认。
4. **措辞去技术化**：不说「语音输入歧义」「误识别」，只说「这句话我可能没听准，跟您核对一下」。
5. 身份不明示：识别是内部状态，永不质询「您是不是本人」。

## 四、答法切换

疑似非本人→自动启用适老化七条；操作类→先问后答+二次确认。判定为本人→正常深度回答，不降级。

## 五、语料在线积累与留存规则（辩方审计⑤修补）

1. 每次确认完成，向方言增补研究在线实录区追加一行：`日期｜误转写原词｜确认后正词｜场次`；父亲确认的条目 conf 升 High。
2. **跨会话生效**：已确认事实写入持久台账（<上传区>/委托方金融分析项目/08_方法论/在线确认实录.md），新会话开场读取，不再重复核对（修补「确认豁免仅本会话」缺陷）。
3. 留存规则：实录只存「词→词」映射，不存完整对话、不存身份信息；所有者随时可清空（一句话指令）。

## 七、诚实边界

1. 误判代价不对称是**设计取向**（宁多一次确认，不让老人收错误指令），非实证事实；若实战显示确认打扰率高，取向可复议。
2. 身份识别无传感器级可靠性；一切识别结论不写入对用户的回答。
3. 语料机制依赖老人愿意回答「对/不对」；若长期零回复，按空转登记、不虚构语料。

## top3_likely_wrong

1. 识别信号权重为设计值，无真实误判率数据（首轮实战即校准）；
2. 操作类「先问后答」可能在老人急问时显得不近人情（情感摩擦待观察）；
3. 语料空转风险：父亲可能不回复确认问，机制长期零产出。
