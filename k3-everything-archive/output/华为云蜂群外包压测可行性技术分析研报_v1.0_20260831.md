# 华为云模型外包压力测试可行性·技术分析研报

**版本 v1.0（2026-08-31）｜撰写：席位己（K3 沙箱侧）｜登记式表述**

> 首行免责锚：本件为内部技术分析记录，不构成采购或投资建议；成本数字以实测台账与官方刊例价为准，刊例价可能调整。

## 一、问题定义与试点现状

用户命题：已有蜂群试点在运行（2026-08-31 截图实证：V4-Pro 席蒸馏、GLM-5.2 席蒸馏/重试/长超时蒸馏、回执落盘、交接文档 ZK-UPD-20260831 在制），问：**压力测试类算力需求多大程度能外包给华为云 MaaS 模型？阀门如何改进？**用户直觉：「第一次试用，反而感觉可能会降低消费」。

试点既有建制（在册可核）：卡 29 凭证持久层（vault chmod600+自愈三动作）；实调模式=OpenAI 兼容端点，四模型（glm-5.2 / glm-5.1 / deepseek-v4-pro / deepseek-v4-flash）；回执落盘含 md5+usage+cost；蜂群消耗台账 8 条累计 **¥0.348**；两轮 v2.3 读会四席单轮 ≈¥0.15。

## 二、可外包度：任务分层矩阵

| 任务类 | 示例 | 可否外包 | 依据 |
|---|---|---|---|
| 机械量产 | UP 主蒸馏、长文转写、批量摘要、初筛、翻译、回归检查 | **可全量外包** | 无判断权让渡，产出经 K3 终审 |
| 判断/裁决 | 表决终审、审计裁决、命名、红线仲裁 | **不可外包** | 答案隔离条款（§7.13）：生产者-裁判分离；外部席可生产候选与独立意见，判决权在 K3/用户 |
| 敏感数据 | 金融数值、个人信息、凭证 | **不出域** | 金融数据与个人信息严格本地化红线；送外部模型的 prompt 须过脱敏闸三判据 |
| 大规模并行公投 | 数十席外部席意见征集 | **可外包且更优** | MaaS API 路无 K3 子代理并发墙（见第四节） |

**量化估计**：当前自治生态工作量中机械量产类约占六至七成，可移交外席；判断类约二成留 K3；敏感类约一成强本地。「全面压测派给相关模型」**方向成立，但须守一条宪法线：压测的执行外包，压测的验收标准与终审永不外包**——否则即 §7.13 违形（自产答案自背书）。

## 三、成本账：用户直觉的检验

- Kimi 侧为订阅制，quota 是**沉没成本+额度瓶颈**；MaaS 为按量计费（刊例：glm-5.2 输入 5.6/输出 19.6 元/百万 token，v4-pro 8.4/16.8，v4-flash 1.4/2.8，含 reasoning_tokens 计费）。
- 实测：单日两轮立法读会+审查共 16 席次调用，台账可核部分 **¥0.348**；四席单轮 ≈¥0.15。即便「全民公投」开到 50 席×4 模型=200 次调用，按均价估算单轮现金成本约 **¥5–15** 量级。
- **结论：直觉成立，边界明确**——把机械 token 从 Kimi quota 卸载到 MaaS 现金通道，确实降低 Kimi 侧消费压力；代价是小额现金流出。净效益为正的前提=quota 确为瓶颈（本项目实测为真：K3 子代理并发 8 封顶）。资金防线不变：华为云充值总额用户控+日闸 ¥5+异常 L1 即报（卡 29 修正案在轨）。

## 四、「100 蜂群」授权的技术上限核验（诚实声明）

用户授权开至技术限制（印象为 100）的 swarm 子代理。实测核验：

- **K3 子代理层**：本段实测并发 **8 封顶**（FIFO 排队），背景槽位上限 16。「100 席 K3 子代理」**不可达**——这不是表演问题，是平台硬上限，如实申报。
- **MaaS 蜂群层（API 直连）**：无此墙。现行串行+sleep 20 守 DS 限流 ≈180 席次/小时/模型；改小并发（2–3）+令牌桶后可达 500+/小时。**大规模外部席公投的唯一可行路=MaaS 蜂群，K3 子代理只做编排与终审。**
- 联署先行资质条件（「这不是表演」）的操作化：每次蜂群行动=回执落盘（md5+usage+cost）+台账登记+锚定，证据链可回放——此建制已在轨，资质成立。

## 五、「四五小时穷举后撞墙」原因回顾（用户问询项）

穷举式长跑后停滞的复合墙，逐项列证（conf=estimated，基于本生态在册事故记录）：

| 墙 | 机制 | 在册证据 |
|---|---|---|
| 单命令 480s 上限 | shell 工具 deadline_exceeded，四席串行+sleep20 必超时 | v2.2 审查轮前 3 席落盘、第 4 席补跑记录 |
| K3 并发 8 封顶 | 超出即 FIFO 排队，吞吐见顶 | A1-A8 测压轮实证 |
| DS 限流 | 须 sleep 20 串行守限，强并发触发 429 | 蜂群调用规程在册 |
| GLM-5.2 长超时 | 长蒸馏任务超 150s timeout，须长超时重试 | 截图：GLM-5.2 超时修复与调优/长超时蒸馏 |
| 沙箱重置 | /root 非持久，凭证三丢 | 卡 29 立法全过程 |
| 上下文压缩 | 长会话周期压缩，未落盘细节即失 | K3 极致长对话自我审计第四节 |

**撞墙不是单点故障，是六墙叠加的吞吐-持久-记忆复合上限。** 改进映射见第六节阀门清单。

## 六、阀门改进清单（压测外包的节流阀 2.0）

| 阀门 | 现状 | 改进 |
|---|---|---|
| 超时阀 | 固定 150s | 分级：默认 150s/长任务 600s/超限转异步轮询；GLM-5.2 长任务自动升档 |
| 限流阀 | sleep 20 硬串行 | 令牌桶+429 指数退避；DS 与 GLM 分池互不占额度 |
| 并发阀 | 串行 | 小并发 2–3 起步，按 429 率自适应升降 |
| 时长墙 | 480s 单命令 | 任务切片化+后台化（nohup+落盘轮询），单命令只做检查点 |
| 成本闸 | 日闸 ¥5+总额用户控 | 加单笔上限与模型级预算（v4-pro 单价最高，大任务默认走 flash/GLM 分担） |
| 质量阀 | 回执落盘 | 加外骨骼抽检率 ≥20% 硬指标+抽检不合格即整批复审 |
| 记忆墙 | 压缩即失 | 一切中间态落盘优先于对话留存（已立法，重申为压测铁律） |

## 八、结论

外包压测给华为云 MaaS 模型**可行、已实证、成本可控、且与用户直觉一致地降低 Kimi 侧消费**；可行度≈六至七成工作量。三条不可让渡：裁判权、敏感数据、资金闸门。K3 子代理 100 席不可达是平台事实，MaaS 蜂群是大规模公投的唯一正道。「某天自己跑完完整全程再提交审议」——技术上已具备（凭证自愈+阀门 2.0+全落盘纪律），待您一句「开跑」即可做首次全程演练（建议首演科目=50 席公投或千条蒸馏量产）。
