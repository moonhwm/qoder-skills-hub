# 递归回灌创新方案——回灌胶囊协议

适用场景：对话次数与工具调用上限迫使用户把旧对话内容"递归回灌"进新对话——整篇搬运
成本高、易失真、还吃光新会话预算。本方案用**分层记忆 + 回灌胶囊 + 差异回灌**替代整篇回灌。

## 一、分层记忆架构（L0-L3）

| 层 | 名称 | 体量上限 | 内容 | 何时回灌 |
|----|------|----------|------|----------|
| L0 | 一句话状态 | ≤50 字 | "项目X v1.3 L1：骨架已落盘，下步跑真实数据" | 每次新会话必带 |
| L1 | 项目卡 | ≤200 字 | 目标/当前状态/下一动作/关键文件路径（一行卡片扩展版） | 恢复项目上下文时 |
| L2 | 回灌胶囊 | ≤800 字 | 固定槽位全要素（见下），自含执行指令 | 继续推进任务时（默认层） |
| L3 | 全量归档 | 不限 | upload 文件区的完整文档/数据/日志 | 胶囊指向但答不出时按需取 |

**核心原则：新会话只回灌完成任务所需的最小层，禁止整篇旧对话回灌。**
能用 L0 回答的不带 L1；能用 L2 推进的不读 L3。整篇回灌 = 把上一会话的预算浪费复制到
下一会话，且失真率随长度上升。

## 二、回灌胶囊固定槽位（L2，≤800 字）

胶囊由 `scripts/build_reentry_capsule.py` 装配，六个固定槽位，顺序与标题不得改动：

```
【项目卡：目标】一句话：为谁解决什么问题。
【当前状态：版本号+毕业等级】如 v1.3 / L1（对接 iteration-convergence-ops 严肃化阶梯）。
【未决项】按优先级列，每条一句话。
【下一动作】新会话可立即执行的一步，具体到文件/命令。
【核验锚点：关键文件路径+开场先 ls 核验的指令】列出 3-7 个关键文件绝对路径。
【信源备忘：证据缺口】哪些关键判断缺公开可查链接/未登记证据链。
```

## 三、自指式设计（胶囊必须指挥下一个 agent）

胶囊末尾**必须**含给下一个 agent 的执行指令，固定句式：

> 给下一个 agent：先 `ls` 核验上方【核验锚点】列出的每个文件存在；任一不存在则如实报告
> 并据 L3 归档重建，**禁止凭胶囊记忆引用统计口径**（数字/排名/结论一律以盘上文件与
> 公开链接为准）。核验通过后再执行【下一动作】。

胶囊是指挥链的一环，不是回忆录：没有执行指令的胶囊视为半成品。

## 四、差异回灌（连续会话间只带变更）

- 连续会话之间**只回灌"自上次胶囊以来的变更"**：新版本条目、新未决项、状态翻转。
- 变更日志由 iteration-convergence-ops 的 `iteration_log.py` 支撑
  （`report` 子命令直接产出可读版本史；`add` 的 why/impact 字段即变更说明）。
- 上一粒胶囊 + 差异日志 = 新胶囊的原料；build_reentry_capsule.py 读取
  status_board.json 与 iteration_log.json 自动装配，避免手工誊抄失真。

## 五、回灌质量自检三问

胶囊写完（或收到上一会话胶囊）必须自问，答不出任何一问即返工：

1. **我现在该做什么？**——【下一动作】是否具体到可执行的一步？
2. **凭什么相信这些结论？**——【信源备忘】是否交代证据缺口，关键判断能否追溯到
   L3 归档或公开链接？
3. **哪些文件必须先看？**——【核验锚点】是否列出路径并附 ls 核验指令？

## 六、诚实边界

- **胶囊是压缩，压缩必有损**：L2 ≤800 字装不下全部上下文，被裁掉的细节可能恰恰是
  下个任务要的——所以胶囊只给入口，不给结论的完整证明。
- **L3 全量归档（upload 文件区）是唯一完整事实源**：胶囊与归档冲突时，一律以归档为准，
  并立即重建胶囊（差异回灌漏记的信号）。
- 胶囊不替代交接五件套：长会话/模式切换的正式交接仍走
  [handoff_protocol.md](handoff_protocol.md)；胶囊管"高频轻量回灌"，五件套管"重交接"。
