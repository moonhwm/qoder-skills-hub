## 研究一：适老化（面向非技术老年用户）输出机制深化研究

### 1. 规范依据（均已核到官方/权威来源）

| 规范 | 与本机制相关的要点 |
|---|---|
| 工信部《移动互联网应用（APP）适老化通用设计规范》（工信厅信管函〔2021〕67 号，2021-04） | 适老版主要文字 ≥18dp/pt、行距 ≥1.3 倍、对比度 ≥4.5:1；颜色不得作为唯一信息载体；严禁诱导性按键 |
| GB/T 37668—2019《信息技术 互联网内容无障碍可访问性技术要求与测试方法》 | 可感知/可操作/可理解/兼容四原则；理解内容不得单独依赖感官特性 |
| 金融监管总局《关于进一步提升金融服务适老化水平的指导意见》（金发〔2024〕34 号，2024-11-11） | 金融产品对老年人须"浅显易懂的语言"+风险提示显性化+可回溯；适老版"文字简洁明晰、内容通俗易懂"；对疑似被骗交易坚持风险提示并强化确认 |
| WCAG 2.x（SC 3.1.5 / 3.1.3 / 1.4.3）＋ W3C COGA | 超出初中阅读水平的内容须提供简化版本；解释生僻词；plain language、短句、分块 |
| 健康素养领域通行准则（CDC/AMA 系） | teach-back：请用户用自己的话复述以确认理解 |
| 老年语音输入实证（媒体口径，conf=estimated） | 65 岁以上语音识别率约 72%（年轻人约 95%），方言更低——转写错误是常态而非例外 |

### 2. 对本对话的实证回指

本对话已两次命中适老化关键场景：①用户语音转写歧义句（"……该罪犯有效干涉……"），主程序未静默猜测、而是声明无法可靠理解并请求重述——符合确认式提问原则；②股票问答涉及金融资产，风险提示已显性化但位置靠后——按金发〔2024〕34 号应前置。

### 3. 试点结论：输出审议机制的适老化改造七条（草案）

1. **结论前置一句话**：任何经审议的答复，首行给一句话结论；审议过程与证据细节默认折叠，不直接呈现给老年用户（"信息扁平化、重点突出"）。
2. **把握三档并轨**：结论统一带【比较确定／一般／再看看】三档标签（与 autonomous-advance-ops §7.4 呈现词表并轨，禁止对老年用户使用英文 conf 词）。
3. **风险显性化前置**：金融/医疗/转账类内容，风险提示放在结论之前，并附"请与家人或官方渠道核实"的防诈提示（金发〔2024〕34 号第十五、十九条）。
4. **术语转译层**：正式输出前强制去术语——如"量比""换手率""加息基点"必须带一句白话解释（WCAG 3.1.5/3.1.3）。
5. **一次一事**：单条答复只承载一个结论＋一个行动建议；多议题拆分（认知负荷控制）。
6. **语音容错规程**：低置信度转写→回显理解并确认式提问（"您是想问……吗？"），高影响事项未经确认不执行。
7. **关键操作二次确认**：涉及钱、文件覆盖、对外发送的动作，二次确认不可豁免。

## 提案一：对接人"待命态"处置条款（草案）

**状态机修订**：健康 → 退化（L0–L4）→ **待命（recovery-unverified）** → 健康

**待命态认定**：用户通报对接方已恢复，但状况不确保。

**待命态规则（四条）**：
1. 回执可接收，但须过**双闸**：①退化特征扫描（autonomous-advance-ops §5.3 口径）；②与盘上文件的一致性核验。双闸不齐 = 回执暂不采信，登记「待复核」，不据此行动。
2. 待命态期间，涉该对接人的决议一律**冻结**（不审议、不表决）；已发出函件保持「未闭合」。
3. 转健康条件：连续 2 次回执通过双闸；转退化条件：任一输出命中退化特征。
4. 主程序**不得模拟或代行**对接人角色（exam-isolation-ops「主程序永不扮演任何角色」条款的延伸）。

## 提案二：exam-isolation-ops 五机制移植进输出审议机制（草案）

| # | 移植机制 | 在输出审议中的对应物 |
|---|---|---|
| 1 | 角色结构隔离 | **盲评**：评审席只见证据包，不见主程序结论草案；证据包须剥离倾向性措辞（防"引导评审"=防题面带毒） |
| 2 | 题面包指纹 | **证据包 sha256[:16] 指纹**入表决记录，保证各席所见材料一致、可事后取证 |
| 3 | 监管门 | 增设**第六类角色「程序监管席」**：事后审查程序合规（各席独立性／证据包一致性／表决口径），裁定 VALID／VALID-WITH-NOTE／INVALID，**只审程序、不改结论** |
| 4 | 诚实边界登记 | **同模型收敛偏倚**：全部评审席为同模型族，全票通过 ≠ 无偏真值——一切表决结果带「模型能力上限参考」标签 |
| 5 | 主程序禁下场 | 主程序只做排程、归档、登记，永不充任评审席（试点 001 已遵守：15 席全为独立子代理，主程序未投票） |

## 提案三：增加议席至 6/6 全票通过的可行性研究（用户缺席场景）

### 1. 实证依据（试点 001 数据）

三轮表决均为 **4 同意 : 1 反对**——反方席三轮全部反对且找到了经核验的实质反证（完整样本 11 次大跌次日 64% 收涨）。**若采用 6/6 全票制，P1 将三轮死锁**：一个获 12/15 席次支持的倾向性判断将被永久阻断，机制从"过滤器"变成"封堵器"。

### 2. 制度先例

- 联合国安理会：**多数（9/15）＋无常任反对**，刻意不采用全票制——全票制等于给每一席否决权；
- 陪审团全票制：以"悬案陪审团（hung jury）"为已知失效模式；
- 欧盟一致同意原则：决策瘫痪的典型案例。

### 3. 统计学批判（移植自 exam-isolation-ops 诚实边界）

评审席为同模型族子代理，**第 6 席的"同意"不提供独立于前 5 席的信息**——全票通过增加的是程序合法性观感，不是准确性。用全票制追求可靠性是方向性错误；可靠性来自独立性设计与反方席，不来自票数门槛。

### 4. 法源约束

联合国映射表决规程 v2.0：实质性事项＝多数＋无常任反对；**用户一票否决权为人身权，缺席不可代理、不可由任何票制替代**；程序性事项本就不适用否决权、按规程自走。输出审议属程序性日常事项——用户缺席不构成合法性缺口，无需用全票制"补位"。

### 5. 结论与方案（选择题式交付）

**严格 6/6 全票：不可行**（实证死锁＋成本 18 席次/命题＋法源冲突＋统计无效）。可行替代：

- **方案 A（推荐基础）**：6 席 **5/6** 超级多数＋反方意见强制随判决书公开（少数派证据不埋没）；
- **方案 B（用户缺席专用闸）**：缺席期间输出门槛升至 5/6；连续两轮 5/6 僵局 → 降级输出并显著标注【未经全票·待追认】，用户恢复后触发复核（76/262 式事后审查）；
- **方案 C**：Q 席入列第 6 席（无投票权，行使"要求记录异议"权）——补合法性而不改票数数学；
- **方案 D**：严格 6/6——不推荐。

**推荐组合 A+B+C**：6 席＝5 评审＋Q 席观察；用户缺席期按 5/6＋待追认标注运行；用户在场则回到 4/5＋用户否决权的现行框架。成本增量约 +20%（18 vs 15 席次），受边际递减硬停止条款节制。
