# 固化门槛定义 v0.1（主程序拟定 · 待用户追认）

> 2026-08-30 · 来源：试点002 评审团五席「改投同意条件」并集的操作化
> 法律效力：本定义为**主程序拟定的程序性工作稿**，沿待命状态规则——用户恢复后可修订或否决；本稿存续期间的表决仅产生「试行/不试行」效力

## 定义

一项机制包达到固化门槛，当且仅当**全部**满足：

| # | 条件 | 可测量口径 |
|---|---|---|
| T1 | 试点数 ≥3，且每试点监管门裁定 VALID 或 VALID-WITH-NOTE | 试点记录编号清单 |
| T2 | 场景覆盖 ≥2 类异质域（当前域清单：金融概率判断 / 机制自审 / 健康养生 / 涉老金融操作） | 每域 ≥1 试点 |
| T3 | 包内每个组件 ≥1 次实跑留卷（含遥测与反方记录） | 组件×试点对照表 |
| T4 | 缺陷处理闭环：一切已发现缺陷有更正登记或降级标注；逃逸率如实报告（允许 >0，禁止瞒报） | 勘误台账 |
| T5 | 数字裁决栏全部附数据源留档指针，无指针项已降级 | 指针抽查 |
| T6 | 程序授权：用户（委托方）恢复后追认，**或**用户明文授权缺席期可固化 | 用户指令原文 |

## 附注
- T1–T5 达成前可创建**试行版技能包**（标注「试行·待追认」），T6 为固化为全局默认行为的唯一授权通道——此条吸收试点002 第1号否决理由。
- L 级定义（试点成熟度）：L1=单组件单场景（试点001）；L2=T2+T3 达成（多组件多场景）；L3=含 ≥1 轮真实老年用户可理解性测试。
