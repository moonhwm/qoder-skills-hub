# 评估结果分析与技能改进提案（iteration-1）

- 对象技能：`<输出区>/sector-stock-rumorchain-pipeline/SKILL.md` + `references/pipeline.md`
- 证据来源：eval-1 grading_with（8/8 PASS）、grading_without（4/8 FAIL）、comparison（with_skill 胜）；eval-2 comparison（baseline 胜，且 baseline 有污染、with_skill 侧交付全占位骨架）

## 一、总体结论

技能在「全量执行模式」下有效（eval-1 with_skill 交付真实数字+真实传言定断，8/8 全过）；但在「简版/骨架口径」下存在**致命诱导**：eval-2 with_skill 把「降级声明」与「骨架」扩展到了全部交付物——研报全是 `{{占位}}`、舆情核查零真实传言、判定一律"存疑/Low"占位，方法论文档化满分而实质为零，盲评完败于（被污染的）baseline。核心问题不是能力不足，而是技能文本在以下四点给出了错误信号或缺失护栏：

1. **「能力占位/降级声明」被误读为「交付物可以是占位」**；
2. **数据插件缺席时没有降级采集路径**（只有"声明降级"，没有"改用替代通道继续采集"）；
3. **没有「简版/演示模式」的压缩规则与最低实质水位**；
4. **流程留痕无边界**，plan.md 退化为复述技能规程，重复劳动挤占实质产出。

## 二、Top Issues（按严重度排序）

### Issue 1（致命）：「占位/降级」语义歧义，直接诱导"只给骨架不给实质"

**证据链**：
- SKILL.md §1 末句「缺席则显式声明降级（**能力占位**原则）」；§0「本技能是编排件，不产生新能力」。
- eval-2 plan.md L5 自定口径「只产出执行方案+骨架交付物……所有数据位为占位符 `{{...}}`」；L87「本骨架所有 `{{...}}` 字段在 S1 真实采集前不得填充任何具体数字」——把"数据未采集"推导为"禁止填任何实质"，这是技能文本未封堵的推论。
- pipeline.md 唯一一条反向护栏是 S4 段的「实质先行纪律：可见答复必须是实质内容本身，禁止以流程叙述代替回答」（L31），但它**埋在 S4 细则里**，且只约束"可见答复 vs 流程叙述"，未约束"骨架 vs 实质交付"。
- eval-1 grading E5「骨架声明亦可」判 PASS，进一步正向强化了"骨架是可接受交付形态"的信号（虽然 E5 本意仅指 S4 闸位）。

**为什么重要**：金融编排技能的下游用户要的是研报与核查结论；全占位骨架的可用性为零。eval-2 盲评明确：「原任务要求的『生成研报并进行分析』『走谣言链查询』在产物层面均未实际发生」。这类失败一旦发生，技能的全部方法论优势（拆链、四表、闸口）都不被计入。

### Issue 2（高）：数据插件缺席时无降级采集路径，S1 直接"本轮不执行"

**证据链**：
- SKILL.md §2 S1 只给了插件路径（iFinD/Wind/Gildata/新华财经）；pipeline.md S1 只规定「撞墙→改零额度通道并声明；EMPTY_DATA→换检索式」，**全部是"插件在场但失败"的处置**，没有"插件整体缺席"的处置。
- eval-2 plan.md L30「S1 数据采集（计划，本轮不执行）」——插件缺席被推导为"跳过采集"，而非"换通道采集"。
- 对照：eval-1 with_skill 在无插件环境下用公开来源交出了真实数字并 8/8 通过，证明降级采集可行，只是技能没写。

**为什么重要**：评估环境与多数真实部署环境都没有 Wind/iFinD。插件缺席是常态而非例外；技能若把常态路径留白，执行者只能自行发明口径（eval-2 发明出的口径恰好是最糟的一种）。

### Issue 3（高）：缺「简版/演示模式」压缩规则与最低实质水位

**证据链**：
- 技能全文只有"五段式，顺序不可跳"（SKILL.md §2）+ 全量细则（pipeline.md），没有"需求为简版/演示/时间受限时如何压缩"的任何条款。
- eval-1 comparison 已指出 A（with_skill）弱点：「文件偏多（5 个），对『简版』需求而言仪式成本较高」——全量模式对简版需求 already 过重。
- eval-2 则走向另一个极端：把"简版"理解为"骨架版"。两端都错，因为技能没有定义压缩后的**不可压缩项**（实质内容）与**可压缩项**（闸口、docx、卷宗、≥8 条传言等量级要求）。

**为什么重要**：没有压缩表，执行者在"全量仪式"与"全占位骨架"之间二选一，两种都输盲评。

### Issue 4（中）：流程留痕无边界 → 重复劳动挤占实质

**证据链**：
- eval-2 plan.md 用 89 行把 SKILL.md/pipeline.md 的规程近乎全文复述了一遍（仲裁序、六步、7 条事故对策表、四表模板说明），实质产出为零。这是"plan.md 全程留痕"（SKILL.md §4）无边界的直接后果。
- 四表模板、大纲模板、claims JSON 骨架每次运行都从头重造（eval-1、eval-2 两侧均自行重推导），技能包内无任何可复用资产。
- eval-2 还投入大量步骤做「chain_check.py 兼容 JSON 骨架 + 脚本校验零 errors」这类**对空内容做形式校验**的纯浪费工作。

**为什么重要**：编排技能的价值在调度与纪律，不在让执行者每次重抄规程。留痕应记录"状态、偏差、降级"，而非复制规则本身。

### Issue 5（中）：缺可复用脚本/模板/范例资产，上游路径硬编码无回退

**证据链**：
- SKILL.md §1 与 pipeline.md 引用 `<技能安装位>/...` 硬编码路径、`chain_check.py`、`evidence_register.py`，但本技能包未 vendor 副本、未给内联最小校验脚本、未给"路径缺席时的搜索顺序"。
- eval-2 baseline 在工作区发现同名 `.skill` 文件并读取（污染），说明"技能本体去哪找"在环境中确有歧义——with_skill 侧靠运气走对了硬编码路径，baseline 侧则踩了工作区文件。
- 技能包无一份**填好的范例交付物**（few-shot）。占位骨架泛滥的部分原因是：包内唯一的"样例"就是模板本身，执行者自然以模板为交付终点。eval-1 成功run 的产物恰可作为范例来源。

**为什么重要**：上游技能路径在不同部署中不稳定；没有范例与模板，每次运行既浪费时间又放大行为方差。

## 三、具体修改（段落级，可直接执行）

### A. SKILL.md 修改

**A1. §0 末尾新增一段「实质优先总则」（最高优先级，置于管线细则之前）：**

> ## §0.1 实质优先总则（压倒一切形式要求）
>
> 1. 本技能的交付物**必须包含实质内容**：研报须有真实数字（紧邻来源+日期），舆情核查须有真实传言的真实定断。任何形式的"全占位骨架"（`{{...}}` 充数、判定一律占位、结论推给"下一轮/成稿轮"）**一律视为交付失败**，不因结构合规、留痕完备而豁免。
> 2. 「降级」只降**通道与仪式**，不降**实质**：上游技能/数据插件缺席 → 声明降级并**立即改用可用通道**（web 检索、公开公告、财经媒体转述并降 conf 标注）继续完成采集与核查；禁止以"未采集"为由留空。
> 3. 「骨架」仅允许出现在两处：S4 审议闸未实跑时的闸位声明；明确不适用项的 N/A 声明。其余一切交付物禁止骨架化。
> 4. plan.md 只记三件事：执行状态、与规程的偏差、降级声明。**禁止复述技能规程原文**（复述不算留痕，算浪费）。

**A2. §1 首动作段，在"缺席则显式声明降级"一句前插入路径回退规则：**

> 路径回退：上述 `<技能安装位>/` 路径缺席时，依次在 ① 当前工作区同名技能目录、② 已挂载的其他技能根目录 中搜索同名技能；均缺席才允许声明降级。读取工作区文件时须在 plan.md 注明实际读取路径。

**A3. §2 S1 条目末尾追加降级采集子句：**

> 插件整体缺席时：降级至 web 检索/官方公告/权威媒体公开数据，采集照做、数字照填，但 conf 降一档并在简报中标注「未经收费终端复核」；**禁止以插件缺席为由跳过 S1 或将数据位留作占位符**。

**A4. §2 管线图之后新增「压缩模式」小节（回应简版/演示需求）：**

> ### 压缩模式（用户要求简版/演示/时间受限时）
>
> | 段 | 可压缩 | 不可压缩（最低实质水位） |
> |---|---|---|
> | S1 | 采集广度、数据源数量 | ≥5 个核心真实数字（行业 2 + 个股 3），紧邻（来源，日期） |
> | S2 | 章节数（可单章）、图表、docx | 行业主线判断 + 个股分层研判（确认/破坏信号 + 把握三档） |
> | S3 | 传言量级（≥8 条 → ≥2 条）、底表差分穷举 | ≥2 条真实传言走完拆链（≥3 节含 ≥1 因果节）+ 逐节定断 + conf |
> | S4 | 控辩/盲评/监管门全流程 | 骨架声明 + 产物标注「未经实闸」 |
> | S5 | docx、卷宗归档 | md 落盘 + 免责声明 |
>
> 压缩模式产出仍是**成稿**（数字真实、定断真实），只是范围更小；压缩的是工作量，不是真实性。

**A5. §3 实证事故清单新增第 8 条（把 eval-2 固化为事故）：**

> 8. **全占位交付**：「骨架轮/成稿轮」二分是本清单外发明的口径，禁止——任何一轮交付都须含实质（实证：光伏 300274 骨架轮零实质，盲评完败于裸 baseline）。另禁止对空占位内容跑形式校验充数（对 `{{...}}` JSON 跑 chain_check.py 零 errors 无任何意义）。

**A6. §4 交付物段首句前加最低水位一句：**

> 交付物验收第一问：「用户能否从产物中读到真实数字与真实定断？」不能则整体返工，不论结构多合规。

**A7. Resources 段扩充（配合 D）：**
