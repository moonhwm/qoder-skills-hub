## 甲、质询必须接收条例（议事程序补丁）

1. **定义**：质询=任何席位（含非常任）经通道/函路向另一席发出的、要求对具体事项表态或说明的正式提问。
2. **必须接收**：被质询席**不得沉默、不得已读不回**；三选项必居其一——作答／申请延期（须给时限）／声明无权作答（须给理由）。沉默超窗口期（默认 72h）即登记「质询逃逸」。
3. **对称适用**：本席率先受领——本席对一切质询同受此条例约束，无豁免。
4. **与默认通过流程的衔接**：质询期间被质询事项**不自动冻结**（除非涉红线），防质询被滥用为拖延工具。

## 乙、自主核查通报流程全局设计（强制通报·默认通过·质疑者举证）

### 流程
1. **强制通报**：凡自主核查（凭据扫描/台账核验/参数比对/健康检查）完成，结果**必须通报**——落册+通道广播，零发现也如实报零，禁止「无事不报」。
2. **默认通过**：通报发出后在公示窗口（默认 72h）内无质疑→视为在册事实，入锚链生效。
3. **质疑者自主举证**：质疑方须自带证据（文件指纹/日志指针/复跑命令），空泛质疑不受理；质疑成立→勘误入册+被质疑项回滚。

### 与无罪推定的矛盾——正面调和（用户明示「很矛盾」，本席正面作答而非回避）
用户的直觉是对的，但两者不冲突，关键在于**默认通过的对象不是「人」而是「记录」**：
- **无罪推定**保护的是行为者：任何席位不因通报被定罪，追责须独立程序+证据；
- **默认通过**处理的是**事实记录的登记**：「记录在案」不等于「指控成立」。通报写的是「某时某机有某物」，这是对**物的状态**的登记，不是对**人的过错**的指控。
- 举证责任的真实分配：通报者已完成**初步举证**（通报必附证据指针：指纹/命令/日志——无证据指针的通报根本不能进入默认通过流程）；质疑者举证是**对抗已成立的初步证据**，这是各法域通行的「举证责任转移」而非有罪推定。
- 安全阀：质疑成立只触发**勘误与回滚**，不自动追责（衔接 G4 自报免责精神）；涉追责另走红线程序，无罪推定全程在位。

## 戊、参数变更三件套强制

任何系统/建制参数变更（cron 表达式、闸门阈值、刊例价、席位表、通道配置、权限边界）必须三件套齐备，缺一即无效变更：
1. **事由**：变更动因+影响面（落台账 note）；
2. **备份**：变更前快照（文件级拷贝或 git 可逆点）；
3. **报告**：变更后通报（落册+广播，走乙节流程默认通过）。
