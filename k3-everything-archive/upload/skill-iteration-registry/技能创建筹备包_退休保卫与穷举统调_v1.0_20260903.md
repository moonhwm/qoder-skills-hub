# 技能创建筹备包 v1.0（2026-09-03）——苏格拉底开场→保皇党审计→隔离卫生化→双技能设计

## 一、苏格拉底四问开场（自问自答试点，答案均可被用户一票推翻）
1. **定义之问**：「好结果」= 用户每周需亲自处理的事项数降到 ≤1（终审一句话），其余全部由 loop 自治闭环——**退休的 operational 定义**；
2. **约束之问**：不动者=红线体系（凭据/动账/承认权）、锚链诚实、余额（¥800/日量级的燃烧须换「事项自治率」而非轮次）；
3. **反例之问**：最可能死于**空转**（心跳无新信息仍烧）与**认知投降**（用户真退了，loop 无人读 diff——手册 §10/§11 明令「Loop 是实习生不是替身」，故设计「Loop 假期」机制：每周一件必呈人读）；
4. **代价之问**：完全自动化的代价=错误无人拦截——故 Maker/Checker 分离（手册核心原则）+独立 verifier 硬门禁不可省；省掉它们的「自动化」=烧钱机（手册 §11）。

## 二、保皇党审计（谁在阻止您退休·注意力债主清单）
| 债主 | 性质 | 自治化方案 |
|---|---|---|
| 待裁决终审项（称呼/G 案/口令两字闸等） | 制度性必需（用户主权不可让渡） | **不可自动化，但可压缩**：汇总为一页《每周终审一页纸》，一周只打扰一次 |
| 写回队列（技能安装位只读） | 平台约束 | 达阈值自动打包 .skill 呈您一键安装 |
| 华为云失陷换钥对账 | 安全必需 | 换钥后自动对账（hwc 基线在案），仅异常呈报 |
| 公投/研究结果待报 | 一次性 | 结果出炉自动广播+一页纸摘要，不催读 |
| 广播条例（全行为广播） | 自制纪律 | 已全自动（REST 通道自愈），零用户负担 ✓ |
| 心跳 cron×2 | 自动体 | 已在退化门休眠纪律下运行，零打扰 ✓ |
**审计结论**：坚定的保皇党=**终审权本身**（合法且不可推翻，只能压缩频次）+**写回队列**（可半自动化）；其余债主已清或有一页纸方案。实名登记：本席（本席）作为常务执行是最大「保皇党」——大量事项仍呈用户，已按 M4/一页纸方案自我约束。

## 三、隔离与卫生化方案（官方件 vs 用户件路径重叠）
原则（系统级 Skill Priority Rules 固化）：**用户技能完全替代同名内置技能**；触发域重叠时按 hifi-umbrella §2 仲裁序。
| 重叠对 | 处置 |
|---|---|
| 内置 humanizer 系（human-style/nature 类）↔ 用户 humanizer-zh v2.5.1 | **隔离**：中文叙事文本一律 humanizer-zh（用户件优先）；内置件降级为「西文/通用场景备援」，触发词登记防双触发 |
| 内置 docx/pdf/xlsx ↔ 用户同名工作流 | 内置=技术执行层保留；用户件的格式规范（宋体/TNR 四域）为上层约束，不冲突 |
| skill-creator-swarm（内置）↔ 用户 skill 创建流 | 内置规程为准（本轮已遵），用户侧 learning 卡档案为补充 |
卫生化执行：重叠对登记入《技能隔离登记册》（本轮建档），新装官方件时先查登记册防再重叠。

## 四、双技能设计裁决（下一轮开写）
- **Skill A：`retirement-guard-ops`（退休保卫局）**——保皇党审计（§二模板）+每周终审一页纸+Loop 假期机制+空转退化门；面向任何用户泛化（无实名）；
- **Skill B：`pan-exhaust-dispatch`（穷举统调署）**——**薄元技能**：引用不复制 omni-exhaust-research-ops（苏格拉底§1/七域§2/全模型§5/脱敏§6 全部继承引用）+用户点名 14 件名录（quota-guard/pangu/autonomous-advance/output-verdict/semantic-oncology/coordination-letter/cron-task-forge/plugin-datasource/exam-isolation/skill-reinstall/consignment-intake/up-distill/k3-territory/skill-refresh）的强制调用矩阵（每任务每域实调或声明缺席）+跨模型向下兼容层（产物=纯 markdown+脚本纯标准库，任何免费/付费/境内外模型可消费）+自迭代检索路径（检索→评估→改写→再检索留痕）+接口自查询（email/Context7/<通道库>/GitHub 四通道在场即用缺席即声明）。
- **防重复声明**：B 不重建 omni 能力，只做「点名清单的统调+便携泛化壳」；一拖十场景作为 B 的**首发试点案例**（v1.5 尽调为其案例库首件）。
