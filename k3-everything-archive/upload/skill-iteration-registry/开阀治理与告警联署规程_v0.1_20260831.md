## §1 凭证修改安全规程（哈希链+指纹）
1. **永不记明文**：任何凭证（API key、授权码、密码）在本生态内只登记**指纹** = sha256(明文) 前 16 位 + 末 4 位掩码；明文只存在于用户侧华为终端密码箱（用户已声明）与各服务官方后台。
2. **修改链登记**：每次凭证新建/轮换/吊销 = 台账条目 `{seq, ts, 凭证别名, 旧指纹, 新指纹, 操作席, 触发口令/依据, 验证方式}`，条目哈希 = sha256(前条目哈希+本条目规范化 JSON)，写入 `vault/credential_chain.jsonl`（append-only，禁整写）。
3. **唯一性验证**：新凭证启用前须完成指纹比对——与同服务旧凭证指纹不同（防误填旧值）且与库内他服务凭证指纹不同（防串号）；验证记录随条目落盘。
4. **通道措施**：可行验证手段白名单——服务官方后台指纹页核对／MCP 工具只读调用回显比对／Cloudflare 等控制台弹窗扫码（用户在场时）／短链一次性确认。**禁**：把明文贴入任何会话、通道、文件。
5. **压力测试授权边界**：用户授权「合法范围内压测」的实装范围 = **仅本侧台账、验证脚本、哈希链路的自压测**（伪造条目注入测试、断链检测测试、指纹碰撞测试）；**明确排除**对华为终端、华为云控制台及任何第三方系统的主动探测/渗透——无授权书且越法律边界，本侧不做。
6. 凭证泄露疑似事件 = 红级告警（§4），处置优先于一切排期。

2. **冲突登记制**：任何席启动新研究/监控任务前，先查计时器任务台账+蜂群消耗台账；同一标的同一维度已有在跑任务 = 须登记差异化理由，否则不得重复开烧（防无序竞争的可测量判据：同标的同维度任务数 >1 且无差异登记 = 违规）。
3. **配额锚定**：「额度守护件」 的 Q 档继续有效；Q2+ 当日一切开阀任务自动暂停（保命优先）。

## §3 测试产物清理规程
1. 测试性条目（临时文件/测试通道行/试验 cron）创建时必带 test 标记或入 practice/ 目录。
2. **同轮删除**：测试目的达成后同一轮次内删除；删除后当场复核（ls/SQL/list_cron_jobs 验证为空）。
3. **核验留痕**：清理动作登记（删了什么/验证命令/结果零残留）；零发现即如实报零，禁编造清理成果。
4. 历史归档（archive/、迁移快照）不属测试残留，保留；界线存疑时按保留处理并登记待裁。

## §4 告警三级与必要性联署
| 级 | 判据（可测量） | 动作 |
|---|---|---|
| 蓝 | 信息性、无处置需求（如零发现核验） | 通道通报即可，无需联署 |
| 黄 | 需后续处置但不危及安全/资金/凭证（如未回函超 48h、任务停滞、版本差超 7 天） | 通知+**必要性说明**（为何不处置不行）+**一席联署**（任一非发起席 ACK-ALERT）后处置 |
| 红 | 危及安全/凭证/资金/合规（如凭证泄露疑似、熔断词命中、额度 Q3） | 立即通知用户+必要性说明+**全体有效席联署**+用户口令后处置；保命类（止损/吊销）可先处置后补联署，但须 24h 内补 |
1. 告警函格式：通道 kind=ALERT，payload 含{级别/判据命中项/必要性论证/建议处置/联署栏}；联署回复 kind=ACK-ALERT。
2. 先例锚定：cron 首跑监控文案合规四件 = 黄级流程首例（已执行）。

## §5 拍板事项全体一致性前置
1. 凡须用户拍板事项，**先**走全体有效会话一致性考量：发起席拟「拍板卡」（事项/选项/各席意见栏）→ 通道广播 → 各席回函；回函齐或默认期 72h 届满 → 汇总一致性结论（一致/多数/分裂如实标注）→ 呈用户。
2. 呈用户时必带：各席原始意见索引（通道 id 清单）+一致性结论+主程序推荐及理由。分裂事项不得包装成一致呈递。
3. 事项状态机：`draft → review → consistent → presented → decided`；每次状态变更写探针状态文件（§6）。
4. 例外：用户已明示「立即/马上」类口令的事项跳过一致性前置，但须事后补登记。

## §6 探针与防卡死（可恢复）
1. **探针状态文件**：`skill-iteration-registry/探针状态.json`——登记未决拍板事项（状态机值+最后变更时间）、未回函函件（>24h 起算）、cron 活性锚、恢复锚点（capsule/plan 路径）。
2. **停滞判据（可测量）**：事项状态 48h 未变 → 黄级告警；7 天未变 → 红级并附「放弃/降级/再推进」三选一建议。
3. **空转禁令延续**：子代理交付同轮释放；无产出循环 2 轮即停并登记。
4. **可恢复**：每轮收尾更新探针文件 + capsule 回灌指针；任一新会话开场先读探针文件即知卡在哪、从哪续。
5. 探针日检并入既有 04:00 cron 的**挂账项**：原 cron 卡全文不在本侧（list 截断），合并须先索回原卡，防整卡覆盖丢失——挂账至席位戊/卡件管理席。
