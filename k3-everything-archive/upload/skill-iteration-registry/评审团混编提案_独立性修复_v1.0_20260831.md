# 评审团混编提案：以模型异质修复 Condorcet 独立性（决策卡 19·草案）

- 文号：席位戊提案 SCH-19
- 状态：**待拍板**（涉外部 API 调用与成本，依卡 18 第四条：跨席涉外部 API/成本的承诺一律待用户逐条口令）
- 动议来源：用户口令「像敏芝一样引入相关的华为云不就解决了吗」（2026-08-31）
- 对口问题：Q-H 自我批判——同模型五席评审 → CJT 独立性假设不成立 → 多数收敛保证失效

## 一、问题重述（数学形式）

Condorcet 陪审团定理要求：①各 voter 独立；②能力 p>0.5。我方评审团五席均为同一家模型实例，误差项高度相关：e_i = c + u_i（c=共享偏差，u_i=独立噪声），有效独立票数 n_eff < 5，定理收敛保证失效。此即 R5 登记的 Q-H objection。

## 二、解法（用户动议的操作化）

引入华为云 MaaS 外部席，把评审团从「同模型五席」改为「跨供应商混编」：

- 共享偏差 c 分解为供应商级分量：e_i = c_vendor(i) + u_i；跨供应商时 c_vendor 不再恒定 → 相关性显著下降 → 近似独立性恢复 → CJT 重新获得近似适用性。
- 数学表述：若五席来自 ≥3 家供应商，组内相关 ρ_within 高、组间相关 ρ_between 低，则按 Dietrich & Spiekermann 2019 的相关票处理框架，收敛速度由 ρ_between 主导，多数正确率随席数恢复的近似成立。

## 三、既有实证先例（非新风险）

- HWC-20260830-10：外部模型甲-V4-Pro 外部席首跑 006 毒饵，裁决与 Kimi 一致且**增量发现时间逻辑矛盾**。
- HWC-20260830-11：GLM-5.2 第二外部席，三源（Kimi/外部模型甲/GLM）裁决一致，**附和偏倚同源性实证排除**；当时登记可用模型池 9 个。
- 即：混编不是新制度，是已有外部评审席实践的常态化提案。

## 四、条文草案

1. 审议闸评审团由五席改「3+2 混编」：3 席本家 + 2 席外部（华为云 MaaS 池轮换，默认 外部模型甲 系 + GLM 系各一）。
2. 盲评规则不变；外部席只见脱敏后考题（P0 级脱敏纪律沿用 HWC-09 三条）。
3. 表决阈值 4/5 不变；若外部席缺席/超时，降级为 3/3 本家席并标注「独立性降级」。
4. 调用频率与成本闸门沿用 external_sampler rate≤0.5 费用闸门。
5. 凭证纪律沿用卡 18：App Secret 只入 <用户配置目录>/external_seat.json（用户亲手放），永不入正文。

## 五、如实声明（风险与依赖）

1. **凭证易失**：<用户配置目录>/external_seat.json 位于沙箱易失层，沙箱重置即失——须用户亲手重放后方可执行混编；本会话当前不假设其在位。
2. 「近似独立」非真独立：各家模型训练语料高度重叠，ρ_between>0 残余存在，混编是改善不是完备解（Dietrich & Spiekermann 2019 明示相关票无解时应转向审慎表述）。
3. 成本：每次审议增加 2 席外部调用，费用闸门内运行。
4. 与席位辛划界一致：席位辛通道经验（外部席=华为云 MaaS 管道）为本提案直接蓝本，不重复造轮。
