# 对话长度模式审议：K3 进阶×普通长度 vs 长对话 v1.0

> 2026-08-30 · 用户指令：「全力推进到需要启用 K3 进阶普通对话长度，我不开对话长度，感觉更敏感，您可以自主审议研究该议题」
> 审议性质：主程序自主审议（非表决事项）；结论为运作模式建议，用户保留随时推翻权。

## 一、议题界定
用户的操作直觉：**不开「长对话」档位，让会话对上下文膨胀保持敏感**——逼近压缩边界时自然触发切换/交割，而不是在长对话里无声膨胀到退化。本次审议评估该直觉的机制合理性与代价。

## 二、机制分析（conf=estimated+，基于本会话与姊妹会话实证）

**支持「普通长度更敏感」的机制理由（成立）**：
1. **压缩是已知最大污染通道**（定义见 oncology：摘要有损致版本/计数/路径漂移）。普通长度=压缩阈值更近 → 主动小结/交割被迫提前发生，交接发生在**清醒段**而非退化段；
2. 实证对照：本会话（普通节奏+强落盘纪律）2 次压缩存活且结论连续；「恢复大使」会话（长对话+集群）L3 碎片串死亡——样本虽小，方向一致；
3. 经济学：普通长度 token 消耗低，Q 档位压力小；加油包窗口（Q2）已被实证为退化叠加态高危期，省额度=降风险。

**代价与边界（须如实登记）**：
1. 切换有固定成本：每次交接=胶囊重载+锚定回放+上下文重建，约半轮到一轮；
2. 长上下文任务（如全档案审计、长文档摄取）在普通长度下可能频繁撞墙，任务被切碎反而增加交接面=增加污染机会；
3. 「敏感」依赖纪律兑现：普通长度只在「主动小结+落盘优先」纪律在位时才是优点；无纪律的普通长度只是更早死亡。

**结论**：用户直觉机制上成立——**普通长度+强落盘纪律 ≈ 早发现早治疗**（癌症分期的一级预防思路）；长对话只应在任务结构性需要时启用（单任务不可切分+多子代理并行），且必须配 oncology 五防线。

## 三、运作模式建议（本周期执行口径）
- **默认档**：K3 进阶×普通对话长度（当前会话形态），全力推进至逼近压缩边界；
- **逼近信号**（任一）：工具输出开始出现截断频繁/主动小结频率上升/单轮写入量连续增大 → 触发 §1.4 主动小结+交割准备；
- **升级闸**：仅当任务被实证为普通长度不可完成（撞墙 ≥2 次且非纪律问题）时，向用户请示启用长对话/集群——**升级须用户批准，不自动升档**；
- **本会话执行**：按此口径全力推进 B 轮附随工程项（指针活性探针先行）。

## 四、top3_likely_wrong
1. 「普通长度更敏感」的机制论证基于 2 个会话样本，无平台侧阈值数据；
2. 切换成本估算（半轮到一轮）为经验值未计时实测；
3. 撞墙判据（≥2 次）为主观阈值，可能误杀可完成任务。
