> 2026-08-29 · 触发：委托方指令「严格化 <通道库> 库的调用」· 现状实证：项目=<项目库标识>（ap-southeast-2，ACTIVE_HEALTHY，PG 17）；claw_poller_config 含 publishable_key（RLS 最小权限设计注记在档）
> 红线基线：<通道库>「严格保密措施不公开、不公布、不上市」＋S-2 泄露案教训（anon push_outbox 已切断）

## 一、凭证分层纪律
1. **publishable_key**：仅客户端用途，须配 RLS 最小权限（实证口径：仅读 pending/标记 picked）；可入本地私有配置，**永不入产物//git/对话引用全文**（引用只给前 12 位脱敏）。
2. **service_role key**：保密层——仅存本地私有文件（push_config.json 类，chmod 600），禁止写入任何登记/日志/胶囊；任何文件出现完整 service_role 即按泄露处置（当轮换 key+逃逸登记）。
3. **换钥流程**：用户换 key 后当轮更新本地配置并核验连通；旧 key 撤销确认前不删本地记录（防断档）。当前挂账：「key 已换」联测待用户口令。

## 二、调用六级（逐级收紧）
1. **默认只读**：SELECT 最小列清单（禁 SELECT * 入产物）；只读调用=默认许可。
2. **写类逐次批准**：INSERT/UPDATE/DELETE/migration/branch 操作=写类例外，逐次须用户显式批准（列出：表/操作/影响行数/回滚方案）。
3. **结构保密**：库结构（表名/schema/RLS 策略）不入对外产物；对内登记可含。
4. **连接私有**：连接串/池配置仅本地；禁硬编码进任何技能包/脚本分发件。
5. **查询登记**：每次调用登记（时间/表/操作/行数/目的一句）入迭代日志 cost 块；批量操作先给预估再执行。
6. **失败不硬推**：连接/权限失败=当轮登记缺口等用户，禁止重试风暴（≥3 次失败即停手报用户）。

## 三、审计与复核
- 权限审计件（06_证据链/<通道库>权限审计_v1.0.md）每季度复核一次；新建表/新策略先入审计再启用。
- MCP 工具调用纪律：list/get/execute_sql(SELECT) 默认许可；apply_migration/create_branch/deploy_edge_function 等写操作=写类例外逐次批准。

## top3_likely_wrong
1. RLS 策略当前覆盖范围未逐表复核（仅凭既有审计件+配置注记，conf=estimated）
2. publishable_key 的「最小权限」假设依赖 RLS 配置未被改动（季度复核日验证）
3. 本规程未覆盖 Storage/Edge Functions 调用（当前项目未用，用到即补章）
