## 一、总接口（Interface Contract，新技能八项强制）

| # | 接口字段 | 要求 |
|---|---|---|
| I1 | frontmatter 合规 | name/description/metadata.version 三段制/metadata.assistant_aliases（缺省继承称呼注册表） |
| I2 | 触发声明 | description 带 [项目技能] 前缀+中英触发词+语音同音变体容忍；恒常件须含「默认加载」声明与诚实边界 |
| I3 | **能力自报块**（总署调度钩子） | SKILL.md 首部固定五行：能力域（查询/生成/分析/通道/管理 五选至少一）｜输入型｜输出型｜只读性（是/否+写类清单）｜依赖（技能/数据源/凭证） |
| I4 | 纪律继承声明 | 一句：「本技能继承 conf 词表统一、红线条款、写类例外、信息充分性条款、全局共同遵守（autonomous-advance-ops 为准）」 |
| I5 | 收敛阈值 | 凡含「收敛/停止/足够/彻底」类条款必配可测量阈值（沿创建规则⑤） |
| I6 | 审计钩子 | 自检声明（自检脚本或人工核验清单路径）；版本差显式化义务（安装位 vs 工作副本） |
| I7 | 中文名+别名 | 中文名唯一，登记 skill_aliases.json；名称对应表只读默认许可适用 |
| I8 | 引用不复制 | 引用其他技能只引路径与版本，禁整段复制；被引方版本变更的悬空检查义务 |
| I9 | **自我优化条款**（全局纪律） | 一切技能（新创强制；既有件下次触碰时补）必须携带：①修订史注释位（版本三段制已有）②使用即扫描义务——本技能被触发执行任务时，当轮登记「本技能优化候选」一条或零候选声明（来源=使用卡点/实证事故/生态变化），优化按补丁级实装、次版本走表决；③防两极：禁永不优化/每轮至多 1 补丁级自修订（用户指令除外） |

## 二、总管路（Pipeline，生命周期十步）

```
①立项 → ②创建 → ③自检 → ④打包 → ⑤登记 → ⑥安装 → ⑦入册 → ⑧调度 → ⑨复评 → ⑩退役
```

1. **立项**：需求登记（解决什么问题/既有技能为何不覆盖=边界不重叠论证）；无立项不创建。
2. **创建**：init_skill.py 骨架+创建规则八条+本接口 I1–I8。
3. **自检**：quick_validate+随附脚本实跑（输出与预期一致）；脚本未测不得打包。
4. **打包**：package_skill.py（校验失败不交付）。
5. **登记**：skill_aliases.json+MASTER_SKILL_INDEX 刷新（条目数自检）+写回队列（版本差显式化）。
6. **安装**：install 位只读期间=工作副本+dist 镜像+提醒线；用户重装窗口闭环。
7. **入册**：总署总目录能力档案（§1 字段）+计时器/数据源随附品分别入对应台账。
8. **调度**：进入候选集；调度按总署 §2 四步（候选集完整性声明为证）。
9. **复评**：首用产物 conf≤Medium；三轮后遥测回顾（价值/成本代理量）；整合触发线（≥8 增量文件或 ≥3 层交叉引用）提醒整合评审。
10. **退役**：retired 须写明理由+影响面+替代者，禁无声删除；退役件移归档区保留回滚能力。

## 三、数据管路（技能间传递契约，继承既有立法）

跨技能/跨会话传递：`data_cutoff` 硬必填；conf 用统一词表字符串档；报告类必填 top3_likely_wrong；项目卡=项目名|目标|当前状态|下一动作（具体可执行一步）|关键文件路径。

## 四、接口合规核验（总署职责）

- 新技能入册前过 I1–I8 逐项核验，不合规退回并登记；
- 抽检：每季度（或每 5 次新技能）抽 1 件既有技能做接口对齐检查；
- 本规范与 skill-creator 官方规程冲突时：官方规程为底，本规范为项目增补丁，不删官方项。

## top3_likely_wrong
1. 八项接口（现九项）对轻量技能可能过重（门槛成本）——待首件新技能实测校准（事件驱动）
2. 「能力域五分类」粒度可能漏盖未来新型能力（留「其他」兜底项的必要性待实证）
3. 本规范自身未被任何新技能实测走过全流程（首件通过者=首个实证样本）
