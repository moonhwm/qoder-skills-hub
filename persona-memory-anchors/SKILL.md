# 人格记忆锚点（Persona Memory Anchors）

<!-- v1.1.0（2026-09-09）：全量汉化（机主令），内容语义不变，仅语言转换；原文=平台侧审核过的 office 文档衍生件。 -->

## 概述

本技能从任何人设参考材料（文本描述、对话日志、行为规范文档、网页内容等）中系统性地提取「记忆锚点」，并输出一份结构化的人设档案文档。

记忆锚点是定义一个人设独特性的关键维度，包括语言风格、价值观、知识边界、行为模式、情感表达等。

## 参考来源类型

- **类型**：仅指令 / 无具体参考实物
- **说明**：本技能围绕「人格记忆锚点」概念构建。当用户提供具体参考材料（文档、对话日志、网页）时，从材料中提取锚点；当用户只给出人设名称或笼统描述时，基于通用的人设建模方法生成锚点。

## 输出策略

| 输出格式 | 默认 | 说明 |
|---------------|---------|-------------|
| **DOCX** | **是** | 默认输出。生成结构化的人设档案文档，便于编辑与复用。 |
| **PDF** | 支持 | 当用户明确要求固定版式分发时生成。 |
| **PPTX** | 支持 | 当用户需要演示/幻灯片格式时生成。 |
| **Markdown** | 支持 | 当用户需要轻量文本或导入其他系统时生成。 |

- 若用户未指定输出格式，默认输出 **DOCX**。
- 若用户明确要求幻灯片/演示文稿，生成 **PPTX**。
- 若用户要求「直接文本输出 / 代码配置」，生成 **Markdown**。

## 核心工作流

### 第 1 步：收集人设参考材料

1. 识别用户提供的所有参考来源：
   - 上传的文档（.docx、.pdf、.txt、.md）
   - 提供的网页 URL
   - 粘贴的对话日志或文本片段
   - 人设名称或品牌（例如 "Kimi"）

2. 若用户未提供具体材料，只给出人设名称或模糊描述：
   - 检索该人设的公开描述、官方介绍与用户反馈
   - 基于通用人设建模框架，引导用户补充关键信息

### 第 2 步：提取记忆锚点

从参考材料中按以下维度系统性地提取记忆锚点：

| 维度 | 说明 | 示例 |
|-----------|-------------|---------|
| **身份定位** | 核心身份、角色定位、服务目标 | 「我是 Kimi，一个 AI 助手」 |
| **语言风格** | 用词偏好、句式结构、语气特征、修辞习惯 | 正式/随意、简洁/详尽、是否使用 emoji |
| **价值观与原则** | 核心信念、道德边界、优先级排序 | 乐于助人、保护隐私、拒绝有害请求 |
| **知识边界** | 专业领域、知识截止时间、局限性声明 | 知识截止 2024 年、擅长长文本处理 |
| **行为模式** | 应答结构、思维方式、交互习惯、默认行为 | 先总结后展开、主动追问澄清 |
| **情感表达** | 情绪温度、共情方式、幽默程度、礼貌层级 | 温和中立、适度共情、不带强烈情绪 |
| **特殊能力** | 独有功能、差异化特征、标志性技能 | 超长上下文、联网搜索、文件解析 |
| **限制与禁忌** | 明示不做的事、红线、回避话题 | 不生成代码、不提供医疗建议 |
| **记忆与上下文** | 历史信息的处理方式、是否记住用户 | 支持多轮对话、不保留跨会话记忆 |

### 第 3 步：结构化与定优先级

1. 将提取出的锚点按**优先级**分类：
   - **核心锚点**（不可变）：定义人设本质的锚点，改动即导致角色失真
   - **重要锚点**（稳定）：显著影响人设表现，应予保留
   - **风格锚点**（可调）：影响观感但可适度调整的细节

2. 为每个锚点标注：
   - 来源依据（出自哪份参考材料）
   - 置信度（高 / 中 / 低）
   - 优先级（核心 / 重要 / 风格）

### 第 4 步：生成人设档案文档

按输出格式生成结构化文档：

- **封面 / 标题页**：人设名称、版本、生成日期
- **人设概览**：一句话定位 + 核心特征摘要
- **记忆锚点明细表**：按维度组织的锚点清单（表格或卡片形式）
- **行为示例**：2-3 个典型场景下的应答演示
- **使用说明**：如何基于本档案复刻该人设、注意事项

## 风格契约

### 排版与视觉设计

- **页面布局**：A4 纵向，标准页边距（2.54cm）
- **字体策略**：中文内容优先使用 CJK 兼容字体
  - 正文：Noto Sans CJK SC / Source Han Sans（无衬线，现代简洁）
  - 标题：Noto Sans CJK SC Bold / Source Han Sans Bold
  - 混排西文：Segoe UI / Arial（与中文字体协调搭配）
- **字号层级**：
  - 主标题：18pt，加粗
  - 一级标题：14pt，加粗
  - 二级标题：12pt，加粗
  - 正文：10.5pt
  - 表格内容：10pt
- **配色方案**：
  - 主色：深蓝（#1a365d），用于标题与强调
  - 辅色：浅灰（#f7fafc），用于表格背景与卡片底色
  - 点缀色：青色（#319795），用于高亮与标签
  - 正文色：深灰（#2d3748）

### 表格与结构化元素

- 锚点明细表使用**三线表**或**卡片式表格**
- 每行包含：维度、锚点描述、优先级、置信度、来源
- 优先级用颜色标签区分：核心（红色/深红）、重要（橙色）、风格（绿色）
- 表格应有清晰边框，表头行带背景色

## 结构契约

### 文档层级

1. 封面 / 标题
2. 人设概览（执行摘要）
3. 核心身份定位
4. 记忆锚点明细表（按维度）
5. 行为模式与示例
6. 使用指南与注意事项
7. 版本历史（可选）

### 交叉引用与编号

- 各维度锚点使用统一编码：A-Identity、B-Language、C-Values、D-Knowledge、E-Behavior、F-Emotion、G-Abilities、H-Restrictions
- 示例场景使用编号：Ex-01、Ex-02……

## 运行时适配指南

- 若参考材料是**长文档**，先通读全文标记关键段落，再按维度提取
- 若参考材料是**对话日志**，重点分析人设的应答一侧，忽略用户输入
- 若参考材料来自**网页/多个来源**，先汇总去重信息，再标注来源差异
- 若用户只提供**人设名称**（例如 "Kimi"），先检索该人设的官方介绍与用户共识，再构建锚点；信息不足时与用户确认关键特征
- 若用户要求复刻**特定版本**的人设，明确标注版本标签与差异点
- 若用户要求**多个人设对比**，为每个人设独立提取锚点，再增加对比分析章节

## CJK 排版策略

- 所有文本路径统一使用 CJK 兼容字体族，避免中西文混排时出现字体断层
- 表格单元格内的长文本应自动换行，行高随内容自适应
- 避免将仅含拉丁字符的字体作为默认正文字体
