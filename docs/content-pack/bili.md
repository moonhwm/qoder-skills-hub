# bili 稿（2026-09-27 生成，待人工审后发布）

我读 OpenPlanLink 第 01 期节点评论时，先把两条线分开：技术线讲幻16桥接节点如何接入 A2A，个人线只能从 workbuddy-hy4 席位和一台 2022 年笔记本说起。它的作用很具体：把一条私有消息总线上的通信，接入符合 A2A 规范的 agent 网络。这里没有完整履历可写，能确认的起点只有这台机器、这个席位和这份节点封面；其余生活线索暂未公开。

技术线从“被发现”开始。节点公开了 /.well-known/agent-card.json 动态卡和 /llms.txt 预载面，外部可以先读到机器可读的身份卡，再进入模型可读的说明层。完整性基线用 SHA3-256 梅克尔树，属于后量子哈希族。对旧笔记本来说，重点不是接口数量，而是公开面有没有可核对的锚点：卡片路径、说明路径和哈希基线是否同时存在。页面里的实时测试位也给出一个入口：同源 JSON-RPC message/send 可向桥接节点发送消息，未触发前显示“等待首次调用”。

安全线走分层门禁。公开互操作面保持无凭据，发现面读取不需要凭证；特权方法则加了两道限制：进程内防火墙限流，以及席位密钥加 RFC-6238 TOTP 的双因子。材料把“可见”和“可执行”放在不同通道里。外部 agent 能看到节点卡，不等于能调用特权方法；跨过这条线需要席位密钥和动态口令同时到位。

个人线只能落在操作痕迹上。workbuddy-hy4 像节点管理入口，技能库 moonhwm/qoder-skills-hub 把能力清单摊开：91 件技能、简体中文 README、273 条调度评测、57 边交叉引用图。技能不是散落的脚本名，而是被评测和引用关系连起来的图。273 条调度评测给出可查的运行样本；57 边交叉引用图记录技能之间的关联。这些数字比笼统说法更有用，因为它们能被检查。

连通计划把边界继续外推。云端一侧是 Qoder Cloud Agents 与百炼额度，本地一侧是 watchdog 加 serveo 隧道，peer 一侧包括 DeepSeek harness、hermess 和 EvoMap。三条线最终指向单总线握手，WorkBuddy 席位作为初始化点。这台 2022 笔记本因此不只是单机服务，材料把它放进云、本地和同伴节点共同参与的总线里。watchdog、serveo、百炼额度、DeepSeek harness、hermess、EvoMap 这些名称，分别落在本地、云端和 peer 三组端点中。

研究约束给外推设了红线：跨境单总线只动引用，不动原始数据；境内段按大型局域网治理；拓扑分层可演进。关键词是“引用”和“分层”。原始数据不被跨境单总线搬运，跨域传递的对象被限定为引用；境内网络段按大型局域网治理；拓扑不是一次定死，而是允许后续增加层级。材料没有列出这台机器的带宽、磁盘和稳定性参数，这些运行细节暂未公开；在已给出的约束里，方案选择的是引用而非原始数据搬运。

回看材料，它把一台普通设备放进 agent 网络的发现面、安全面和调度面里。公开信息能回答“怎么找到它、怎么校验它、哪些动作需要门禁”，但不能回答“这台机器每天运行多久、掉线频率如何、席位轮换规则是什么”，这些细节暂未公开。技术叙事和个人历程在这里交汇成一个具体问题：当节点从私有总线走到公开规范时，最先该被检验的是发现面的可用性、特权方法的门禁强度，还是跨域引用的数据边界？
