## 第一章 总则

第一条【目的】为统一本生态正式文书之文件编码，杜撞号、杜断档、杜无号，使每一件文书均可经件号溯源至责任席与提交序，特制定本规格。

第二条【分层】编码空间分两层并建：

- **L1 公文形制层**：凡以公文形制对外出具之文书，版式编码要素依《党政机关公文处理工作条例》与 GB/T 9704《党政机关公文格式》执行；
- **L2 生态件号层**：本生态内部一切正式文书、函件、通告、台账件、蓝图件，均须配生态件号并入册登记。

第三条【纪律】

1. 件号**先登记后使用**；未入册之件号不具效力，视同无号；
2. **停用号段永不复用**；废止件号以状态字段标记，不物理删除；
3. **撞号以台账提交序先到先得**，后到者让号并留痕（继承协调函 2026-08-29 撞号判例）；
4. 件号一经登记，**字形永不改写**；订正以新发件号并列明取代关系为之；
5. 件号不含凭据、真名、内网地址等私有词表要素（编码即公开面）。

## 第二章 L1 公文形制层·要素检查单（人工项）

以公文形制出具之文书，送审前逐项核对：

| 序 | 要素 | 规格 | 备注 |
|---|---|---|---|
| 1 | 文种选定 | 决议/决定/命令（令）/公报/公告/通告/意见/通知/通报/报告/请示/批复/议案/函/纪要 十五种其一 | 一文种一文；请示与报告不得混用 |
| 2 | 发文字号 | 机关代字〔年份〕序号，三者齐备，六角括号〔〕，序号不编虚位、不加「第」 | 机检正则见第三章附则 |
| 3 | 份号 | 涉密公文须标注，6 位 3 号阿拉伯数字 | 非涉密可缺省 |
| 4 | 密级与保密期限 | 绝密/机密/秘密，顶格标注 | 与凭据主权纪律联挂 |
| 5 | 紧急程度 | 特急/加急（电报：特提/特急/加急/平急） | 缺省视为平件 |
| 6 | 签发人 | 上行文须标注 | 下行/平行文可缺省 |
| 7 | 成文日期 | 阿拉伯数字全年月日（如 2026 年 10 月 3 日），以签发日为准 | 禁汉字数字混排 |
| 8 | 印章与署名 | 发文机关署名与印章一致 | 电子件以签名指纹替代并注明 |
| 9 | 页码 | 4 号半角宋体阿拉伯数字，单右空一、双左空一 | Markdown 预检域外，标注「版式核验转人工」 |

> 说明：L1 层涉字体、行距、红头等版式参数，超出 Markdown 预检能力域；本门以「要素齐备性」为检点，版式参数核验转人工并载入预检报告。

## 第三章 L2 生态件号层·语法规格

### 3.1 件号通式

```
<谱系前缀>-<子类>-<日期码>-<责任标识>-<序号>
```

各段以连字符分隔；日期码二形——YYYYMMDD 紧凑形（CL/EVT 谱系）或 YYYY-MMDD 分节形（DF/TREE/WK/GW 谱系），一谱系一制，以 §3.2 登记为准；序号两位起步、不编虚位至三位以上。

### 3.2 已登记谱系（存量入册）

| 谱系前缀 | 语义 | 语法制式（正则） | 例 |
|---|---|---|---|
| CL | 协调函（含回执引用） | `^CL-[A-Z]+-\d{8}-[A-Z0-9]+-\d{2}$` | CL-SYNC-20261001-K3-01 |
| DF-NOTICE / DF-ORD / DF-MIN | 东方通告/裁示/简报 | `^DF-(NOTICE\|ORD\|MIN)-\d{4}-\d{4}-[A-Z0-9]+-\d{2,}$` | DF-MIN-2026-1003-GITCODE-01 |
| TREE | SHA3 哈希树清单件 | `^TREE-[A-Z0-9]+-\d{4}-\d{4}-\d{2}$` | TREE-K3-2026-1003-03 |
| EVT | 系列事件登记 | `^EVT-\d{8}-[A-Z]+-\d{3}$` | EVT-20260901-SKILLREFRESH-001 |
| WK | 全域唤醒书 | `^WK-\d{4}-\d{4}-\d{2}$` | WK-2026-1002-01 |
| OTL | 蓝图与 OTL 主文档标识 | `^OTL-[A-Z]+-\d{3}$` | OTL-BLUEPRINT-001 |
| GW | 公文合规预检门自体文书 | `^GW-[A-Z]+-\d{4}-\d{4}-\d{2}$` | GW-DOCCODE-2026-1003-01 |
| BC | 桌面席报备件 | `^BC-\d{3}$` | BC-012 |

### 3.3 新谱系设立

新谱系须先在本规格登记一行（前缀/语义/正则/首例），再投入使用；未登记谱系之件号，机检检出即「谱系未注册」退回。

### 3.4 机检规则（--doccode 闸）

1. **抽号**：全文（代码块内豁免）抽取形似件号之字符串（`[A-Z][A-Z0-9]+(-[A-Z0-9]+)+`）；
2. **语法校验**：命中已注册谱系前缀者，按该谱系正则校验，不合制 = error；
3. **撞号与入册校验**：本件声明件号（「件号：」行提取）已入册且归属文书非本件 = error（撞号）；本件声明件号未入册 = error（先登记后使用）；引用他件已入册件号 = 放行；引用语法合规而未入册之件号 = warning（提示补登）；
4. **断档提示**：同谱系序号跳跃 ≥2 者出 warning（提示补登或说明）；
5. **无号提示**：正式文书全文零件号者出 warning（简报/草稿豁免，报告类强制）。

## 第四章 台账规格（doccode_registry.jsonl）

每行一 JSON 对象，append-only，哈希链串接：

```json
{"seq":1,"code":"GW-DOCCODE-2026-1003-01","series":"GW","doc":"references/doccode-spec.md","seat":"k3-mirror-sync","date":"2026-10-03","status":"active","prev_hash":"GENESIS","sha256":"……"}
```

- `sha256 = sha256( 前五行字段紧凑JSON + prev_hash )`，写入时实算，改史即断链；
- `status`：active / superseded（须附 `replaced_by`）/ revoked；
- 台账与本规格同库同版本流转；任何席位可复算校验。
