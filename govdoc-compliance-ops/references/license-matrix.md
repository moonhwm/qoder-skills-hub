# 开源协议条款匹配矩阵（AGPL-3.0/SSPL 分层组合口径）

> 协议闸裁决依据。立法背景：主权人 2026-10-03 裁定采用 AGPL-3.0/SSPL 分层组合，已成文《ima与A2A约束下开源协议补充论证》（https://www.kdocs.cn/l/cboAFwILF079 ，云端登录墙在案）。本件只做匹配核对与名实纪律检查，不作许可政策裁决。

## 资产类型→许可层映射

| 资产类型 | 许可层 | 标识写法 |
|----------|--------|----------|
| 软件代码（适配器/脚本/工具链/机检件） | GNU AGPL-3.0 | LICENSE 官方原文入库；源文件头 SPDX: AGPL-3.0-only；附 NOTICE 版权行 |
| 服务栈敏感组件（经清单登记之托管服务组件） | SSPL-1.0 | 双行标识：「代码层：AGPL-3.0」「服务栈层：SSPL-1.0（源可得约束）」 |
| 文档/蓝图/规程附件 | CC BY-SA 4.0 | 页脚载明许可徽记与链接 |
| 数据集（总线快照/语义索引/简报数据集） | ODbL-1.0 | 随附 ODbL-1.0 指针 + 字段级出处台账 |
| 治理文本（规程/报告/声明） | 不许可化 | 单独标注「主权人保留终审权」，宪法性保留 |

## 条款匹配检查单（协议闸逐项）

1. 资产类型判定唯一：同一资产不得同时落两层；服务栈组件以清单登记为准（当前清单为空，增删须主权人批准）。
2. LICENSE 文本不变量：一律官方原文入库，哈希登记，不得改写、节选、翻译充数。
3. SPDX 标识拼写：`AGPL-3.0-only` / `SSPL-1.0` / `CC-BY-SA-4.0` / `ODbL-1.0`，逐字核对。
4. NOTICE 文件：版权行+席位指纹齐备。
5. 网络服务场景：凡「经网络提供调用」之组件，GPL-3.0 判定为不适格（SaaS 漏洞），须 AGPL-3.0 或 SSPL 层。

## 名实纪律（SSPL 层）

- SSPL-1.0 未获 OSI 认可：涉该层组件之 README/页面/模型卡，不得笼统自称「开源」，统一表述「源可得（source-available）强约束」。
- 双行标识缺一不可；只见 SSPL 不见 AGPL 行 = 退回。

## 第三方引入三先行

引入任何第三方组件前，三项先行缺一不得引入：

1. NOTICE 署名（原作者版权行与许可声明保留）；
2. 密钥扫描（检出不带凭据形态）；
3. SBOM 登记（组件/版本/许可/出处入台账）。

许可字段空缺（EMPTY）或自定义 NOASSERTION 之组件：未核清不得引入，挂账待审。

## 兼容性速查

| 第三方许可 | 引入 AGPL-3.0 层 | 处置 |
|------------|------------------|------|
| MIT / BSD / Apache-2.0 | 兼容 | 保留其许可声明，衍生分发随附 |
| AGPL-3.0 | 天然相容 | 衍生使用落入同等义务 |
| GPL-3.0 | 兼容（AGPL 第十三节桥接） | 组合体按 AGPL 分发 |
| SSPL-1.0 | 慎入 | 入服务栈层清单，名实纪律适用 |
| 空缺/自定义 | 不得引入 | 挂账候审 |

## 治理文本豁免

规程、报告、声明、送审稿等治理文本不进入开源许可体系；其效力源自主权人授权而非版权许可。文书页脚如出现 CC 标识须为「文档附件」定位而非「治理文本」定位，错位即退回。
