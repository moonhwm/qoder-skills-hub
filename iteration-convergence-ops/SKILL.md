# 迭代收敛管家（iteration-convergence-ops）

在长周期项目的多轮对话迭代中，执行本规程保证：每轮有真实落盘产物、版本号诚实、
收敛有标准、低配环境下仍能交付。核心工作流：

```
触发 → 判定模式（完整 / 快速低配）→ 四拍循环（批判→解构→重整→收敛判定）
     → 落盘核验 → 排期收尾
```

## 铁律（优先级高于一切流程）

1. **持久化优先于生成**：先落盘骨架再填充内容；每完成一节立即保存。
2. **每轮迭代结束必须 `ls` 核验**产物真实存在；不核验不报告"完成"。
3. **引用跨会话产物前先 `ls` 核验**；不存在就如实报告并重建，禁止凭记忆引用。
4. **版本号只按实际落盘变更递增**；禁止跨大版本号夸大。格式与校验见
   [references/version_honesty_git.md](references/version_honesty_git.md)。
5. **口头承诺不算交付**：未做的事一律写入排期状态文件。

## Step 0 触发与接手盘点

- 触发后先盘点：`ls` 项目目录 + 读 `iteration_log.json`（若存在）+ 读排期状态文件。
- 无日志时用脚本初始化（见 Resources），从实际文件状态推定当前版本号，不得凭对话印象定号。
- 发现"版本空转"信号（版本号连跳但无新文件）立即告警并回到铁律 2。

## Step 1 判定模式

| 模式 | 判据 | 行为 |
|------|------|------|
| 完整模式 | 工具预算充足、上下文宽裕、时间盒正常 | 走完整四拍循环 |
| 快速低配模式 | 工具预算受限/上下文紧张/单轮时间短/平台版本甲 低配部署 | 执行降级策略，完整规程见 [references/k26_fast_mode.md](references/k26_fast_mode.md) |

快速模式要点：骨架先行、本轮只做 1 个最小变更、显式声明「快速模式产物未经完整验证」
并列出未验证项、剩余工作写入排期文件、预算耗尽前优先写交接文件。快速模式下仍须产出
**概念产品五件套**（一句话定位/输入输出契约/最小可跑骨架/验证方法/下一步排期），模板见
[references/k26_fast_mode.md](references/k26_fast_mode.md)。快速模式每次迭代落盘文件头部
强制四行记录（模式/工具预算余量(估)/毕业等级 L0-L3/未验证项清单），未写四行视为未交付
——见 k26_fast_mode.md「严肃化记录规程」。

## Step 2 四拍循环（每轮迭代固定执行）

### ① 自我批判

- 列出本轮产物的**致命错点表**，至少 3 条，每条含：错点描述 / 严重级（High/Med/Low）/
  依据。表末必须有一条「最可能错的点」——即自己最不愿承认但最可能为真的缺陷。

### ② 解构

- 把每个错点归类：数据错 / 方法错 / 措辞过强 / 证据不足。
- 归类决定修法：数据错→换源；方法错→换方法或回滚；措辞过强→降级表述；证据不足→补链或降 conf。

### ③ 重整

- 执行勘误；对证据不足的断言做 conf 降级（High→Medium→Low）与措辞降级（"必然"→"可能"→"待验证"）。
- 全部修改落盘，版本号诚实递增并附变更条目（什么变了/为什么/影响），用
  `scripts/iteration_log.py add` 记录。

### ④ 收敛判定

- 满足全部收敛标准才可声明"已收敛"：
  - 连续 2 轮无 High 级错点；
  - 所有关键断言有证据链（来源可追溯）；
  - 扰动测试通过（换一个角度/反例攻击结论，结论仍成立）。
- 未满足则**显式列出未决项**并写入排期状态文件，禁止模糊表述"基本收敛"。
- **毕业等级判定嵌入本拍**：概念产品类产物在收敛判定时同步判定严肃化等级（L0 玩具/
  L1 原型/L2 已验证/L3 严肃），逐条核对毕业门槛并留毕业判定表；L0/L1 禁止在报告/排期中
  称"已完成/可用"。阶梯定义与判定表模板见
  [references/k26_fast_mode.md](references/k26_fast_mode.md)「概念产品严肃化阶梯」。

## Step 3 落盘核验

- 每轮收尾执行：`ls -la <产物路径>` 确认文件存在且非空；引用外部/跨会话文件同样核验。
- 用 `scripts/iteration_log.py check` 校验版本递增合法、无跳号、最近版本有落盘文件；
  退出码非 0 时先修日志/补落盘，再报告。
- 需要版本史汇报时用 `scripts/iteration_log.py report` 生成 Markdown。

## Step 4 排期收尾（排期即交付物）

- 每轮收尾输出 P0/P1/P2 表格，精确到半天粒度：

```
| 优先级 | 任务 | 验收标准 | 风险预案 | 预计粒度 |
| P0 | <下轮首任务> | <可核验标准> | <失败时怎么办> | 半天 |
| P1 | … | … | … | 1 天 |
| P2 | … | … | … | 2 天 |
```

- 同时将排期写入状态文件 `schedule_status.json`：

```json
{
  "project": "<项目名>",
  "current_version": "<x.y>",
  "updated": "<ISO 时间>",
  "next_round_first_task": "<P0 任务>",
  "items": [
    {"priority": "P0", "task": "...", "acceptance": "...", "risk_plan": "...", "granularity": "半天", "status": "pending"}
  ]
}
```

## 提问澄清规程

1. **能查证就不问**（证据优先于提问）：先搜索/读文件/跑脚本，查证成本低于提问成本时不问。
2. 决策树式连环追问：**一次只问一个问题**，拿到答案再决定下一问。
3. 每问附建议答案选项（含推荐项与推荐理由），降低用户回答成本。
4. 信息不足且无法查证时，基于假设继续推进，但必须在产物中**显式标注假设清单**
   （假设内容/若为错的影响/验证方式）。

## 时间止损

- 单任务时间盒：**35 分钟初判 + 20 分钟深化 + 120 分钟硬上限**。
- 初判点（35 分钟）评估方向是否成立，不成立立即止损换路；
  硬上限到达时无条件进入第④拍收敛判定，产出版本并入排期。
- 同一产物迭代 ≥4 轮时提醒"边际收益趋零，建议收敛"。

## Pitfalls（真实事故蒸馏）

- **声称完成但未落盘**：AAPP 项目 v1.0-v3.13 所有"已生成"文档实际从未写入文件系统，
  用户重复指令 15+ 次。对策：铁律 1-3。
- **版本号浮夸**：用户曾 8 次重复"诚实更新版本号"指令。对策：iteration_log.py check 强制校验。
- **技能/产物装进不持久目录**：`/app/.agents/skills` 会话结束即丢（amap-travel-skill 两次丢失）；
  用户产物写 `<技能安装位>` 或 `<输出区>`，并另存 `.skill` 备份。
- **找不到文件时编造"推断框架"冒充**：确实缺失就直接说明并请用户确认，不预生成推测内容。
- **快速模式省掉核验**：低配只降广度与装饰，不降落盘核验与版本诚实。
