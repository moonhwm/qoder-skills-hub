# 平台版本甲 快速低配模式规程

当运行环境资源受限时（平台版本甲 类轻量部署、工具预算受限、上下文紧张、单轮时间短），
进入**快速模式**。本规程目标：在低配条件下仍产出可落盘、可交接、可收敛的迭代结果，
而不是产出"聊得很热闹但什么都没留下"的空转对话。

## 低配信号识别

出现以下任一信号，立即判定进入快速模式并显式声明：

| 信号 | 判据 |
|------|------|
| 工具预算受限 | 会话提示工具调用次数/步数上限，或收到"工具调用预算已耗尽"类警告 |
| 上下文紧张 | 上下文使用率 >70%，或长文档无法一次性读入 |
| 单轮时间短 | 单轮可用时间 <10 分钟，或用户明示"快速给一版" |
| 模型/部署降级 | 运行在 平台版本甲 类低配模型上，长链路推理质量明显下降 |
| 环境不稳定 | 沙箱频繁重置、网关 504 频发，长任务成功率低 |

进入快速模式后第一轮输出必须以「【快速模式】」开头，并列出触发信号。

## 降级策略表（按优先级执行，上面的不可被下面的牺牲）

### a) 持久化优先：骨架先行

- 第一个工具调用就落盘骨架文件（空标题+章节占位），再逐节填充。
- 每完成一节立即保存，禁止攒到末尾一次性写。
- 每轮迭代结束 `ls` 核验产物真实存在；不核验不许报告完成。

### b) 范围收敛：本轮只做 1 个最小变更

- 把"本轮目标"砍到最小可验证单元（一个函数/一节文档/一张表）。
- 其余想法写入排期状态文件，不在本轮展开。

### c) 显式声明验证缺口

- 输出固定声明：「快速模式产物未经完整验证」，并逐项列出未验证项
  （未跑测试/未交叉核对来源/未做扰动测试等）。

### d) 禁止无谓装饰

- 不做长链路中间步骤的格式化美化、不生成可选图表、不写与验收无关的段落。
- 每步自问："这一步删掉会影响交付吗？"不会就删。

### e) 剩余工作写入排期文件而非口头承诺

- 「下次再做」一律写入排期状态 JSON（见 SKILL.md 排期节），口头承诺视为未承诺。

### f) 工具预算耗尽前优先写交接文件

- 预算剩余 <20% 时，停止新工作，写交接文件：当前版本号、已完成项、
  未完成项、下轮首任务、关键文件路径清单。
- 交接文件本身也要 `ls` 核验。

## 快速模式声明模板

```
【快速模式】触发信号：<信号>
本轮最小变更：<一件事>
未验证项：<清单>
剩余工作已写入：<排期文件路径>
```

## 概念产品五件套

快速模式下仍须建设性推进"概念项目产品"，最低交付为五件套（可全部放在一个文件里）：

1. **一句话定位**：为谁解决什么问题，如「为 X 类用户提供 Y 能力」。
2. **输入输出契约**：输入字段/格式、输出字段/格式、错误情形；写成接口契约表。
3. **最小可跑骨架（MVP）**：能跑通主路径的最简代码/文档骨架 + mock 数据；
   骨架必须落盘并能执行（哪怕是打印 mock 结果）。
4. **验证方法**：怎么判断它工作——一条可执行的验证命令或检查清单。
5. **下一步排期**：P0/P1/P2 各一项，精确到半天粒度。

五件套模板：

```markdown
# <概念产品名> v0.1-alpha
1. 定位：<一句话>
2. 契约：输入 {…} → 输出 {…}；错误：{…}
3. MVP 骨架：<文件路径>（已落盘，ls 核验通过）
4. 验证：`<可执行命令>` 应输出 <预期>
5. 排期：P0 <任务+验收>（下半天）；P1 …；P2 …
```

## 工具预算耗尽的交接协议

收到预算警告或预估剩余不足时，立即执行：

1. 停止一切探索性操作。
2. 写 `HANDOFF.md`（或追加到既有交接文件）：版本号、完成清单、
   未决清单、下轮首任务（带验收标准）、关键路径清单。
3. `ls` 核验 HANDOFF.md 与所有引用的产物。
4. 最后一条消息只报交接文件路径与一句话状态，不再开新线程。

## 快速模式 Pitfalls

- **快速≠免核验**：省掉的是装饰与广度，不是落盘核验与版本诚实。
- **快速模式不许跳版本号**：一轮只产出一个版本，诚实递增（见 version_honesty_git.md）。
- **禁止"先聊完再补文件"**：文件补写承诺在历史上从未兑现过；要么现在写，要么写进排期文件。
- **五件套缺一不可**：只给 MVP 骨架不给验证方法，等于没交付。

## 概念产品严肃化阶梯（L0→L3）

快速低配模式下产出的概念性应用流程容易停留在"玩具"水平：聊得像产品，实则无真实
输入跑通过。本节给出四级严肃化阶梯，每次升级必须过毕业门槛并留痕，禁止越级自称。

| 等级 | 名称 | 定义 | 毕业门槛（进入本级须满足） |
|------|------|------|---------------------------|
| L0 | 玩具 | 只有描述/伪代码/示意数据 | —（起点）。特征：无真实输入跑通 |
| L1 | 原型 | 可运行骨架 + 明确输入输出契约 + 一个手工用例跑通 | 骨架落盘（ls 核验）且第三人可按契约复跑 |
| L2 | 已验证 | 至少一个真实数据用例跑通 + 证据链登记 + 边界/敏感性粗测 | ① 真实数据（非 mock）用例跑通并留输出；② 关键判断按 `<技能安装位>/evidence-chain-verifier` 的证据登记格式登记（claim/source_type/url 或 no_public_url_reason/check_date/falsifiable_test/confidence 六字段）；③ 边界与敏感性粗测各至少 1 条（极端输入/参数扰动后结论是否仍成立） |
| L3 | 严肃 | 第三方可复核 + 完整敏感性/失效模式分析 + 交接五件套 | ① 关键判断附公开可查链接（对接 evidence-chain-verifier 的 url 字段）；② 完整敏感性分析与失效模式清单（每条失效模式写触发条件与后果）；③ 交接五件套齐备（对接 cross-session-workflow-bridge 的 handoff_protocol.md） |

### 每级禁止事项

- **L0/L1 禁止在报告/排期中称"已完成/可用"**；只允许写"L0 玩具/L1 原型（未经验证）"。
- **L1 禁止把 mock 数据结果当作产品输出**对外引用。
- **L2 禁止只做单点真实数据验证就宣称"对全量数据成立"**；粗测之外的范围一律标"未覆盖"。
- **L3 禁止缺失效模式分析即交付**；"可复核"意味着复核者不看你的解释、只看链接与文件就能得出结论。
- **通用**：升级必须留痕——每次升级写版本号 + 毕业判定表（逐条门槛打勾/叉+证据路径），
  用 `scripts/iteration_log.py add` 记录，禁止无判定表越级自称。

毕业判定表模板：

```markdown
## 毕业判定：<项目> <版本> 申请 L<X>
| 门槛 | 达成? | 证据路径 |
|------|-------|----------|
| <逐条照抄上级毕业门槛> | ✅/❌ | <文件/命令输出路径> |
判定：通过 / 不通过（不通过则列差距并入排期）
```

## 严肃化记录规程（快速模式产物头部四行）

平台版本甲 快速模式**每次迭代落盘文件头部强制四行记录**（写在文件最前，任何模板不得省略）：

```
模式(完整/快速) | 工具预算余量(估) | 毕业等级(L0-L3) | 未验证项清单
```

示例：

```
模式：快速 | 工具预算余量(估)：~30% | 毕业等级：L1 | 未验证项：真实数据用例未跑、敏感性未测
```

- 四行齐全才算交付；**未写四行的快速模式产物视为未交付**，不登记版本、不进排期完成列。
- 毕业等级必须与最近一份毕业判定表一致；判定表不存在时最高只能写 L1。
- 完整模式产物不强制四行，但建议保留"毕业等级"与"未验证项"两行。
