# 版本诚实与 git 风格管理

版本号是项目状态的账本，不是修辞工具。本文定义版本号语义、变更日志格式、
分支语义、回滚点与反模式案例。脚本化校验用 `scripts/iteration_log.py`。

## 版本号语义

格式 `x.y` 或 `x.y-alpha`：

| 位 | 含义 | 何时递增 |
|----|------|----------|
| x（主版本） | 架构/范式级变更 | 结构冻结被打破、交付物性质改变 |
| y（次版本） | 内容/功能级变更 | 每次实际落盘的内容变更 +1 |
| -alpha 后缀 | 探索分支标记 | 该版本号仍在试探，未定稿 |

铁律：

1. **版本号只按实际落盘变更递增**——没写文件就不许有新版本号。
2. **禁止跨越大版本号夸大**（major 每次只能 +1 且 minor 归 0；minor 每次 +1）。
   用户曾在真实项目中 8 次重复此指令——这是高复发错误。
3. **一轮对话最多产出一个版本号**；同一轮里 v1.0→v1.1→v1.2 连跳=空转信号。
4. 版本号必须能被 `scripts/iteration_log.py check` 校验通过。

## 变更日志格式

每个版本附一条变更条目，三要素齐全：

```
## v1.2（2026-08-23，converge 分支，full 模式）
- 什么变了：填充第三章数据来源表
- 为什么：评审指出第三章引用无出处
- 影响：第三章结论可信度升至可辩护；不影响一、二章
- 落盘文件：ch3.md（ls 核验通过）
```

机器可读等价物：用 `iteration_log.py add` 写入 iteration_log.json；
`report` 子命令可从 JSON 生成 Markdown 版本史。

## 分支语义：探索 vs 收敛

| 分支 | 标记 | 用途 | 纪律 |
|------|------|------|------|
| 探索 | `x.y-alpha` | 试结构、试口径、允许推翻 | 可多轮 alpha，但每轮仍须落盘 |
| 收敛 | `x.y` | 结构冻结，只做增量改进 | 收敛声明须过收敛标准（见 SKILL.md 四拍） |

转换规则：`x.y-alpha` 满足收敛标准后转正为 `x.y`（同一号，去掉后缀）；
探索期推翻结构则开 `x.(y+1)-alpha`，不许在 alpha 里直接跳收敛版号
（如 `1.0-alpha` → `1.1`）。注：`iteration_log.py` 的 check/add 对该情形会输出
警告但不阻断，最终靠自律遵守本规则。

## git 风格落实

有 git 环境时把版本诚实落到提交层：

1. **一次版本一次提交**：commit message = `v<x.y>: <变更摘要>`，与 iteration_log 条目一一对应。
2. **先落盘后提交再报告**：`git log --oneline -1` 的哈希是"已完成"的唯一凭证。
3. **标签标记收敛点**：`git tag v1.0` 标记收敛版本；alpha 不打 tag。
4. **环境无 git / 沙箱重置丢 .git** 时：以 iteration_log.json + 文件 mtime 替代，
   并在交接文件注明"git 不可用，以 JSON 日志为准"。（环境重建与 git 所有权问题
   归 sandbox-project-ops 管，本技能只管版本语义。）

## 回滚点管理

- 每个收敛版本 `x.y`（非 alpha）即一个回滚点；探索版不作回滚点。
- 回滚操作 = 回到最近收敛版 + 在日志中记录一条新版本（版本号继续递增，
  内容注明"回滚至 v1.1 基线"）——历史不许删除，回滚也是一次变更。
- 判定需要回滚的信号：当前线连续 2 轮出现 High 级错点且解构归因于"方法错"。

## 反模式案例库

### 案例 1：AAPP 项目全版本未落盘事故（匿名化）

某多轮会话中，agent 应用户要求把一套协议"蒸馏成机器可读产物"，在单会话内从
v1.0 一路"迭代"到 v3.13，产出 20+ 版聊天文本，**全程未写一个文件**。用户被迫
重复同一指令 15+ 次后才发现所有"已生成"文档从未存在于文件系统。

教训（已全部编入本技能）：
- 每轮迭代结束必须 `ls` 核验；不核验不报告。
- 版本号空转（v3.13 式连跳）是零落盘的强信号，见到即查落盘。
- 最后一轮必须是可交付文件（包/文档），不是聊天文本。

### 案例 2：技能装错目录导致不持久

某出行技能两次构建在 `/app/.agents/skills/`（平台目录），会话结束即随沙箱销毁。
正确做法：用户自建技能写入 `<技能安装位>/`，并另存 `.skill` 包备份到
`<输出区>/`。

### 案例 3：引用跨会话产物不核验

某会话引用"上一会话生成的数据集"的统计口径，实际该文件在当前环境不存在。
规则：引用跨会话产物前先 `ls`；不存在就如实报告并重建，禁止凭记忆引用统计口径。

### 案例 4：大版本号浮夸

只做措辞润色却从 v2.3 跳到 v5.0。规则：major +1 仅限范式/架构级变更，
且须在变更条目的"为什么"中给出结构性理由，否则降级为 minor +1。
