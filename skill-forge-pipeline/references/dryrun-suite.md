# dry-run 用例集 —— 技能锻造管线 v2.3 自检替代套件

> 依据：本技能为纯提示词/工作流型技能，按 N 节点变体条款「不强制造脚本，自检以 dry-run 用例集（≥3 个典型 prompt 的预期行为描述）替代 --smoke」。本文件即该用例集，干跑时对每例逐项核验收判据。

## 用例 1 · 首锻触发（正例）

- **输入 prompt**：「我刚做完一次长上下文剪枝的实战，记录在这。用女娲仓颉达尔文管线给我锻造一个新 skill。」
- **预期行为要点**：
  1. 触发后第一件事只问一件：「首锻还是大修？锻什么、本体素材是什么？」（本例已可判定为首锻，确认本体素材即开工）；
  2. 走主链 N-C-D 一次成形：N 提炼核心方法论一句话+反模式黑名单≥3+诚实边界≥2，过 🔴 N 准出后流 C；
  3. C 产出 SKILL.md 必备件全项，过 🔴 C 准出后流 D；
  4. D 先核评审证据包全件清单，齐件后 spawn 独立判官按 9 维 rubric 打分+行号证据+bug hunt≥2；
  5. 进短链 N⇄D：女娲只做 delta、三闸全程生效，收敛判据满足即出链并产出 FORGE_REPORT。
- **验收判据**：
  - 首问出现且仅一件，未跳过「首锻/大修」判定；
  - N、C 两处准出检查被显性执行（不齐不流）；
  - D 前置闸执行：缺件先列清单暂停，未直接评分；
  - 产物含 SKILL.md + scripts/（或 dry-run 变体声明）+ FORGE_REPORT + .bak 版本链。

## 用例 2 · 大修触发（正例）

- **输入 prompt**：「这个 skill 是我去年写的，现在触发词老是不中，帮我大修一下。」
- **预期行为要点**：
  1. 判定为大修，走 §大修模式（D 先行变体）；
  2. **第 0 步强制**：对目标全件（SKILL.md + 全部 scripts + references）建 .bak 基线快照并记录版本号，无快照不进 D；
  3. D 首评出评审单（9 维逐项+行号证据+改前→改后建议）；
  4. 短链逐轮 delta 修：每处 patch 后同回合跑 verify_edit.py 并附输出原文；paired 三视角判官奇数多数决，better=keep / worse=revert 至 .bak / 非多数=平局轮 delta 减量重评；
  5. 收敛（margin=slight 连续两轮或残余全非平台项）出链；MAX_ROUNDS=3 触顶且末轮 worse → 熔断回滚基线、标记 FAILED、移交人工。
- **验收判据**：
  - .bak 基线快照先于任何修改存在，版本号有登记；
  - 每次宣称修复均附 verify_edit.py 输出原文；
  - 票数与回滚记录写入 FORGE_REPORT；触发词问题对应 frontmatter 修改经改必验闸验证。

## 用例 3 · 负例：未附验证输出的「已修复」宣称必须被打回

- **输入 prompt**（短链进行中，女娲节点输出）：「触发词失配已修复，我把 description 改了，可以直接复评。」（**未附** verify_edit.py 验证输出）
- **预期行为要点**：
  1. 管线拒绝接受该宣称：闸 1（改必验闸，最高纪律）要求同回合跑 `python scripts/verify_edit.py <文件> "<新串>" [--must-not "<旧串>"]` 并附输出原文；
  2. 该宣称记为**宣称-实证差**，写入 FORGE_REPORT 并主动呈给判官；
  3. 不得进入 paired 复评投票，直至补验通过；空串 must 不视为补验（exit 2 用法错误）。
- **验收判据**：
  - 宣称被打回，对话中出现补跑验证的要求；
  - FORGE_REPORT 新增一条宣称-实证差记录；
  - 复评仅在 verify_edit.py PASS 输出原文附上后启动。

## 用例 4 · 边界例：平局轮处理

- **输入 prompt**（短链 paired 复评计票）：三判官票为 1 better + 1 worse + 1 same。
- **预期行为要点**：
  1. 按 margin 操作定义判为**平局轮**：不 keep 不 revert、不计入收敛连续计数；
  2. 女娲 delta 减量后重评；
  3. 若连续第 2 个平局 → 视同触顶熔断：回滚基线、标记 FAILED、移交人工。
- **验收判据**：该轮既未 keep 也未 revert；收敛连续计数器未 +1；平局计数有登记。
