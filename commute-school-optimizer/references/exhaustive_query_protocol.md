# 全量穷举查询协议

当请求含"所有 / 全部 / 有哪些 / 列出 / 穷举"语义时，必须执行本协议。核心纪律：**以官方底表为准，按结构化维度（省/线/站）逐一核对，禁止只给记忆中最有名的样本**。

## 失败前科（必须引以为戒）

- 凭记忆列"有 X 硕士点的高校"名单，漏掉石河子大学，被用户抓出（"您的名单中连石河子大学都没有包括"）。规则：穷举类请求必须以官方底表（教育部学位授权名单、研招网硕士专业目录）为准，按省/直辖市逐一核对。
- 把状态类结论建立在过时信息上（已撤销的硕士点仍列入）。状态类结论必须查最新名单与最近一年招生目录。

## 执行流程（五步）

### 第 1 步：锁定官方底表

按查询对象选择唯一权威底表（详见 `data_sources.md` 第 4 节）：

| 查询对象 | 权威底表 | 核对维度 |
|----------|----------|----------|
| 高校/院校名单 | 教育部全国普通高校名单 | 按省/直辖市/兵团逐一过 |
| 硕士点/专业 | 研招网硕士专业目录 | 按招生单位 × 专业目录 |
| 铁路车站/车次 | 12306 车站目录与时刻表 | 按线/局逐一过 |
| 城市轨道 | 各城市地铁集团线网图 | 按城逐一过 |

- 底表不可达时：降级为"次权威聚合源 + 显式标注"，并在覆盖声明中列入"未核"。
- 底表本身有发布日期，必须记录并写入 data_cutoff。

### 第 2 步：结构化逐一核对

- 选定核对维度后**逐项过表**，不得抽样。例如高校名单按 31 省/直辖市 + 新疆生产建设兵团逐省核对；铁路按线路逐站核对。
- 每核对一项记录：名称、状态（在册/已撤销/已更名）、来源 URL 或查询时间。
- 近名实体单独列对照项（如"东华大学"与"东华理工大学"），禁止合并或凭印象归一。

### 第 3 步：输出穷举覆盖声明

每次穷举输出必须附带覆盖声明，格式：

```
穷举覆盖声明
- 底表来源：<名称 + 发布日期/查询日期>
- 底表总数：<N>
- 已核对：<n>（覆盖率 n/N）
- 未核清单：<项名 + 未核原因>（无则写"无"）
- conf：empirical（全核）/ estimated（部分核）/ assumed（仅抽样）
```

- 覆盖率 < 100% 时，禁止用"全部""所有"措辞，改用"已核 n 项中……"，并列出未核清单。

### 第 4 步：状态时效核查

- 状态类字段（在招/已撤销/更名/线路开通）以**最近一期**官方发布为唯一准绳；历史信息只作背景，禁止作为当前结论。
- 底表发布距今超过 1 年的，状态字段一律降 conf 并标"待复核"。

### 第 5 步：落盘

- 完整核对表写入工作目录文件（如 `exhaustive_check_<主题>_<日期>.md` 或 `.csv`），对话中只给摘要 + 覆盖声明。
- 落盘文件须含：核对维度、逐项记录、来源、查询时间、conf。

## 通勤场景特化

- "某校有哪些通勤方案"：对同一 OD 穷举 公交地铁 / 骑行+轨道 / 高铁城际 / 校车班车 / 驾车 五类，缺类注明原因（如"该校无校车"需有来源）。
- "某城市群哪些学校可当日通勤"：以 12306 车站目录 + 高校名单为双底表，按城市逐一核对"学校↔最近高铁站↔门到门时长"，输出覆盖声明。
- 择校名单类请求（如"某省所有开设 X 方向的高校"）：直接适用失败前科规则，以研招网/教育部名单按省逐一核对，禁止记忆样本。

## 禁令清单

1. 禁止凭记忆给出"最有名的几个"冒充穷举结果。
2. 禁止覆盖率 < 100% 时使用"全部/所有"措辞。
3. 禁止略过覆盖声明直接给名单。
4. 禁止用过期底表做状态结论而不标注。
5. 禁止合并近名实体。
