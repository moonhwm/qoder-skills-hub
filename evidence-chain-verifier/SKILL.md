# 证据链核查员（evidence-chain-verifier）

## 概述

对任何输出中的关键判断执行"登记 → 分级 → 附链 → 冲突处理 → 自修正"五步规程，把每条断言变成可公开复核、可证伪、带置信度的证据链条目。领域无关：高校名单、企业资质、法律判例、产品参数、文献结论均适用。目标：最大限度避免 AI 幻觉，让人工复核只需点链接、跑证伪检验，而不必重做检索。

## 核查五原则（全程默念）

1. **标签 ≠ 实质**：有名称/牌子，不等于有内容。
2. **历史 ≠ 当前**：旧数据不能证明当前状态；状态类结论必须以最近一期官方口径为准。
3. **名义 ≠ 实际**：名单在册 ≠ 在岗/可用/有效。
4. **位置 ≠ 融入**：身处体系 ≠ 参与其中。
5. **数量 ≠ 质量**：数量多 ≠ 方向对、水平高。

每次下结论前，自问是否触犯其中某一条。

## 触发后五步（核心流程）

### Step 1 登记：强制证据登记

把输出中的每个关键判断（数字、排名、状态、资质、存在性断言）登记为一条证据链条目，必填字段：

| 字段 | 说明 |
|---|---|
| claim | 断言内容，写成可被证据推翻的陈述 |
| source_type | 信源类型（官方底表/监管平台/官网/权威媒体/自媒体/记忆推断） |
| url | 公开可查 URL；**无 URL 的关键判断必须改填 `no_public_url_reason`**，显式标记"不可公开复核"并说明理由 |
| check_date | 查证日期（YYYY-MM-DD） |
| falsifiable_test | 可证伪检验方法：复核者如何推翻这条断言（查哪个库、搜什么词、看什么字段） |
| confidence | High / Medium / Low / Conflict（定义见 Step 2） |

不可证伪的表述（"实力雄厚""业内领先"）不得进入正文结论；如必须引用，标注为"话术"并单独统计——话术密度本身是风险信号。

用脚本校验登记完整性（纯标准库，stdin 读 JSON 数组）：

```bash
python3 scripts/evidence_register.py --pretty < claims.json
```

输出校验错误清单、非阻断警告（如未来日期）、按 confidence 分组的 markdown 复核清单与统计。输入输出格式见脚本 `--help` 与 docstring。

### Step 2 分级：置信四级 + 冲突区

按信源强度定 confidence，**结论置信度不得高于其最弱支撑证据**：

- **High**：≥2 个独立信源互证（互相引用不算独立），其中至少 1 个为官方底表/监管平台级；
- **Medium**：1 个权威信源（官方/监管/权威媒体）；
- **Low**：单一非权威信源或推断所得；
- **Conflict**：信源间矛盾（含时间口径不一致，如旧名单 vs 新名单）。

证据等级金字塔、各类证据最大有效期表、证据文件命名契约 `{主题}_{类型}_{日期}` 见 `references/evidence_grading.md`——**开始登记前先读它**，用它给 source_type 定级和判断是否过期。

### Step 3 附链：关键判断节点公开可查链接

每个重要判断节点给出公开可查询链接（官网/官方底表/监管平台/裁判文书网等）。纪律：

- 链接必须是**真实可访问的入口页**，禁止伪造 URL、禁止编造深链；
- **宁给官方入口首页 + 检索路径，不给编造的具体深链**（例：给"研招网硕士专业目录首页 → 选省份 → 选学科"路径，而非拼凑的专业库详情页 URL）；
- 无法给出公开链接时，回 Step 1 填 `no_public_url_reason`，不得假装有链接。

各领域的官方入口清单模板与"入口页 + 检索路径"格式范例见 `references/self_correction_protocol.md` 第 4 节——**附链时读它**。

### Step 4 冲突处理：冲突永不压制

发现 Conflict 条目时：

1. 显式列出冲突双方（断言、信源、等级、日期），禁止悄悄选一个写进结论；
2. 对每个冲突执行 **≥3 次补充检索**（换关键词、换信源类型、换时间口径）尝试消解；
3. 消解路径与结果写入冲突记录；消解不了标 **unresolved**，相关结论降级为"存疑"，措辞用"存在矛盾，倾向 X 因为 …"。

冲突处理细则见 `references/evidence_grading.md` 第 4 节。

### Step 5 自修正：发现先前结论错误时的固定动作

发现错误（自查或用户指出）立即执行，不得悄悄改写：

1. **勘误表**：列出 原结论 / 新结论 / 证据 / 影响范围（波及哪些已输出内容）；
2. **conf 降级**：受波及条目置信度按新证据重定级；
3. **措辞降级**：超出证据强度的措辞改写（"系/确为"→"高度疑似"→"存疑"）；
4. **版本号诚实递增**：在同一大版本内递增小版本（v1.0 → v1.1），不跨大版本掩盖修正。

勘误表格式与版本规则见 `references/self_correction_protocol.md`——**发生修正时读它**。

## 元范式（所有报告的固定件）

1. **conf 三级标注**：对齐既有技能风格，关键证据另注 实证（直接证据）/ 估算（间接推断）/ 假设（待验证），与四级 confidence 并用。
2. **top3_likely_wrong**：每份报告末尾主动列出**本次最可能错的 3 个点**及各自影响方向（如某信源可能过时、某归类可能有误）。
3. **data_cutoff**：报告首页标注**数据截止时间**与**建议复核日期**（默认 12 个月后，快变领域 6 个月）。
4. **落盘纪律**：所有中间产物写文件——登记 JSON、检索记录、冲突表、勘误表——命名遵守 `{主题}_{类型}_{日期}` 契约，禁止只在对话里留结论。

## 全量穷举纪律

穷举类请求（"列出所有有 X 的院校/机构/案件"）：

- 以**官方底表**为唯一准绳（如教育部名单、监管平台全量数据），按省/类别**逐一核对**，输出覆盖率说明与"待核实"清单；
- **禁止只给记忆中最有名的样本**（真实事故：凭记忆罗列高校名单漏石河子大学被用户抓出）；
- 底表拿不到全量时，显式说明覆盖缺口，不得用记忆补齐后冒充穷举。

## 证据优先于提问

能用公开检索查证回答的问题，不要反问用户。只有核查路径本身需要用户决策（如预算/范围/用途影响深度）时才提问，并附已查到的部分结果。

## 对接 claims-deep-audit

- **本技能（evidence-chain-verifier）**：领域无关的上层规程——证据登记、分级、附链、冲突处理、自修正五步，产出**证据链登记表**与可复核报告骨架。任何任务的关键判断都过这套规程。
- **claims-deep-audit**：领域专用的深度核查器——针对机构/项目/导师/产品的宣传主张，执行 R1–R8 八轮核查与欺诈四分型（A 有壳空虚 / B 无壳裸骗 / C 名称偷换 / D 学科嫁接），调用本技能的登记表承载其证据。
- 分工：先由本技能把全部关键判断登记成链；若核查对象是"某主体是否名副其实"，转交 claims-deep-audit 做八轮深查，其产出回填本技能的登记字段（url/confidence/falsifiable_test），冲突与勘误走本技能 Step 4/5。
