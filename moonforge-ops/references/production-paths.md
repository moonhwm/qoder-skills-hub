## 路径一：代码渲染动画（code-rendered）

模型写程序逐帧画画面：HTML/Canvas/WebGL/p5.js/Three.js/Manim → 录屏或 ffmpeg 导出。
- 证据锚：可见代码仓库/工程文件；提示词从 172 字符开放委托到 17,664 字符逐秒分镜皆有。
- 经验卡要点：整数像素网格、固定色板、禁外部资源等「严格规格」类提示词可复现性最高。

## 路径二：控制软件（software-driving）

模型操控既有软件：After Effects（x-sheet 曝光节奏/分层合成）、Blender（景深处理）、浏览器录屏。
- 证据锚：可编辑工程文件（.aep/.blend）留存。
- 经验卡要点：价值在可编辑的后期流程，原始像素可能来自其他模型——归此时须注明原始素材来源。

## 路径三：剪辑素材（footage-editing）

模型对已有视频/真人素材做剪辑、拆帧、节奏对齐（ffmpeg 拆帧+HTML/Playwright 渲染+音效峰值对齐）。
- 证据锚：素材授权与原始片清单。
- 经验卡要点：「整支视频是代码」应理解为程序合成，不等于零现成素材。

## 路径四：编排外部视频模型（orchestration）

模型当导演：写剧本/分镜，调外部视频模型出片段（实证案例中出现的服务：字节 Seedance、MiniMax 海螺——均为真实厂商服务名，版本以各案例披露为准，如 Seedance2.5），音频侧实证出现 Suno、ElevenLabs，再合成。
- 证据锚：各外部服务的调用披露与账单口径（区分账面 API 等价 vs 缓存命中——实证 99% 缓存命中案例账面 $38.99 vs 无缓存反事实 $486）。账单口径属创作者披露，本件只做证据分级记录；其真实性定断（是否造假/夸大）归 rumor-chain-verifier，引用不复制。
- 经验卡要点：B站 BV1Kean6pE4V 即此路径范式（Opus 5.5 剧本+剪辑+后期 / Suno 音乐 / Seedance2.5 仅片段素材）。

## 警示条款

1. 「一句话/one prompt」跨度极大（172–17,664 字符），且常含隐藏输入（参考片、预置 skill、内部多轮审查循环）——按实际素材清单描述输入，不按提示词字数描述。
2. 模型自评分数（如「给场景打 8/10」）是工作流内部机制，不是第三方画质验证。
3. 有 MP4 不等于创作者认为成片完成（有案例明确标「未完成」止损）。
