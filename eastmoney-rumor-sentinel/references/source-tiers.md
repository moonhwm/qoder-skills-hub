# 信源分级与处置流程（东财传闻哨兵）

## 一、信源三级表

| 级 | 信源 | 地位 |
|---|---|---|
| 一级（定断源） | 交易所公告（沪深北）、证监会/监管发文、新华财经公告与政策检索（xhcj-news plugin）、公司正式公告 | 真伪只认此级；一级未证实=传闻 |
| 二级（准新闻源） | 东财快讯/东财新闻中心、主流财经媒体 | 可作线索与背景，仍须一级源定断重大断言 |
| 三级（传闻源） | 东财股吧帖、自媒体、聊天截图、「朋友说」 | **一律按未经证实传闻处理**，哨兵的本职采集面 |

判级（红/黄/蓝）是**词面信号分档**，不是真伪判定：红色=词面涉监管/造假/内幕声称，黄色=涉基本面事项，蓝色=无信号词。真伪核验须升级走流程二。

## 二、升级核验流程（三级→一级）

1. 红/黄档条目需要核验时，转 **rumor-chain-verifier** 拆链（事实节/因果节/价值节，逐节定断）；
2. 一级信源取证（v1.1.0 通道成文）：
   - **公告/政策检索**：`python3 /app/.agents/plugins/xhcj-news-agent/skills/xhcj-news/scripts/xhcj_query.py call <api_name> key=value`（本地脚本走 agent-gw，凭证优先级：KIMI_API_KEY→AGENT_GW_TOKEN→~/.kimi/agent-gw.json；凭证不在场=能力占位，降级交易所官网直查）；
   - 交易所官网直查（上交所/深交所公告查询）或通用检索（须标注信源级与检索日期）；
   - **通道实测注记（2026-09-09 穷举矩阵七查，含勘误）**：`xhcj-mcp-announce-search` 是**结构化事件库**——keyword 匹配事件文本（`info_event_txt`），**不匹配公司简称**。正确用法=**两段法**：①事件词检索（减持=1286 条/简称变更=196 条/更名=124 条在证）②结果按 `_source.secu_abbr` 过滤目标公司。公司名直查（飞乐音响=0/云瀚=0）是**用法错误不是通道空回**——本栏前版「通道存疑」结论勘误撤回，改记：通道可用，公司名直查路径错误在案。`get_AStock_News_byStockName` 资讯稿通道实测可用（公司名直查有效）。公告原文取证的有效降级=交易所官网+通用检索（标注信源级）；
   - 查无实据标「查无实据」，禁编造补齐；
3. 定断后登记进 **evidence-chain-verifier** 证据链（分级/附链/冲突/勘误）——本技能不自行登记证据链，分工不越权；
4. 核验结论回写哨兵报告对应条目（已证实/已证伪/查无实据+来源日期）。

## 三、分档处置

- 🔴 **红色档**：当周《白话市场一周》必含示警段（白话：有人在网上这么说→这事官方没说→内幕类说法不可验证且传播可能违法）；涉「内幕/听说」词必加内幕示警（避险守则第四条）。
- 🟡 **黄色档**：记录待核，作周报「选事」候选；核实前不进入任何事实陈述。
- 🔵 **蓝色档**：归档，不呈报细节，只报数量。

## 四、误报与词表维护

- 词面判级必然有误报（如「减持压力」是分析帖非传闻帖）——误报不追罪，词表修订走版本注记：增删词须写理由与日期，禁静默改词。
- 「ST」按词面命中即红，不区分公司名含 ST 与讨论 ST 制度；需要更细时逐条人工判读，不靠正则硬猜。

## 五、采集纪律

- 礼貌抓取：单页单代码、代码间 1 秒间隔、不翻页深挖、不碰登录态/验证码面；连续失败 3 次即停手如实登记（疑似反爬/封禁，不绕过）。
- 只碰公开面；采集数据按金融数据本地化纪律不出项目、不外发；报告外发走 release-gate-audit。
- 定时化=cron 新建须机主显式口令（冻结期纪律），手工跑不受限。
