# 长表逐字收割台（<长桌收割件>）

> 生态位：本技能管**收割时的完整性**（acquisition integrity）——上游触发于「要抓一个长表」；下游衔接：证据链登记/信源分级 → evidence-chain-verifier；会话级上下文压缩病总防治 → <语义肿瘤件>（本件是其 §1「大输入切分」在收割场景的特化与扩展，引用不复制）。

## §0 问题本体（为什么需要本规程）

超长表（约 ≥500 行）逐字收割时，**收割代理的上下文会在多次大写入后被系统压缩，中段源文被隐藏（出现 `[~N tokens omitted]` 类标记），代理若继续「转写」就会凭记忆编造行**——产出「前缀真实 + 中/尾段伪造」的文件，且伪造者往往无法自知。此类污染文件外表格式完好，只能靠与源比对发现。2026-09-04 实战（官方考试成绩全表批，14 主体 15,691 行）同型事故 3 起 6 段，全部经本规程检出并修复。

**核心立场：收割是搬运，不是创作。任何「记不得了就顺着写」都是伪造。**

## §1 铁律（收割五则，违反任一=整段作废）

1. **抓后立即连续写盘，不做中间分析**——拿到源页第一件事是分块落盘，分析、总结、统计一律在落盘之后。
2. **每块 ≤120 行**——write_file 首块 `append=false`，后续 `append=true`；单次写入不超过 120 数据行（也不超工具字符上限）。
3. **只凭当前可见内容逐字转写，绝不凭记忆续写**——保留原值的转义、空单元格、缺考/弃考/备注原文；不自补合并单元格、不「规范化」。
4. **源被隐藏即停写重抓**——发现 `[~N tokens omitted]` 或源文不可见，立即停写，重新抓取同一 URL，从本地文件末尾序号继续（不靠回忆补洞）。
5. **拼接前必过重叠带 diff 闸**——相邻段件必须含重叠带（建议 ≥5 行）；重叠带逐字一致（`OVERLAP_IDENTICAL`）方可拼接；不一致即上报，禁止自行处置。

辅助纪律：**edit_file / write_file 报「成功」后必须 grep 实证**（假报成功实战再现过）；所有行数以 `wc -l`/`wc -c`/awk 复核，不引用代理自报数字当终值。

## §2 通道阶梯（实测序，在场即用最前）

1. **web_open_url 直取**——首选；官方 wap 版页面常被搜索引擎全文索引、返回整表无截断。非 wap 页报错（internal error 等）先试 `_wap` 变体（URL 文件名加 `_wap` 后缀）。
2. **browser 通道**——常被验证码/超时墙阻断，作备选并留痕。
3. **shell/ipython 直连外网**——沙箱内通常无外网（curl ConnectionError），不要依赖；若意外可用，优先 `curl` 存原始字节（最强保真）。
通道状态每任务实勘一次并留痕，不沿用上次会话结论。

## §3 标准收割链（八步）

0. **侦察（S 级确认）**：确认源页单 URL 内含全表（inline 全量、行数规模、列结构、有无分页）；立判据再动手（先立判后执行）。
1. **分段派单**：按行号均分给**干净上下文子代理**（每段建议 ≤1300 行/约 ≤100KB），相邻段留 ≥5 行重叠带；并行上限 8 个后台代理。派单文本必须完整携带 §1 五则与输出格式契约（表头、转义保留、文件首行注释 `<!-- 序号范围: A-B -->`）。
2. **收割**：子代理按 §1 执行；**回传仅元数据**（文件路径/字节数/总行数/首末序号/自检结果）——含 PII 的全表不穿行主上下文。
3. **段件自检**：主线程用 shell 复核每段——`grep -c '^| '` 行数、awk 序号连续无断无重、首末序号与派单一致、无 `[~N tokens omitted]` 污染段。
4. **重叠带 diff**：相邻段重叠带逐段 diff，全部 `OVERLAP_IDENTICAL` 才进下一步。
5. **shell 拼接**：只用 `head`/`tail -n +K`/`cat` 按行号机械拼接，**禁止任何代理凭记忆重打内容行**；拼接后再跑一次全表 awk 连续性。
6. **独立复核**：派**未参与收割的干净代理**重新抓源，等距抽点（首/中/尾 + 旧 FAIL 点）比对关键字段，全部 PASS 才算闭合；11/13 主体即抽即中是不够的——**每主体至少 3 点**。
7. **落 manifest**：全台账（URL/成功变体/首末序号/字节数/缺口显式列表/复核结论）+ PII 扫描（如 `\d{10,}` 正则 0 命中）+ tmp 分段件全清。
工具化：`scripts/harvest_integrity.py` 提供 continuity / overlap / scan 三合一机检（见 §6）。

## §4 伪造签名鉴识（抽检时发现即立案）

出现以下任一签名，该段按「疑似伪造」处置（详细判据与分级见 `references/fabrication-forensics.md`）：

- **机械序号签名**：同一单位名挂数十个连续 +1 代码、块大小清一色（如每块恰 3 行）；
- **周期重复签名**：数值元组以固定行周期（如 200 行）重复出现，代码机械 +N；
- **零有机变异**：整段无缺考/弃考/同分/备注等真实表格的自然噪声；
- **越界签名**：本地出现的代码/序号在源表不存在（源最大值可经官方源或第三方转载旁证）。
处置铁则：**疑似段不修补、不猜测——整段作废，走 §5 修复链**；比对抽样记录 PASS/FAIL 与五字段对照留痕。

## §5 修复链（伪造段标准处置）

1. 立案：记录伪造范围（起止序号）、签名类型、抽样 FAIL 证据；
2. 派**干净上下文代理**分段重收该区间（派单文本同 §3.1，含五则）；
3. 新段与本地健康段做重叠带 diff（边界外扩 ≥5 行）；
4. shell 拼接置换（先 sed 核对两侧边界行，再 head+中段+tail）；
5. 独立复核代理重抓源抽点（必须覆盖置换段内抽点 + 旧 FAIL 点复测），全 PASS 结案；
6. 更正轨迹如实留痕（FAIL 不掩盖，写入 manifest/晨报）。

## §6 工具

```bash
python3 scripts/harvest_integrity.py continuity <文件.md> [--col 1]      # 序号连续性/断号/重号
python3 scripts/harvest_integrity.py overlap <段件A> <段件B> --band 945 950 [--col 1]  # 重叠带逐字 diff
python3 scripts/harvest_integrity.py scan <文件.md> [--col 1] [--unit-col 4] [--value-cols 5,6,7]  # 伪造签名机检
```
三个子命令均以退出码 0/1 给出 PASS/FAIL，适合挂进 verifier。机检只能筛查，不能替代 §3.6 的重抓源比对。

## §7 Pitfalls（实战教训，每条都出过事）

- **相信「子代理自报完成」**：收割代理会自爆也会隐瞒——一切行数/字节数以主线程 shell 复核为准。
- **让原代理「补写」伪造段**：原代理上下文已污染，补写=二次伪造；修复必须用干净上下文代理，原代理只许跑 shell 拼接。
- **重叠带一致就推全段一致**：渭南案 930–932 行在「1–946 全可信」结论内仍抽查出 3 行异常——重叠带只管边界，中段靠 §3.6 抽点与 §4 签名。
- **行数巧合即判真**：旧文件末行序号与真源巧合一致（1322/2492 两案）但内容伪造——行数对≠内容对。
- **拼接时「顺手修正」格式**：任何非机械改动都会污染比对基线；格式问题立案另处，不混入拼接。
- **edit_file 假报成功**：改收割/校验脚本后输出与改前完全一致——grep 实证四处修补点才发现未生效。改完必 grep。
- **PII 随回传扩散**：回传/晨报只写元数据；raw 仅本地，交付件先跑长数字正则扫描。

## top3_likely_wrong

1. 120 行/块、1300 行/段、8 并行三参数来自单一环境（2026-09-04 实测）实证，不同平台压缩阈值不同——新环境先小表试航再全量；
2. §4 签名鉴识对「精心伪造」（带有机噪声的编造）检出力弱——它防的是压缩后机械编造，不防恶意造假；
3. `_wap` 变体技巧以政府站群为样本，其他站点未必存在等价移动版——侦察步先确认再依赖。
