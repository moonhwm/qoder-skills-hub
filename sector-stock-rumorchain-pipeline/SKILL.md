# 研报个股谣言链一体化管线（sector-stock-rumorchain-pipeline）

> 溯源：2026-09-01 实盘固化——消费电子研报+奋达科技(002681)反转研判+舆情谣言链核查全流程（三案过闸卷宗可查）。v2.0.0 并收东财传闻哨兵（原 eastmoney-rumor-sentinel，2026-09-08 创刊，2026-09-09 并入退役）。

## §0 性质与边界

本技能是**编排件**：把「行业研报 + 个股分析 + 舆情核查 + 股吧采集」编为一条管线。除 §5 股吧采集段为本件本体外，其余各段的权威规程在其本体技能（引用不复制）。行业与个股均为占位符（消费电子/002681 只是实例）。

## §1 触发与首动作（点进去搜）

用户指令命中 description 任一触发语时，**第一步必须先读两个上游技能本体**（用户口令「得点进去搜」的法定含义）：

1. 读 `/app/.user/skills/hifi-integration-umbrella/SKILL.md` ——确认在场技能名录与 §2 冲突仲裁序，本管线按仲裁序调度：红线件（plugin-datasource-ops）→ 验收闸（output-verdict-gate）→ 执行件。
2. 读 `/app/.user/skills/rumor-chain-verifier/SKILL.md` 及其 `references/playbook.md` ——舆情核查段的拆链/定断方法以其为准。

路径回退：上述 `/app/.user/skills/` 路径缺席时，依次在 ① 当前工作区同名技能目录、② 其他已挂载技能根目录 中搜索同名技能；均缺席才允许声明降级。读取非标准路径时须在 plan.md 注明实际读取路径。缺席则显式声明降级（能力占位原则），禁止假装已调度。

## §2 五段式管线（顺序不可跳）

```
S1 数据采集 → S2 研报写作 → S3 舆情谣言链 → S4 输出审议闸 → S5 成稿与归档
```

- **S1 数据采集**（plugin-datasource-ops 纪律；大窗口历史回填/大空间筛查的定位段路由至 omni-exhaust-research-ops §2.5 筛查定位四法子模块，保存质量铁律同遵：凡入卷必全质量）：探针先行→按市场路由金融插件（A 股：iFinD/Wind/Gildata；舆情：新华财经）→多检索式交叉→原始返回落盘 `/mnt/agents/output/research/{topic}/`→每数字紧邻（来源，日期）。股吧传闻面素材由 §5 采集段供给。
- **S2 研报写作**（report-writing 技能）：研究与写作分离；行业→细分→板块行情估值→个股（基本面/技术面/催化/风险）→总结风险；`.agent.final.md` 为必经中间件。
- **S3 舆情谣言链**（rumor-chain-verifier 六步 + evidence-chain-verifier 登记）：采集多空传言清单（吧帖由 §5 供，红/黄档信号帖优先入池）→拆链（事实/因果/价值节）→逐节定断+conf→四表交付→断言登记 JSON 脚本校验。
- **S4 输出审议闸**（output-verdict-gate，金融实质输出必过）：控辩对抗→5 席盲评 4/5 超级多数→监管门；不过闸不发出。
- **S5 成稿与归档**：md→docx（按在场字体规范）；全部产物归集归档。

**路由明文**：命中「研报+个股」即触发整管线；用户未点名舆情时，S3 仍以压缩口径固定执行（≥2 条传言），禁止因未点名而跳过；用户明确排除舆情核查时方可跳过 S3 并在 plan.md 声明。个股代码有效性核验为 S1 首动作：核验失败（非个股/已退市/无此代码）→ 显式降级 + 给出补正路径，禁止以占位标的充数；处置声明须同时写入 plan.md 与成稿文首。命中「东财/股吧/扫吧」类触发而无研报需求时，允许单跑 §5 采集段交付白话报告，不强制起整管线。

各段细则与 checklist 见 [references/pipeline.md](references/pipeline.md)（执行前读）。

### 压缩模式（用户要求简版/演示/时间受限时）

| 段 | 可压缩 | 不可压缩（最低实质水位） |
|---|---|---|
| S1 | 采集广度、数据源数量 | ≥5 个核心真实数字（行业 2 + 个股 3），紧邻（来源，日期） |
| S2 | 章节数（可单章）、图表、docx | 行业主线判断 + 个股分层研判（确认/破坏信号 + 把握三档） |
| S3 | 传言量级（≥8 条 → ≥2 条）、底表差分穷举 | ≥2 条真实传言走完拆链（≥3 节含 ≥1 因果节）+ 逐节定断 + conf |
| S4 | 控辩/盲评/监管门全流程 | 骨架声明 + 产物标注「未经实闸」 |
| S5 | docx、卷宗归档 | md 落盘 + 免责声明 |

压缩模式产出仍是**成稿**（数字真实、定断真实），只是范围更小；压缩的是工作量，不是真实性。

## §3 实证事故清单（硬性，来自实盘闸口抓获）

1. **量级数字必复算**：媒体「N 倍量/翻倍」类约数不得照抄——用原始数据复算（实证：「4 倍量」实算 3.03 倍，首轮 5 席全否）。
2. **三层产物级联**：md/JSON/checklist 任何一层修订，其余层必须同步重生成（实证：chains JSON 与 checklist 漂移致两轮不过闸）。
3. **修订声明≠落盘事实**：每轮修订后 grep 复验零残留再送审；edit 类工具对长中文文件可能未持久化，以读回为准（实证：三次"编辑成功"实际未生效）。
4. **悬空引用检查**：来源日期晚于报告日落款=未来日期，一律剔除（实证：IDC/中商 2026-09-02 残留图注三处）。
5. **互斥数字并置检查**：同段落数字做算术自洽检验（实证：2267.1 万/2368.7 万/45% 三数互斥）。
6. **多口径并列**：YTD/涨幅/募资额等存在双口径时并列呈现并注明基期（实证：实募 8.49 亿 vs 原拟 11.69 亿裁决曾反转）。
7. **占位 URL 禁充数**：查不到的链接填 no_public_url_reason + 检索路径，禁拼凑深链。
8. **全占位交付禁止**：「骨架轮/成稿轮」二分是规程外发明的口径，禁止——任何一轮交付都须含实质。另禁止对空占位内容跑形式校验充数。

## §4 交付物

交付物验收第一问：「用户能否从产物中读到真实数字与真实定断？」不能则整体返工，不论结构多合规。

- 研报：`.agent.final.md` + `.docx`；谣言链核查报告 md + 证据链 JSON；审议闸卷宗目录；plan.md 全程留痕（状态/偏差/降级三栏，禁止复述规程）。
- 结尾必备：免责声明「本报告为研究分析，不构成投资建议」。

## §5 股吧采集段（东财传闻哨兵本体，v2.0.0 并入）

> 定位：**采集判官**不是判真伪官——只做「公开面有什么帖、词面像不像传闻」；真伪定断转 S3（rumor-chain-verifier），登记转 evidence-chain-verifier。可单段调用（口令「东财/股吧/扫吧」），也可为 S1/S3 供料。

### 5.0 红线（全继承，不可降级）

- 首行免责锚；无目标价、无评级、不预测涨跌点位；概念翻白话；涉「内幕/听说」必示警；量化结果先白话后附来源日期。
- 持仓数量、成本、金额、账号**永不**入分发包/广播/报告正文，仅本地私藏层台账（纪律全文见 [references/持仓观察纪律章程_v1.0.md](references/持仓观察纪律章程_v1.0.md)）。
- 金融数据与采集台账严格本地化不出项目；报告外发先过 release-gate-audit。

### 5.1 三拍流程

1. **采集判级**：`python3 scripts/eastmoney_sentinel.py --codes 300059[,...] [--tag 标签] [--out 采集目录] [--report 报告.md]`。观察名单默认读 [assets/watchlist.json](assets/watchlist.json)（名单修订须机主口令，留痕理由）；产出 `<code>_yyyymmdd.jsonl` 台账 + `<code>_seen.txt` 跨日索引 + 可选 md 报告。
2. **呈报**：md 报告按红/黄/蓝分档，首行免责锚，文末白话提示；全名单零新增如实报零，不制造「有料」假象；通道被反爬拦截时报障不报零（ChannelBlocked 判定），「如实报零」行在受阻时自动抑制。
3. **留痕**：每次扫描的 summary（fetched/new/error）入当轮留痕；失败如实登记不中断其他代码。

### 5.2 判级纪律（词面≠真伪）

- 红=监管/造假/退市/立案/内幕声称类词；黄=重组/中标/减持/业绩等基本面词；蓝=无信号词。词表见脚本 RED_WORDS/YELLOW_WORDS，修订规程见 [references/source-tiers.md](references/source-tiers.md) 第四节。
- 红/黄档需核验→升级流程（source-tiers 第二节）：拆链→一级信源取证（交易所公告/新华财经 plugin，xhcj 两段法：事件词检索→_source.secu_abbr 过滤）→查无实据如实标注，禁编造补齐。

### 5.3 联挂与频度

- **《白话市场一周》取材源**：周五收盘周报的传闻面素材由本段供给；红色档必含示警段。
- **频度纪律**：手工跑不受限；定时化=cron 新建须机主显式口令（冻结期纪律）；静态名单不配高频 cron。
- **能力占位声明**：东财快讯/资讯第二源未实测不进技能，标记为可扩展位；xhcj-news plugin 在场即作一级信源通道，缺席显式声明降级为交易所官网直查。

### 5.5 热点全扫与当日/前日传言核实（v2.1.0 机主整合令增编）

**能力边界（先证伪后出口，2026-09-09 实证）**：
- 股吧通道：东财对本通道拉人机验证时为 ChannelBlocked——受阻期股吧面采集能力**降级态**，报障不报零，严禁以其他源冒充吧内词面。
- 当日/前日传言核实**可用三通道**（2026-09-09 实盘验证）：
  1. **公告核实**：xhcj 公告检索两段法（事件词检索 → `_source.secu_abbr` 过滤），命中即取 `info_title/info_publ_date/announcement_link`；
  2. **快讯扫描**：xhcj `get_newsflash_stock`（startdate/enddate/Title）扫当日与前日快讯，零命中如实报零；
  3. **热点全扫**：xhcj `get_xhcj_hotNews`（默认近 7 天）+ `search_prodinfo_stockSector_news`（板块资讯，按行业 tag 过滤）——名单外热点由此入池，解决「只看名单漏热点」缺口。
- **核实流程**：热点/快讯/吧帖入池 → 词面判级 → 红/黄档走公告两段法取证 → 查无实据如实标注 → 定断转 S3 拆链。 MCP 数据面优先（xhcj/gildata/iFinD/Wind），通用网页检索仅兜底。

### 5.6 重置规程（v2.1.0 增编）

- **跨日索引**：`<code>_seen.txt` 为跨日去重锚，**永不自动删除**；名单修订或机主口令「重置」时，先归档旧索引（`_seen_yyyymmdd.bak`）再重建，留痕理由。
- **台账轮换**：`<code>_yyyymmdd.jsonl` 按日滚动，月末归档入注册处哨兵采集目录。
- **降级重置**：通道由受阻恢复时，首日扫描标注「恢复期首扫」，补漏窗口=受阻起始日至今。

### 5.7 自动运维与继承（v2.1.0 增编）

- **cron 挂载点**：交易日 15:30「收盘补数重算」例扫为本段自动运维载体（任务卡自包含；异常才报，全蓝一句话报平安）；新建/改频 cron 须机主显式口令。
- **继承链**：《传闻核查链式编排契约 v1.0》采集环=本段；升级核验链=公告两段法+一级信源；链外能力（真伪定断/证据登记）永不内吞。
- **自我推进**：例行扫描完即日报；非常态任务（热点深挖、名单重构）呈选择题候机主，不擅自扩权（autonomous-advance 族挂起中，点名复活后从其纪律）。
- **外骨骼接口**：呈报形制遵 cognitive-exoskeleton 方法论——选择题式交付、conf 三级、top3_likely_wrong 随重大定断附出。

### 5.4 诚实声明

- 采集面=股吧列表页+帖正文（post_article JSON 直解已实测；财富号异构站标 skipped 不抓）；评论不深挖（未实测），需要时先实测再扩版。
- 判级误报必然存在，不追罪；报告只呈词面信号，禁止把黄色档写成「公司确有此事」。
- 与 guba_scan.py v1.0 的台账契约保持兼容（同目录同格式追加）。
