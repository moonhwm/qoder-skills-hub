# 套磁信教练（grad-advisor-outreach）

把"联系导师"从玄学变成可复核流程：方向速览 → 约束识别 → 导师画像 → 自我镜像 →
信件生成 → 发送跟踪，全程由内核层（诚实检查、可验证性审计、时间止损、元认知提醒）兜底。

## 第一原则（内核层，不可拆卸）

1. **诚实检查**：信件中每个具体声称必须能被 CV/论文/成绩单直接辩护。删不掉的数字锚点是防伪水印；删了信件就退化为模板。
2. **可验证性审计**：引用导师论文/术语必须能追溯到具体出处（论文标题+年份），查无此源的引用一律删除或泛化。
3. **时间止损**：每位导师研究 ≤35 分钟，每封信初稿 ≤20 分钟，每天信件工作 ≤120 分钟。同一封信迭代 ≥4 轮时必须提醒"边际收益趋零，建议发送"。
4. **元认知提醒**：AAPP 是信息收集清单，不是决策引擎。量化评分仅供娱乐性参考；最终决策回归直觉——与哪位导师聊得最舒服、回复最热情。

## 工作流（M1→M6）

### M1 方向相关性速览（5-10 分钟/导师）
抓取导师最近 3 篇论文标题 + 职位描述关键词，与申请者兴趣词求交集：
- 交集 ≥2 → relevant，进 M2
- 交集 =1 → marginal（可发信，接受低回复率）
- 交集 =0 → irrelevant（建议跳过，除非有特殊理由）

### M2 约束条件识别（5-10 分钟/导师，**最易漏、优先级最高**）
逐字读职位描述，对照约束类型库找"暗约束"。完整类型库见 `references/aapp_modules.md`，最高危三类：
- **C1 强制转博**："intended for students who will transition to PhD" —— 申请者只要独立硕士时属 fatal，必须发信确认而非猜测
- **C3 语言硬门槛**：IELTS/TOEFL 分数要求 vs 申请者实际成绩
- **C5 经费不确定**："funding contingent" / 自费

### M3 导师画像构建（10-15 分钟，可选深度模块）
教育时间线、近 5 年论文分层（S/A 级）、平台资源（设备/组内规模/中国学生比例）、指导信号（tenure 状态、建组年限、近期招人活跃度）。产出"信件可用洞察"2-3 条。时间紧张时关闭 M3，仅凭 M1+M2 出信。

### M4 申请者镜像校准（一次性 5 分钟）
诚实定位：院校层次、语言成绩、科研产出、技能、核心短板、候选池位置估计。引导问题见 `references/aapp_modules.md`。定位决定策略：候选池后 30% → 广撒网 15-20 位 + 诚实探索型语气，不装强。

### M5 信件生成引擎（10-20 分钟/封）
按 `templates/letter_templates.md` 选模板：
- **T1 正式套磁信**（方向匹配，含论文 Hook）：150-200 词，必备段 hook/differentiation/gap/platform/interest/request
- **T2 探索性询问信**（信息不足试探）：120-150 词
- **T3 约束确认信**（存在致命疑问）：130-160 词，核心是把 C1 类暗约束问清楚

生成后运行 `scripts/letter_honesty_check.py`：

```bash
python3 scripts/letter_honesty_check.py draft.txt        # 人类可读报告
python3 scripts/letter_honesty_check.py draft.txt --json # 机器可读
```

exit=1（BLOCK）时必须修正后再发。收敛范例与修改对照见 `references/letter_playbook.md`。

### M6 发送与跟踪（5 分钟/封）
- 发送窗口：周二/周三上午（收件人时区）； attachments：正式信 CV+论文摘要，询问信仅 CV，≤5MB
- 7 天无回复 → 发 1 次礼貌跟进；仍无回复 → 标记关闭，不纠缠
- 回复分类：positive（interview/call/discuss）/ negative（filled/closed）/ neutral（review/committee），更新跟踪表

## 螺旋渐进式排期

不要一口气做完。按周期推进（详细模板见 `references/aapp_modules.md`）：

- **Cycle 1（第 1-3 天）**：完成 M4 自画像 → 选 5-8 位导师做 M1+M2 → 发第一批 3-5 封
- **Cycle 2（第 4-7 天）**：回顾回复 → 微调 M5 模板 → 第二批 3-5 封
- **Cycle 3（第 8-14 天）**：对积极回复者加载 M3 深画像 → 准备面试 → 第三批
- **Cycle 4（第 15-21 天）**：跟进未回复者 → 评估备选路径（考研/工作/RA）→ 关闭本轮

每个周期产出**必须落盘**（信件文件 + 跟踪表），不允许只在对话里迭代。

## Pitfalls（实测失败模式）

- **版本号空转不落盘**：曾有会话把本协议从 v5.0 一路"迭代"到 v3.13、产出 20+ 版聊天文本而零文件落盘。规则：每轮迭代必须写文件（`字母_收件人_vX.Y.md`），版本号诚实递增，禁止大版本号浮夸跳跃。
- **无限打磨同一封信**：用户要求"榨取最后优化空间"时也要执行时间止损；v19 之后"信件本身不再迭代"，转入发送前检查清单。
- **不可验证的具体化**：为显得充实而编造 gap 期细节（"re-analyzing datasets"），被用户确认"宽泛解释 gap 是可接受的"后回退。规则：宽泛但真实的表述 > 具体但不可辩护的表述。
- **凭印象筛导师**：导师名单、职位状态、约束条件必须以官网/职位原文为准；名字不像中国人不要猜国籍，去查教育背景。
- **把 AAPP 评分当决策依据**：评分只是信息清单的副产品；用户最终采纳的结论是"行动优先——72 小时内提交申请，同时发出套磁信"。
- **忽视跟进纪律**：套磁不是发完就完；7 天跟进、1 次封顶、然后关闭。
